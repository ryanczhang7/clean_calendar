## Decided

1. **The cached stores stop following the cache for everyone when one
   listener leaves, as far as the tests know.** `cachedStores.ts:91`'s
   guard reduced to `if (live !== null)` survives the whole unit project
   (3000/3000). The kinds store is read through `useKinds` by several
   components at once (`CalendarPage.tsx:469`, `:543`, `WeekView`, `DayView`,
   `KindLegend`), so a view switch
   would leave the page blind to Realtime rows and drained ops. No test
   holds two listeners and removes one. Filed as **CAL-062** with the
   failed-marker precedence (Decided 5). Rests on E-HAND C91 and E-STRYKER
   `cachedStores.ts`.
2. **The app's own event and kind actions are never tested on the
   `online` default they run on.** Every test passes its own `online`. With
   the default made `() => false`, an online edit is queued and never sent,
   and the whole unit project passes (EV72 3000/3000; KA55 after a false
   kill, KA55b). This is EPIC-04's done-when ("the edit is on the server
   within seconds") failing silently on any device that never goes offline.
   Filed as **CAL-061**. Rests on E-HAND EV72, KA55, KA55b and E-STRYKER
   `eventActions.ts`, `kindActions.ts`.
3. **The app's sync status, built with no window, is never shown to follow
   the network.** Every `syncState` test passes `window` explicitly; the
   app's instance passes nothing. `target ?? (…)` made `target && (…)`
   survives the whole unit project (SST56, 3000/3000), so the indicator
   could stay "Synced" in airplane mode. Filed as **CAL-063**, with the
   window listeners' removal. Rests on E-HAND SST56 and E-STRYKER
   `syncState.ts`.
4. **The drain's best-pinned behaviour has one blind spot: an op whose row
   the cache, or the server, no longer holds.** That situation is reachable
   (Discard of a failed insert leaves the insert's later ops queued), and
   every step of it survives: the token fallback (`:176:19`, which would jam
   the outbox for good), the "gone from the server altogether" branch
   (`:214-220`), and the failed notice's title for an uncached row
   (`titleFromPatch`, `eventIdOf`, `noticeTitle`: 41 mutants). Filed as
   **CAL-064**. Rests on E-STRYKER `drain.ts` and E-FULL (W176, W214, W96).
5. **A failed marker loses to a later queued op as far as the tests know.**
   `cachedStores.ts:155` reduced to `else marks.set(op.id, "saving")`
   survives the whole unit project (C155, 3000/3000). An event edited again
   after its op failed would lose its failed badge and CAL-045's strip,
   which is gated on `sync === "failed"`. In CAL-062. Rests on E-HAND C155.
6. **Two pass-level drain rules are unpinned: the announcement belongs to
   one pass, and a reminder's undo survives a conflict.** Without the
   `announce = false` reset, every pass after the first announced one toasts
   "Back online. n changes synced." (D11: 88/88; whole project 2999/3000,
   the one failure a timeout in `noSecrets.test.ts`). With CAL-044's
   re-queue reduced to events only, a reminder's restore over a re-stamped
   deleted row is dropped (RQ1: 3000/3000). Filed as **CAL-065**. Rests on
   E-HAND D11, RQ1 and E-STRYKER `drain.ts:236`, `:320`.
7. **A pull's "never overwrite a pending op" rule is pinned only for the
   tables whose two names agree.** The cache calls overrides `overrides` and
   the outbox calls them `event_overrides`; filtering by the cache's name
   (Y2) survives the whole unit project, and mapping it to `""` (Stryker
   `hydrate.ts:32:14`) the narrowed one. In the same cluster, `retryOp`
   and `discardOp` on a seq that is already gone (O293, O310) survive the
   whole project too, and the first would put a table-less op in the
   outbox that jams every later pass (reasoned). Filed as **CAL-066**.
   Rests on E-HAND Y2, Y2-full2, O293, O310.
8. **CAL-045's Discard is unpinned in its commonest case.** A refused update
   leaves the server row's stamp equal to the cache row's, so the sheet's
   remount rests on the generation counter alone, and every Discard test
   hands back a server copy with a different stamp. Pinning the generation
   to 0 (`:142:22`) or counting it down (`:154:63`, T154b 104/104) passes.
   Also unpinned: a Discard's replacement leaking into the next event opened
   (`:139:26`), and a second Retry after a refused one (`:240:24`). Filed as
   **CAL-067**. Rests on E-STRYKER `EventSheet.tsx`, E-HAND T154b and
   E-FULL (W139, W142, W240).
9. **Two `syncState` tests claim more than they pin, and are named here

   calls its listener" passes with the drain subscription doing nothing (S2);

## Evidence

Everything was measured on one Windows 11 host (12 logical CPUs) with Node
24.19.0, Vitest 5.0.4, Stryker 10.0.0 (`@stryker-mutator/core`, built-in
command runner), Dexie and `fake-indexeddb` as locked in `pnpm-lock.yaml`
(`dexie ^4.4.6`, `fake-indexeddb ^6.2.6`), React `^19.3.0`, host time zone
America/Chicago. The unit project was 3000 tests in 89 files. Nothing was
measured on CI. Stryker's sandbox (`.stryker-tmp/`) and its JSON reports
(`reports/mutation/e04-*.json`) are gitignored and will not survive a clean
checkout.

**Load.** The Stryker runs were sequential, at `concurrency: 6`. Hand
mutations through `mutate.sh` ran **at the same time**, each waiting for
the current Stryker run to finish building its sandbox (a lock file in the
scratchpad, so no sandbox copied a mutated file). Load creates false
*kills* (timeouts, flakes), never false survivals, so every survivor below
stands. Every kill that later mattered was re-run or read from its output.

**Baseline.** Unmutated, the whole unit project ran twice before anything
else: `Tests 1 failed | 2999 passed (3000)` (the failing test was not
captured), then `Tests 3000 passed (3000)`. That first failure is counted
in E-FLAKE.
