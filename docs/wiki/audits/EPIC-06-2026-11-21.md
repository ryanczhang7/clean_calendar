**`shared/recurrence.ts`: 13 survivors (2 gap, 3 acceptable, 8 equivalent).**

- **Gap (CAL-079):**
  - `:103:34` `wall - before` -> `wall + before`. The only test of a wall time
    that does not exist is in London on 29 March, where `before` is 0.
  - `:151:9` `k === 0` -> `false`. See "Tests whose names claim more than they
    pin".
- **Acceptable:**
  - `:76:14` `((instant % 1000) + 1000) % 1000` -> `(… + 1000) * 1000`.
    - This adds a constant 1 000 000 ms (16 min 40 s) to every wall time.
    - The bias cancels in `fromWall`, because the offset carries it too, so
      the instants do not change.
    - Only `dateOf` moves, and only for a start in the last 16 min 40 s of a
      local day. No test has such a start.
    - It is not a plausible defect.
  - `:76:16` `instant % 1000` -> `instant * 1000`, and `:78:5` `+ ms` ->
    `- ms`. These drop or negate the milliseconds of every occurrence after
    the first.
    - The event form builds whole-minute instants.
    - The capture path parses the model's ISO strings, which could in
      principle carry seconds (not checked).
    - No view shows sub-second precision.
- **Equivalent:**
  - `:53:7` and `:65:5`: the formatter cache (`true`, and the `set` call
    removed). Only performance changes.
  - `:73:9` `p.type in fields` -> `true`: writes `literal` parts into a key
    that nothing reads.
  - `:76:15` `+ 1000` -> `- 1000`: for whole-second instants the result is
    `-0`, which is the same number.
  - `:99:19` and `:99:38`: `before === after ? [before] : …` forced to the
    two-element branch, or `[before]` emptied. When no transition falls
    within a day, the duplicate entry, or the fallback `wall - before`, gives
    the same instant.
  - `:146:9` `sWall === null` -> `false`: a 29 February that does not exist is
    dated `1970-01-01`, which falls outside every range after 1970.
  - `:148:9` `until !== null` -> `true`: `"2026-…" > null` is `false`, so a
    null `until` still never stops the loop.

## What would have to be true for this to be wrong

- **Stryker's command runner reports a mutant killed whenever the command
  exits non-zero, for any reason.** A flaky `CalendarPage` case would show as
  a false kill in `page` and hide a survivor. There were two unexplained
  failures in one baseline run, and load-induced timeouts are shown under R4.
- **The milliseconds survivors are harmless only if no stored instant
  carries seconds or milliseconds.** The `recurrence.ts` `:76:16` and `:78:5`
  survivors are classed as harmless on that basis. A capture or an import
  that writes them would make those two real.
- **`moveEvent.ts:134` is equivalent in the app only while
  `CalendarPage.tsx:365` is `landedStart`'s only caller.**
  `grep -rn landedStart src`, with test files excluded, finds the import,
  that call and the definition.
- **CAL-079's severity assumes someone keeps a repeating event in the
  02:00-03:00 hour of a spring-forward night.** The defect is certain; how
  often anyone meets it was not measured.
- **CAL-081's severity assumes the two clusters really are drawn with the
  widths that `TimeGrid.tsx:151-152` computes.** The layout map was measured;
  the rendered style was read off the code, not observed.
- **Deno is assumed to resolve `Intl` offsets as Node does.** The shared
  fixture shows it does for the cases it holds. P1 to P3 ran under Node only.
