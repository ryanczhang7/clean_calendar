## Decided

1. **The `mutation` gate as committed still cannot start.** This is the
   sixth audit in a row. The same 4 git-listing tests in
   `src/geminiBoundary.test.ts` and `src/deploy/noSecrets.test.ts` fail in
   Stryker's initial run. Not filed: the fix is in `stryker.config.mjs` or
   `project.conf`, which are the PO's. Rests on E-GATE.
2. **The event sheet has the highest-impact gap: an untouched numbered
   reminder is not pinned across an All-day switch, and an all-day series'
   basis on a timed date is not pinned either.** Both mutants survive the
   whole unit project, and each one changes **when** the reminder fires
   with no error shown. Filed as CAL-087. Rests on E-SHEET and E-WHOLE.
3. **The service-role check is pinned on one spelling of the cron's key.**
   The decoder's `-` mapping and its padding for length % 4 = 3 can both be
   broken with the Deno suite green. Either one would make every scheduled
   run answer 401 for a key with that spelling, so no reminder fires
   anywhere. The three-segment rule can be dropped too. That is defence in
   depth behind `verify_jwt = true`. Filed as CAL-085. Rests on E-DENO and
   E-JWT.
4. **The send-reminders failure lines are mostly unpinned.** No test makes
   the `sent_at` PATCH throw. No test asserts that a successful DELETE logs
   nothing. The one DELETE-failure test's log needle floats
   (`includes("sub-a")`). For an unattended one-minute cron these lines are
   the only record. Filed as CAL-086. Rests on E-DENO.
5. **A failed reminder-only save cannot be retried** if the guard reset at
   `EventSheet.tsx:382` is lost, and nothing tests the retry. The impact is
   lower (the owner has to close and reopen the sheet), but the user sees it
   and the story is cheap. Filed as CAL-088. Rests on E-WHOLE.
6. **Not filed, put to the PO: a `sent_at` PATCH that answers non-2xx is
   ignored** (`handler.ts:292-301` checks neither `res.ok` nor `res.status`).
   The reminder stays unmarked, so the next minute's run pushes it again
   while it is still inside the five-minute window. That could mean up to
   five repeats, although the notification `tag` (`pushHandlers.ts:84`)
   replaces rather than stacks them on the device. This is a behaviour
   question, not a missing test. CAL-028's notes left it "open for review",
   and CAL-086's Out of scope names it.
7. **Everything else that survived is equivalent, acceptable, low-impact
   and not filed, or not EPIC-07 code.** The classification is in E-CLASS.
   One survivor, `PermissionCard.tsx:41:36` (Allow carries `aria-busy` at
   mount), is a real gap that is left unfiled as too small. The PO may file
   it.
8. **Every assertion in scope that passed on arrival is now earned.** The
   two that never were are CAL-057's "without the reminder prop, the form
   has no Reminder field" and "without the third argument the name has no
   reminder part". Each is earned here by one mutation (E-EARN). The other
   stories' were earned in their own cycles (E-EARN lists where).
9. **One claimed row of every handoff's mutation table reproduces** on
   today's tree (E-HANDOFF). That is eight stories and eight rows. One
   count differs from what the handoff claimed, and the reason is explained
   there (CAL-057, because more tests now exist).

### E-JWT: what the decoder mutants do to real-shaped keys

This is a scratch Deno script (`deno run`, no permissions). It encodes
`{"role":"service_role","n":X}` the way the test's `b64url` does and decodes
it with the shipped expression and with each mutant, for X in `""`, `"a"`,
`"ab"`, `"abc"`, `"~~~>"`, `"???>"`, `"ûï"`:

| X | len % 4 | has `-` | has `_` | shipped | `62:39` (`-` -> `""`) | `63:36` (`4 +`) | `63:24` (no pad) |
|---|---|---|---|---|---|---|---|
| `""` | 0 | no | no | service_role | service_role | service_role | service_role |
| `"a"` | 2 | no | no | service_role | service_role | service_role | service_role |
| `"ab"` | 3 | no | no | service_role | service_role | **throws** InvalidCharacterError | service_role |
| `"~~~>"` | 2 | yes | no | service_role | **throws** InvalidCharacterError | service_role | service_role |
| `"???>"` | 2 | no | yes | service_role | service_role | service_role | service_role |

(`"abc"` and `"ûï"` behave like `""` and `"a"`.) So `62:39` and
`63:36` break real spellings, while `63:24` and `63:41` (pad 0) are
equivalent: Deno's `atob` accepts unpadded input. The suite's fixture,
`SERVICE_CLAIMS` with `n: "???>"`, is the `_`-only, length-2 row, the one
row where no mutant differs. **Unrepresentative if** the real key's
spelling is known not to have the property. Nobody checked the project's
actual key here, and must not print it to do so. The gap is that the
decoder can regress for keys of that spelling unnoticed. It is not a claim
that today's key would break.

### Tests whose names claim more than they pin

- `handler_test.ts:101`, "the test's service-role JWT exercises base64url

## What would have to be true for this to be wrong

- **Stryker's command runner counts any non-zero exit as a kill.** A flaky
  test in a command would hide a survivor. Each baseline passed twice (the
  plain check and Stryker's initial run).
- **The Deno instrumentation activates mutants.** Shown by the selective
  result (E-DENO) and by `process.env` being readable. If a future Deno
  removes the `process` global, every mutant survives, and the run would
  look broken rather than green.
- **Deno's `atob` stays forgiving about padding.** If it became strict,
  `63:24` and `63:41` would turn from equivalent into gaps.
- **"Equivalent" in the sheet assumes the stored reminder agrees with its
  event's All day** (0 on timed, -540 on all-day). The sheet maintains
  that. Data written another way (SQL, an old client) could make
  `259:5`, `268:*`, `270:5` and `413:9` observable.
- **The two excluded test files cannot kill an EventSheet mutant** (E-WHOLE).
- **The impact statements for CAL-087 and CAL-088 are reasoned**, not
  observed in a browser.
