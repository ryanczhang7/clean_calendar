# Audit: H23 — probe artifacts, tree scanners, and the classifier nobody could reach

**Date:** 2026-09-13
**Scope:** finding **H23** from the consolidated field report (new in WORLD-011),
read against the harness at `f247a68`. Acted on in full: the classifier is now
reachable from test code in any language, `paths.conf` knows what a probe
artifact is, and the pattern is written into `tdd-cycle` and `stack-profiles`.
**Left out:** H21 and H22, which arrived in the same revision of the report and
are not this round's scope. H21 is **already fixed here** — see Evidence.

## Decided

- **The fix H23 asks for had a missing half, and the missing half came first.**
  The report says *"`paths.conf` knows what a test artifact is; expose `classify`
  to test code."* Measured against this checkout, the first clause is false:
  `src/ui/__import_guard_probe.ts` classified as **`source`**. Exposing the
  classifier alone would have shipped a guard helper that returns exactly the
  wrong answer the four hand-rolled regexes returned — a fix that changes the
  mechanism and not the result. So `paths.conf` learned the convention first,
  and the script exposes it second.
- **Probe artifacts are `test`, by a naming convention with a leading `__`.**
  `**/__probe_*.*` and `**/__*_probe.*`. One rule makes the scanner and the phase
  lock agree: a tree-scanning guard skips the file, and RED may write it, because
  it is a test artifact that happens to live in the source tree. It has to live
  there — lint overrides are path-scoped, and a probe linted from a temp
  directory is linted under the wrong rules, which makes both the probe and the
  rule stop testing anything while still passing.
- **The leading `__` is load-bearing, and is the second-order trap the report
  names.** Matching `*_probe.*` would classify a real `heat_probe.ts` as a test
  and make it invisible to every guard — the same defect pointing the other way.
  Both directions are pinned, and both were earned by mutation.
- **`scripts/classify.sh` is the interface, and it is stack-neutral.** Paths as
  arguments or on stdin; `--only CATEGORY` to filter a list you already have;
  `--list CATEGORY [PATHSPEC]` to enumerate the tree. Bash, per the portability
  rule, so a guard in any language shells out once per suite. It refuses an
  unknown category rather than returning nothing, because a typo'd
  `--only sources` silently reads as "this tree has no source files", which is
  the failure mode the script exists to prevent.
- **`--list` enumerates tracked files *and* untracked ones git does not ignore.**
  Skipping untracked files would have excluded probes for free — and would have
  made every just-written module invisible to every guard until it was committed.
  That is a vacuous pass wearing a fix's clothes. Probes are excluded by their
  **classification**, never by their tracking status.
- **Catching the `ENOENT` is the wrong fix, and the reasoning is recorded rather
  than assumed.** It treats the symptom, hides every future cause, and lets a
  scanner degrade toward scanning nothing while reporting green. Written into
  `tdd-cycle` as a named non-fix, because it is the cheapest thing a future agent
  will reach for.
- **The pattern is stated where both audiences read it.** `tdd-cycle` carries the
  general shape — a test that writes into the tree and a test that reads it are
  not independent, and worker isolation isolates module state, not the
  filesystem. `stack-profiles` carries the operational convention, because the
  tempting one-liner is different in every language (`glob`, `readdirSync`,
  `Path.rglob`) and each one is a private copy of a rule that lives in
  `paths.conf`.

## Evidence

- **The report's premise was checked before it was acted on, and was wrong.**
  Claim: `paths.conf` already distinguishes a probe artifact. Measured with
  `bash -c '. .claude/hooks/lib.sh; classify …'` at `f247a68`:
  `src/ui/__import_guard_probe.ts` → `source`, `src/core/__probe_a.ts` →
  `source`. No rule in the `test` block matches either: the block keys on
  `test_*`, `*_test.*`, `*.test.*`, `*.spec.*` and `__tests__/`. This is the
  report's own K2 applied to the report — an instruction naming a mechanism is a
  claim like any other.
- **H21 is already fixed upstream, and was fixed independently.** The report
  lists it as *"fixed downstream, open upstream"*. It was closed here on
  2026-09-11 in PR #14, from the same defect arriving by a different route: CI
  refused a licence-only PR with `1 source file(s) changed with no test changes`.
  `LICENSE`, `COPYING`, `NOTICE`, `AUTHORS` and `CONTRIBUTORS` classify as
  `docs`; `.gitattributes`, `.editorconfig`, `.mailmap` and a root `CODEOWNERS`
  as `harness`. Nothing to do this round beyond telling the consuming project.
- **Every assertion added was earned by a reverted mutation**, through
  `scripts/mutate.sh`, each restored byte-for-byte:

  | Mutation | Watched red |
  |---|---|
  | probe rule stops matching (`__*_probe` → `__NEVERMATCH`) | `a probe classifies as test`, `--list source skips probes` |
  | exclusion widened (`**/__*_probe` → `**/*_probe`) | `classify src/ui/heat_probe.ts` — a real module goes invisible |
  | `--list` narrowed to `--cached` only | `an untracked new module is still source` |

  The middle one is the point: it is the trap the report warns about, and without
  it the suite would have accepted an over-broad exclusion that silently removed
  files from every guard.
- **RED was genuine on both halves.** `classify`: 16 of 18 red before the script
  existed (the two that passed assert empty output and could not fail yet).
  `lib`: 3 red on the probe cases before the `paths.conf` rule.
- **The suite is green and larger.** `bash scripts/ci-local.sh` — 13 suites, 520
  assertions, 0 failures. `classify` is new at 18.

## What would have to be true for this to be wrong

- That a naming convention is the right contract. It is a convention, not an
  enforcement: a guard can still write an artifact under any other name, and
  nothing upstream detects that. The report's "seal it from both directions" is
  only half-mechanised here — the classifier will skip a correctly named probe,
  but nothing refuses a badly named one.
- That `__probe_*` does not collide. Two leading underscores plus the word makes
  a real module unlikely, and the widened-exclusion mutation proves the narrow
  form is doing the work. A project with a genuine `__probe_reading.py` would be
  bitten.
- That shelling out per suite is acceptable. A guard calling `classify.sh` once
  and caching is cheap; one call per file would be a process per file, which on
  Windows is slow enough to matter. The convention says once per suite.
- That `git ls-files` is the right enumerator. It is wrong inside a worktree with
  no git — a tarball export, some CI caches — where `--list` returns nothing and
  a guard would see an empty tree. It returns empty rather than erroring, which
  is the vacuous-pass shape; a caller that asserts on a non-empty list is
  protected and nothing makes it do that.

## What was not checked

- **No real project exercised this.** Every test here is a fixture. The consuming
  project's four drifted scanners are the actual subject, and the report's own
  "prove the harmonisation did not narrow anything" step — run every old variant
  against the new shared one over the live tree and compare file lists — can only
  happen there.
- **The race itself was never reproduced.** It needs contention (v8 coverage
  instrumentation widened the window; 1 failure in a full run, 0 in 8 isolated
  runs). What is pinned here is the invariant, not the timing.
- **`--list` was not measured on a large tree.** It classifies per path in bash;
  on a repository with tens of thousands of files this will be slow, and no
  budget was taken.
- **H22 is untouched**, and is a real gap: RED cannot declare a test-only
  dependency. It is filed, not fixed.
- **Whether the consuming project will pick this up.** Same vendoring-currency
  problem as the last two rounds; the stamp added in PR #17 is now `2026-09-13`
  and is the thing that makes the comparison cheap, once that project re-vendors.

## Stories filed

None. Findings from a field report are applied here directly and recorded in this
