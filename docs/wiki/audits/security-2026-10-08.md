# Security audit: the harness itself (run-1, `quick`, repo-wide)

The first `/security-audit` run, made as HARNESS-043's DV-1 to set the command's
budget default. It audited this repository with Cloudflare's vendored
`security-audit` skill at `c1c8a8c`. Raw run output is outside the repository
at `~/security-audit-skill/agentic-dev-harness/run-1/` (`run-metadata.json`,
`architecture.md`, `coverage-ledger.json`, `findings.json`, `REPORT.md`,
`FINDINGS-DETAIL.md`, `NEEDS-VALIDATION.md`, and one `agents/<id>/` directory per
dispatch).

## Scope

Audited: the whole tree at `df37b71` (HARNESS-043 GREEN; the story file was
dirty), profile `quick`, strict budget 16 agent invocations. One hunter wave
over nine coverage units, one final critic, one fresh verifier per candidate
performing both the Phase 3 candidate check and the Phase 5 record check, as
`quick` merges them.

Deliberately left out by the profile, not by choice: a second hunter wave, a
separate final-clean critic, and separate Phase 3 and Phase 5 verifiers.
**No target code was executed** — see *What was not checked*.

## Decided

These are conclusions. A story citing this audit follows them without reopening
them; the numbers they rest on are in *Evidence* and are not settled.

1. **Nothing was confirmed, and "nothing found this run" is the only honest
   verdict.** Five source-grounded leads exist, every one `needs_validation`;
   zero `confirmed`, zero `rejected`. No lead has a severity, because none has
   a bounded observed result. Do not read this as "clean": Cloudflare's own
   measurement is that one run finds roughly half of what repeated runs find,
   and this run's coverage is partial (below).
2. **Every lead is one boundary read five ways: the auto-approval list in
   `.claude/settings.json`, and the files CI trusts as evidence, let the agent
   do more than the user consented to or than the docs claim.** Ranked by the
   impact the trace would have if it holds:
   - `task.sh/eval-args/allowlisted-prefix` — `scripts/task.sh:50` runs
     `eval "$cmd" "$@"`, so a quoted argument to an auto-approved command is
     re-parsed as shell. Fix shape: `eval "$cmd \"\$@\""`.
   - `settings.json:allow:git-log-diff-output-arbitrary-write` — `git log`
     and `git diff` are auto-approved by prefix and both accept
     `--output=<file>`; the lock's parser has no `--output` rule.
   - `story-id/path-traversal/allowlisted-scripts` — `new-story.sh:11`,
     `gates.sh:332`, `phase.sh:158` join an unvalidated id into a path; all
     three are auto-approved.
   - `workflows/pull-request/self-attested-ci-verdict` — the PR's own
     `check-boundaries.sh`, `gates.sh` and `project.conf` produce the CI
     verdict about the PR, and `harness` is writable in GREEN/GATES. Law 3's
     literal sentence holds; the "defence in depth where the hook was never in
     the loop" claim (`boundaries.yml:3-6`, `lib.sh:6-8`) does not.
   - `check-boundaries/gate-record/unauthenticated-result-text` — the gate
     record's marker is a public constant and its `result:`/`PASS` lines are
     unbound docs text; CI's `gates.sh` has no story and so does not apply
     `required_gates`.
3. **These are not findings to fix from this audit.** They become stories only
   once validated. The command's rule — one `fix` story per *confirmed*
   finding or cluster — filed **no story**, because nothing is confirmed. The
   three leads whose only blockers are "no sandbox" and "how Claude Code
   matches `Bash(prefix:*)`" can each be settled in a throwaway Claude Code
   session in minutes; the owner-observed checks are in `NEEDS-VALIDATION.md`.
   A story to make the fixes test-first is the right next shape once one
   holds, and the fixes are small (an argument check, a `--output` rule, an
   id regex).
4. **The budget default is 18, from this run's 16.** 16 was spent exactly
   with 5 candidates and one hunter lost to a safety classifier; DV-1's rule
   adds one reserve verifier (17), and one more covers a critic-reassigned unit
   that `quick` would otherwise defer with no spare call (18). A run with a
   sixth candidate at 16 would have been `incomplete` with an unvalidated
   fingerprint.
5. **The phase lock itself was not audited.** Both `hook-stdin::phase-guard`
   units are deferred (below). Nothing in this document speaks to whether the
   lock keeps its stated guarantees.

  `git log -1 --format=format:probe --output=<scratch>/probe-out.txt` was
  **refused** ("Permission to use Bash with command … has been denied.",
  `is_error: true`) and wrote no file; `git log -1 --oneline` **ran**. On the
  settings *before* HARNESS-047 the same probe was not blocked at all (git
  then failed it on the format - see the correction below). So the consent
  half of lead 2 is closed by the deny rule for `git log`, with two limits:
  the transcript cannot show whether a dialog appeared (for the plain
  `git log`, the session scrollback the user pasted shows none); and only
  `git log` was probed live - the `git diff *--output*` deny is pinned by text
  only. Full record: `docs/backlog/stories/HARNESS-047.md`, DV-2.
- **Correction, 2026-10-10.** The record for lead 2 said a bare
  `--format=<string>` is tformat. It is not: git treats a `--format` value as
  a template only when it contains `%` (local git docs,
  `git-log.html:1747-1749` and `:2782`); `--format=probe` is looked up as a
  named pretty format and git exits 128 before writing. The probe command in
  `NEEDS-VALIDATION.md` and `findings.json` is corrected to
  `--format=format:probe`. Found by the session that ran the check.

## What would have to be true for this to be wrong

- Claude Code's `Bash(prefix:*)` matcher refuses or prompts on arguments
  containing `;`, `$(`, `>` or `../` regardless of the allow rule — then leads
  1–3 widen no consent and are hardening only.
- `git log --output` is intercepted by a built-in dangerous-flag check — then
  lead 2 is hardening only.
- Branch protection on `main` requires a human review that reads harness-path
  diffs and `## Gate results` edits — then leads 4–5 are reviewer-dependent
  residuals.
- The agents read the attack-class blocks they were pointed at rather than
  skimming them; the hunters' negative conclusions ("holds", "design") rest on
  that.

## What was not checked

- **Nothing was executed.** This host has no OS-enforced sandbox, so the
  skill's rule applied: every finding is source-traced and anything that
  needs execution stays `needs_validation`. No fixture ran, no hook was fed
  JSON, no git command was run with `--output`.
- **The phase lock** (`phase-guard.sh`, `lib.sh` parsers, the `cwd`
  relocation of `HARNESS_ROOT`, the `mutate.sh` exemption, the `.gitignore` +
  `git add -f` composition hunter-wild handed over). Both units blocked, then
  deferred.
- The `project.conf` gate manifest's demotion/waiver/`skipped-when` lines as a
  way for the graded phase to define its own pass; the refresh as an update
  channel (pinning, downgrade, detached HEAD); every auto-approved git prefix
  beyond `log`/`diff` for option-based writers. All three are deferred units.
- Platforms other than Windows 11 / Git Bash; the validators on Linux/macOS.
- Downstream projects (fantasy-world-builder, manga-translator). They run the
  command themselves after a refresh.
- Whether a `standard` run, or a second `quick` run, finds what this one did
  not — Cloudflare's "roughly half" is read out, not measured here.
