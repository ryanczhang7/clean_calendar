## Context

EPIC-05, brief §4.3: "confidence and missing fields are shown rather than
guessed silently". The function returns a confidence per field and a list of
missing fields (CAL-018). The confirm screen marks each field by that state,
never by colour alone, summarises in one `role="status"` line, and puts focus
where the owner's attention is needed (`components.md`, "Confirm screen"
table; `voice.md`, "Confirm screen"; `accessibility.md`, "Live regions").
`EventForm` gains a per-field state prop so the sheet is unaffected (all
fields `confident` by default).

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given a field with confidence below 0.8, when the confirm form
  renders, then the field has the warning background, a warning glyph in its
  label, and the helper "Not sure about this — check it" linked by
  `aria-describedby`; at 0.8 or above it is plain. *Control:* 0.79 must be
  marked and 0.80 must not. (Settled: the 0.8 threshold is `components.md`'s.)
- **AC-2** - Given a field in `missing`, when the form renders, then it has the
  warning background, the glyph, and the helper "Not found in the text — add
  it", and it is empty rather than pre-filled with a guess.
- **AC-3** - Given the proposal, when the form opens, then focus is on the
  first missing field in form order, else the first low-confidence field, else
  Title.
- **AC-4** - Given the proposal, when `confirmSummary` builds the status line,
  then it reads "Found {n} of {total} details." plus " Check {low fields} and
  add {missing fields}." when applicable, with the plain field names from
  `voice.md` - for example "Found 4 of 5 details. Check the kind and add the
  end time." - and it is rendered in a `role="status"` element.
- **AC-5** - Given a proposal with no fields found, when the form renders, then
  every field is empty and the summary reads "Couldn't find event details.
  Fill them in, or try a clearer screenshot."
- **AC-6** - Given Title or Start is still empty, then "Save event" has
  `aria-disabled="true"` and its description names the empty field.

### Block 1 - the pure confirm-state module (AC-1 to AC-6)

`src/capture/confirmSummary.ts`, pure, no React:

```ts
import type { CaptureField, CaptureResponse } from "../../shared/captureSchema";
export const LOW_CONFIDENCE = 0.8;                 // strictly below is low; 0.8 itself is confident
export type FieldState = "confident" | "low" | "missing";
/** The form's names for the five captured fields, in FORM order. */
export const FORM_FIELDS = ["title", "kind", "start", "end", "location"] as const;
export type FormField = (typeof FORM_FIELDS)[number];
export type FieldStates = Record<FormField, FieldState>;
export function fieldStates(response: Pick<CaptureResponse, "confidence" | "missing">): FieldStates;
export function summaryText(states: FieldStates, allDay: boolean): string;
export function firstFocus(states: FieldStates): FormField;        // AC-3
export function blankMissing(value: EventFormValue, states: FieldStates): EventFormValue;   // AC-2
export function saveBlockers(value: EventFormValue): FormField[];  // AC-6: subset of ["title", "start"], form order
export function saveDescription(blockers: FormField[], allDay: boolean): string | null;
export const LOW_HELPER = "Not sure about this — check it";
export const MISSING_HELPER = "Not found in the text — add it";
export const NOTHING_FOUND = "Couldn't find event details. Fill them in, or try a clearer screenshot.";
```

- **Capture → form names:** `title→title`, `kind→kind`, `startsAt→start`,
  `endsAt→end`, `location→location`. Form order is the order above (Title,
  Kind, Starts, Ends, Location - All day and Notes are never marked).
- **`fieldStates`:** a field is `missing` iff its capture name is in
  `response.missing` (the function already normalises: an unmatched kind
  arrives as `kindName: null` **and** `"kind"` in `missing`, `handler.ts`
  150-169, and the prompt lists every null; the client does **not** second-
  guess a null value not in the list - a null `endsAt` with `missing: []` is
  the +1 h default of CAL-020, unchanged). Else `low` iff
  `confidence[name] !== undefined && confidence[name] < LOW_CONFIDENCE`
  (an absent entry is confident - every CAL-020 fixture passes `{}`). Else
  `confident`. **0.79 is low; 0.80 is confident** (AC-1's control).
- **`summaryText`:** `found` = the number of fields not `missing`, of 5
  (story Notes: all-day is derived, not counted). `found === 0` →
  `NOTHING_FOUND` exactly (AC-5). Else `"Found {found} of 5 details."`, then
  when either list is non-empty one more sentence, space-separated:
  `" Check {low} and add {missing}."` with both; `" Check {low}."` with low
  only; `" Add {missing}."` with missing only. Lists are in **form order**,
  joined `"a and b"` / `"a, b and c"` (`voice.md`, "title, start time and
  notes"). Names carry the article: `the title`, `the kind`, `the start
  time`, `the end time`, `the location`; with `allDay` true, start and end
  read `the start date` / `the end date`. `voice.md`'s example holds:
  kind low, end missing, timed → `"Found 4 of 5 details. Check the kind and
  add the end time."`
- **`firstFocus`:** the first `missing` in form order, else the first `low`,
  else `"title"` (AC-3).
- **`blankMissing`:** a `missing` field is **empty, not a guess** (AC-2):
  `title` → `""`; `location` → `""`; `kind` → `kindId: null`; `start` →
  `startDate: ""`, `startTime: ""`; `end` → `endDate: ""`, `endTime: ""`.
  Everything else is `proposalToFormValue`'s value, which keeps its CAL-020
  signature and behaviour exactly (its 14 frozen tests call it with three
  arguments and expect the +1 h / next-whole-hour fallbacks).
- **`saveBlockers`:** `title` when `value.title.trim() === ""`; `start` when
  `startDate === ""` or (`!allDay` and `startTime === ""`). An empty **end**
  does not block (PO decision 3). **`saveDescription`:** `null` for `[]`;
  else `"Add {names} to save."` with the same names and joining - `"Add the
  title to save."`, `"Add the title and the start time to save."` (added to
  `voice.md` by this story).

### Block 2 - `EventForm` gains per-field state (AC-1, AC-2)

`src/events/EventForm.tsx`, one new **optional** prop; every existing caller
(`EventSheet.tsx`, `ConfirmPage.tsx`, both test files) stays valid unchanged:

```ts
fieldStates?: Partial<Record<FormField, FieldState>>;   // default: every field "confident"
```

For a field whose state is `low` or `missing` (the five of `FORM_FIELDS`;
All day and Notes never):
- the field's wrapper (`.field`, or the `Starts` / `Ends` `<fieldset>`)
  carries `data-state="low"` / `"missing"` (the tests' handle; CSS keys the
  `--color-warning-subtle` input background off it, not off a colour-only
  class) - `confident` sets **no** `data-state`;
- the label (`<label>` for Title/Location, the `Kind` `<span>`, the
  `<legend>`) gains a glyph `<svg aria-hidden="true" data-glyph="warning">`
  (a 16 px triangle-bang in `--color-warning`; a real glyph, `aria-hidden`
  because the helper carries the meaning);
- a helper `<p id={…-state}>` with `LOW_HELPER` / `MISSING_HELPER` follows the
  input(s) (before the existing error `<p>` when both render), and every
  input of the field has that id in `aria-describedby` - the Title input, the
  Location input, **both** Start inputs, **both** End inputs. When the end
  also has an error, `aria-describedby="{helperId} {errorId}"` (space-joined,
  helper first). `aria-invalid` is **not** set by a state: a guess is a
  warning, not an error.
- **Kind:** `KindPicker` gains an optional `describedBy?: string` prop
  (`src/events/KindPicker.tsx`; callers `EventForm.tsx`, `KindPicker.test.tsx`
  - the new prop is optional, so both stay valid) and puts it on its
  trigger `<button aria-haspopup="listbox">` as `aria-describedby`.

The sheet renders without the prop and is **byte-for-byte unaffected** in
markup: every `EventSheet.test.tsx` and `EventForm.test.tsx` case stays
green and untouched (new cases are appended to `EventForm.test.tsx`).

### Block 3 - `moveStart` with an empty start (AC-2)

`src/domain/eventForm.ts`, `moveStart(value, startDate, startTime)` keeps
its signature. Today it carries the end along by the old duration; with a
blanked start (`startDate === ""`) there is no duration: the amended rule is
**when the previous start is empty, set the start and leave the end as it
is** (empty stays empty; a filled end stays). An all-day toggle (`setAllDay`)
with an empty start keeps it empty. Every existing `eventForm.test.ts` case
(all of them start from a filled value) stays green and untouched; the new
cases are appended there. RED checks what the shipped `moveStart` does with
`""` and amends this block if the rule already holds.

### Block 4 - the confirm page (AC-3 to AC-6)

`src/capture/ConfirmPage.tsx`, props and `proposalToFormValue` unchanged.
With a handoff:
- `states = fieldStates(handoff.response)` once; the initial value is
  `blankMissing(proposalToFormValue(proposal, kinds, now), states)`; the
  late-kinds lookup (CAL-020) still applies only while `kindId` is `null` -
  and **not at all when `kind` is `missing`** (a missing kind stays empty).
- After the `<h1>`, before the `<form>`: `<p role="status">{summaryText(
  states, value.allDay)}</p>` (AC-4), computed from the **proposal's** states
  - it does not change as the owner edits (the announcement is the
  proposal's; `accessibility.md`: "then the confirm summary (status)"). The
  no-state render keeps exactly one `role="status"` (the frozen CAL-020
  lookups).
- `EventForm` gets `fieldStates={states}` (the full record is a valid
  `Partial`).
- **Focus on open (AC-3):** `firstFocus(states)` → the element: `title` the
  Title input; `kind` the picker trigger; `start` the `Start date` input;
  `end` the `End date` input; `location` the Location input. Applied once,
  in an effect, **after RouteFocus has focused the `<h1>`** (CAL-020 Block 5
  measured RouteFocus running later in the same commit; `queueMicrotask`
  landed after it) and no earlier than the first render - the kind trigger
  exists before the kinds load, so the focus does not wait for them.
  Nothing else moves focus on open.
- **Save (AC-6):** `blockers = saveBlockers(value)`; Save has
  `aria-disabled="true"` while `blockers.length > 0 || busy` (CAL-020's
  `title.trim() === ""` rule is now the `title` blocker), and while blockers
  exist `aria-describedby` points at a visually-hidden `<p id>` holding
  `saveDescription(blockers, allDay)`; with none, no `aria-describedby` and
  no `<p>`. At submit, an **empty end** (PO decision 3) is filled before
  `validate`: timed → start + 1 h; all-day → `endDate = startDate`. Then as
  CAL-020: `validate`, the kind-required focus, `createEvent(...)`.
- The missing/low marking is computed from the proposal and does **not**
  clear as the owner types (the helper says what the model did; the owner
  sees their edit in the field). RED may amend if `components.md`'s table is
  read otherwise.
