## Context

EPIC-06, brief §4.5: birthdays repeat yearly, gym weekly. The expander exists
(CAL-023); this story puts its output on the calendar and adds the Repeat
field to the event form (`components.md`, "Event sheet", field 7, and "Event
chip", Recurring variant). Views read occurrences through a new
`useOccurrences(start, end)` hook that combines `useEventsInRange` and
`useOverrides` (CAL-014) with `expand`, so the cache stays the single source
the views render from.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given the form, when Repeat is set to Weekly on an event starting
  Wednesday 14 October 2026, then the helper reads "Every Wednesday" and an
  Ends choice of "Never" or "On date" appears; Yearly reads "Every year on 14
  October"; Daily reads "Every day".
- **AC-2** - Given Repeat = Weekly and Ends = On date 30 November 2026, when the
  event is saved, then it is stored with `recurrence = {freq: 'weekly', until:
  '2026-11-30', tz: <device zone>}`; "Does not repeat" stores `null`; an end
  date before the start date shows "The series must end after it starts." and
  nothing is saved.
- **AC-3** - Given a weekly series in the cache, when the month view for
  November 2026 renders, then a chip appears on every Wednesday of the series
  that falls in the grid's 42 days, including the leading and trailing days of
  adjacent months.
- **AC-4** - Given an occurrence chip, when it renders, then it shows a repeat
  glyph and its accessible name includes ", repeats weekly" (or daily,
  yearly).
- **AC-5** - Given a cancelled override for one occurrence in the cache, when
  the view renders, then that occurrence has no chip and the others do.
- **AC-6** - Given an occurrence chip, when it is opened, then the sheet shows
  the occurrence's own date and time with the series' repeat settings.

**Block 1 - the form model (`src/domain/eventForm.ts`).** `EventFormValue`
gains three required fields; every existing literal in the tree (31 in four
test files, listed in Block 9) gains them too:

```ts
export type RepeatFreq = "none" | "daily" | "weekly" | "yearly";
export type EventFormValue = {
  /* existing fields unchanged */
  repeat: RepeatFreq;          // "none" = Does not repeat
  repeatEnds: "never" | "on";  // meaningful only while repeat !== "none"
  /** yyyy-MM-dd; meaningful only while repeatEnds === "on" */
  repeatUntil: string;
};
export type FormErrors = { title?: string; end?: string; repeatUntil?: string };
export const REPEAT_UNTIL_ERROR = "The series must end after it starts.";
export function repeatHelper(value: EventFormValue): string | null;
```

- `newEventValue(...)` returns `repeat: "none", repeatEnds: "never",
  repeatUntil: ""`.
- `valueFromEvent(event)`: `recurrence === null` → the three defaults above;
  otherwise `repeat = recurrence.freq`, `repeatEnds = until === null ?
  "never" : "on"`, `repeatUntil = until ?? ""`.
- `repeatHelper`: `"none"` → `null`; `"daily"` → `"Every day"`; `"weekly"` →
  `` `Every ${format(start, "EEEE")}` `` ("Every Wednesday" for 2026-10-14);
  `"yearly"` → `` `Every year on ${format(start, "d MMMM")}` `` ("Every year
  on 14 October"). `start` is `local(value.startDate)`, so the weekday is the
  start date's, device zone.
- `validate`: in addition to the existing rules, when `repeat !== "none" &&
  repeatEnds === "on"` and (`repeatUntil === ""` or `repeatUntil <
  startDate` as `yyyy-MM-dd` strings) → `errors.repeatUntil =
  REPEAT_UNTIL_ERROR`. `repeatUntil === startDate` is valid (a one-occurrence
  series). While `repeat === "none"` or `repeatEnds === "never"`,
  `repeatUntil` is ignored entirely.
- `toNewEvent` and `patchOf` build `recurrence` as
  `recurrenceOf(value)`: `repeat === "none"` → `null`; otherwise
  `{ freq: repeat, until: repeatEnds === "on" ? repeatUntil : null, tz:
  Intl.DateTimeFormat().resolvedOptions().timeZone }`. `patchOf` sets
  `patch.recurrence` only when it differs structurally from
  `original.recurrence` (compare `freq`, `until`, `tz` field by field; both
  `null` is equal). Tests read the device zone from the same `Intl`
  expression, never a literal.

**Block 2 - the Repeat field (`src/events/RepeatField.tsx`).**

```ts
export function RepeatField(props: {
  value: EventFormValue;
  onChange: (value: EventFormValue) => void;
  error: string | undefined;   // errors.repeatUntil
}): JSX.Element;
```

Markup, in order inside one `<fieldset class=group>` whose `<legend>` is
"Repeat":
1. a native `<select aria-label="Repeat">` with options, in this order and
   with these values and visible texts: `none` "Does not repeat", `daily`
   "Daily", `weekly` "Weekly", `yearly` "Yearly". Changing it sets `repeat`
   and, when the new value is `"none"`, leaves `repeatEnds`/`repeatUntil`
   as they are (they are ignored).
2. when `repeat !== "none"`: a `<p>` helper with `repeatHelper(value)`,
   referenced by the select's `aria-describedby`.
3. when `repeat !== "none"`: a nested `<fieldset>` with visible legend
   "Ends" and `aria-label="Repeat ends"` (the Starts/Ends date fieldset
   already owns the name "Ends"; PO decision 4). Inside, two radios sharing
   one `name`: `<input type="radio" value="never">` labelled "Never" and
   `<input type="radio" value="on">` labelled "On date". When
   `repeatEnds === "on"`, an `<input type="date" aria-label="Repeat until">`
   bound to `repeatUntil`, with `aria-invalid="true"` and `aria-describedby`
   pointing at a `<p class=error>` carrying `error` when it is defined.
   When `repeat === "none"` neither the helper nor this fieldset is in the
   DOM.

`EventForm` renders `<RepeatField>` after the Notes field and before nothing
else (Reminder is a later epic), passing `errors.repeatUntil`. No other
`EventForm` markup changes.

**Block 3 - `Event` carries an optional occurrence date (`src/data/rows.ts`).**

```ts
export type Event = {
  /* existing fields */
  /** CAL-024: set only on an expanded occurrence of a recurring series;
   *  never stored, never sent. Absent (no key) on a stored row. */
  occurrenceDate?: string;
};
```

An expanded occurrence is an `Event` whose `id` is the **series id** (so
opening it edits the series, which is CAL-024's documented limit until
CAL-025), whose `startsAt`/`endsAt`/`title`/`kindId`/`allDay`/`location`/
`notes` are the occurrence's (after overrides), whose `recurrence`,
`origin`, `captureJobId`, stamps and `sync` are the series', and whose
`occurrenceDate` is set. A stored row has no `occurrenceDate` key at all,
and `toEvent`/`toEventInsert` never read or write it.

**Block 4 - the hook (`src/sync/useOccurrences.ts`).**

```ts
export type OccurrencesSnapshot = {
  status: "loading" | "ready" | "unavailable";
  events: Event[];   // non-recurring events in range + occurrences, by startsAt
};
export function useOccurrences(
  start: Date,
  end: Date,                     // half-open [start, end), as useEventsInRange
  stores?: { events?: EventsStore; overrides?: OverridesStore },
): OccurrencesSnapshot;
export function occurrencesIn(
  events: readonly Event[],
  overrides: readonly EventOverride[],
  start: Date,
  end: Date,
): Event[];                      // the pure core; the hook is this over the two snapshots
export function chipKey(event: Event): string;
  // event.occurrenceDate === undefined ? event.id : `${event.id}@${event.occurrenceDate}`
```

`occurrencesIn`: for each event with `deletedAt === null`: if
`recurrence === null`, include it iff it overlaps the range (the existing
`eventsInRange` rule: `startsAt < end && endsAt > start`); otherwise call
`expand(series, overridesForIt, {start, end})` from
`shared/recurrence.ts` with `series` built from the event (its
`recurrence` is non-null there) and `overridesForIt` = the overrides whose
`eventId === event.id`, mapped to `Override` (drop `id`, `eventId`, stamps),
and map each `Occurrence` to the `Event` of Block 3. A series' own stored
row is **never** included as itself: occurrence 0 stands in for it. Result
sorted by `startsAt`, ties by `id`. Overrides for a non-recurring event are
ignored.

`status`: `"unavailable"` if either store is unavailable; else `"loading"`
if either is loading; else `"ready"`. The hook subscribes with
`useSyncExternalStore` to both stores and asks each to `refresh()` once
from an effect when it is `"loading"`, exactly as `useEventsInRange` and
`useOverrides` do, and memoises on `(eventsSnapshot, overridesSnapshot,
start.getTime(), end.getTime())`. Default stores: `eventsStore`,
`overridesStore`.
