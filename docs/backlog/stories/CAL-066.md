## Context

EPIC-04, from `docs/wiki/audits/epic-04-2026-11-06.md` (Decided 7;
Evidence E-STRYKER `src/sync/hydrate.ts` and `src/sync/outbox.ts`, E-HAND
Y2, O293 and O310).

Two outbox rules hold today and are pinned only for the tables or the cases
that happen to be tested:

- **A pull never overwrites a pending override** (`hydrate.ts:32`, CAL-015
  Block 5, extended to overrides by CAL-056). The pull looks up pending ops
  by the outbox's name for each table, and the cache's overrides table is
  named `overrides` while its ops say `event_overrides`. Map it to `""`
  (Stryker `:32:14`), or filter by `table.name` instead of the mapped name
  (Y2), and an override with a queued op is written over by the pull. The
  whole unit project passes 3000 of 3000 (Y2's first full run "failed" on a
  `sw.test.ts` timeout and passed on the re-run, E-FLAKE). The held-row
  cases cover events and kinds, whose two names agree, so they cannot tell
  the mapping from the raw table name. Under the defect an owner's "this
  event only" edit made offline reverts on screen at the next pull. Once its
  op lands, the drain writes only the stamps, so the reverted values can
  stay until the row changes again (reasoned, not observed).
- **Retry and Discard of an op that is already gone do nothing**
  (`outbox.ts:293`, `:310`). With `retryOp`'s `if (op === undefined)
  return` removed (O293), a retry for a seq that no longer exists puts a
  bare `{ status: "queued" }` record into the outbox. It has no table and no
  id, so every later pass throws on it, stops, and keeps everything behind
  it queued. With `discardOp`'s guard removed (O310), it rejects with a
  `TypeError`, which `SyncStatus` and the sheet do not catch. Both are a
  second press away: a toast's Retry after the dialog already retried or
  discarded the op. Both survive the whole unit project (O293 3000/3000;
  O310's one failure is a `noSecrets.test.ts` timeout).

Test-only: the shipped modules are believed correct, so each new assertion
passes on arrival and is earned by the mutant its criterion names.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given a cached override with a queued (and, separately, a
  failed) `event_overrides` op, when a pull returns a newer server copy of
  that override, then the cached override keeps the optimistic value and
  the overrides mark still moves; and an override with no op is written. A
  test fails when `hydrate.ts:32`'s `"event_overrides"` is `""` and when the
  pending filter at `:59` compares with `table.name` (audit Y2).
- **AC-2** - Given an outbox that holds no op with seq 42, when
  `retryOp(db, 42)` resolves, then the outbox is unchanged: the same records,
  and no record without a `table`. A test fails when `outbox.ts:293`'s
  `if (op === undefined) return;` is removed or its condition is `false`.
- **AC-3** - Given an outbox that holds no op with seq 42, when
  `discardOp(db, 42, repos)` is called, then it resolves (it does not
  reject), no repository is called, and the cache is unchanged. A test fails
  when `:310`'s guard is removed or its condition is `false`.
