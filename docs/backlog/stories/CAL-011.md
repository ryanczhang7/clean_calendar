## Context

EPIC-03. Ties the three views together: which period is visible lives in the
URL (`/month/2026-10`, `/week/2026-10-12`, `/day/2026-10-14`; `/` is the last
used view at today), the top bar gets Today, previous/next and the period
title, the view switcher is a radiogroup, the keyboard paths in
`accessibility.md` ("Keyboard paths") work, and on the phone a tapped month
cell shows its day list below the grid (`layout.md`, "Phone specifics").
Controls arrive through `AppShell`'s `toolbar` slot (CAL-002), so the shell is
not edited.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given `/month/2026-10`, `/week/2026-10-14` or `/day/2026-10-14`,
  when the page renders, then that view and period show and the `<h1>` reads
  "October 2026", "12 – 18 Oct 2026" or "Wednesday 14 October 2026"; a week
  URL on any day normalises to that week's Monday.
- **AC-2** - Given each view, when "Next" and "Previous" are pressed, then the
  URL moves by one month, week or day and the buttons are named "Next month" /
  "Previous month" (week, day likewise); "Today" moves to the period
  containing today. On the phone week view they move by one day.
- **AC-3** - Given the view switcher, when Week is chosen while 14 October 2026
  is the focused or selected date, then the URL becomes `/week/2026-10-12`;
  the switcher is a `radiogroup` named "View" with radios Month, Week, Day
  and the current one `aria-checked="true"`; arrow keys move the selection.
- **AC-4** - Given focus in the calendar and not in a text field, when `T`,
  `M`, `W` or `D` is pressed, then the app goes to today or switches view as
  `accessibility.md` lists.
- **AC-5** - Given a focused month cell, when the arrow keys, Home/End or
  PageUp/PageDown are pressed, then focus and `aria-selected` move as
  `accessibility.md` specifies (PageDown from 31 October lands on 30
  November), and the grid is a single tab stop.
- **AC-6** - Given `/` with no stored preference, when it renders, then the
  month of today shows; after the owner switches to week, `/` shows the week
  of today (preference in `localStorage` under `cc.view`).
- **AC-7** - Given the phone breakpoint and the month view, when a cell is
  tapped, then a day list below the grid lists that day's events as 56px rows
  (chip buttons), or reads "No events on {Wed 14 Oct}" with an "Add" button.

### Block 1 - `src/calendar/period.ts` (pure)

```ts
export type View = "month" | "week" | "day";
/** `date` is a local midnight: the 1st for month; for week the URL's day (any weekday); for day the day. */
export type Period = { view: View; date: Date };
export const VIEW_KEY = "cc.view";
/** localStorage[VIEW_KEY] when it is one of the three views; "month" otherwise, or when storage throws. */
export function readView(): View;
/** Writes VIEW_KEY; a throwing storage is swallowed (as `onboarding.ts` does). */
export function storeView(view: View): void;
/** `/` → `{ fallback, today }` normalised; `/month/yyyy-MM`, `/week/yyyy-MM-dd`, `/day/yyyy-MM-dd` → that period; anything else (another route, an unparseable or impossible date) → null. */
export function parsePath(pathname: string, fallback: View, today: Date): Period | null;
/** `/month/2026-10`, `/week/2026-10-14`, `/day/2026-10-14` - the date as held, zero-padded. */
export function periodPath(period: Period): string;
/** The period of view `view` holding `date`: month → its 1st; week → `date` (phone) or `weekStart(date)` (otherwise); day → `date`. */
export function periodOf(view: View, date: Date, phone: boolean): Period;
/** ±1 month (to the 1st) / ±7 days / ±1 day; week on phone moves ±1 day. */
export function shiftPeriod(period: Period, dir: 1 | -1, phone: boolean): Period;
/** The visible-title. See the table. */
export function periodTitle(period: Period, phone: boolean): string;
/** "Previous month" / "Next month" etc.; week on phone says "day". */
export function navNames(view: View, phone: boolean): { previous: string; next: string };
/** One keyboard step from `date` in the month grid, or null for a key it does not handle. */
export function moveDay(date: Date, key: string): Date | null;
```

Titles (`periodTitle`): month `MMMM yyyy` → "October 2026"; day `EEEE d MMMM
yyyy` → "Wednesday 14 October 2026"; week on tablet/desktop runs Monday to
Sunday of `weekStart(date)` (from `src/domain/timeGrid.ts`): same month
`"12 – 18 Oct 2026"`, across a month `"28 Sep – 4 Oct 2026"`, across a year
`"29 Dec 2025 – 4 Jan 2026"` (en dash, spaces); week on phone is the 3-day
window `date − 1 … date + 1` as `"Tue 13 – Thu 15 Oct"` (`layout.md`,
"Phone specifics"; across a month `"Wed 30 Sep – Fri 2 Oct"`, no year).

`parsePath("/week/2026-10-14", …)` keeps `date` = 14 Oct: **the URL is not
rewritten**; AC-1's "normalises to that week's Monday" is what the view and
title show (the week of the 12th) - PO decision 2. `shiftPeriod` on a
desktop week moves from the Monday: next from 14 Oct is 19 Oct.

`moveDay` (AC-5, `accessibility.md`, "In the month grid"): `ArrowLeft`/
`ArrowRight` ±1 day; `ArrowUp`/`ArrowDown` ±7; `Home`/`End` the Monday /
Sunday of that date's week; `PageUp`/`PageDown` ±1 month keeping the
day-of-month, **clamped to the target month's last day** (31 Oct → 30 Nov,
31 Jan → 28 Feb 2027); any other key → null. Pure: it does not know the
visible grid; the caller decides whether the result is in view.

### Block 6 - `src/calendar/MonthView.tsx` gains selection and the keyboard

```ts
export function eventsOnDay(events: Event[], day: Date): Event[];   // occupancy + cell order, now exported for DayList
export function MonthView(props: {
  year: number; month: number; events: Event[]; kinds: KindsSnapshot; today: Date; loading: boolean;
  /** Local midnight of the selected day; the one tab stop. */
  selected: Date;
  /** A click on a cell, or a key that moved the selection (possibly out of the visible grid). */
  onSelect: (date: Date) => void;
}): JSX.Element;
```

- The cell whose `dayKey(date) === dayKey(selected)` has `tabIndex={0}` and
  `aria-selected="true"`; every other cell `tabIndex={-1}` and no
  `aria-selected`. Every `<EventChip>` and "+N more" button inside the grid
  gets `tabIndex={-1}` (Block 7), so **the grid has exactly one element with
  `tabIndex >= 0`** (AC-5, single tab stop). The `useFocusableInteractive`
  suppressions on the cells come out; `useSemanticElements` stays (CAL-009 PO
  decision 14).
- `onKeyDown` on the grid: `moveDay(selected, event.key)`; null → nothing;
  a date → `event.preventDefault()` and `onSelect(date)`. Clicking a cell →
  `onSelect(its date)`.
- Focus follows the selection: after a key-driven `onSelect`, once the
  re-render lands the cell carrying `tabIndex={0}` is focused (a ref set by
  the key handler, consumed in a `useEffect`), including when the page has
  moved the grid to another month in between. A click does not move focus
  programmatically (the click already did).
- No `Enter`/`Space` handling (PO decision 6: that opens the sheet or the
  day view, CAL-012). Everything else in `MonthView` is unchanged, and
  `MonthView.test.tsx`'s existing cases change only by passing the two new
  props (`selected` = today's date in the fixtures unless a case says
  otherwise).

### PO decisions at PLANNED → RED (2026-10-18, lead-po, Fable 5.1)

1. **The period `<h1>` moves into the top bar** (`PeriodNav`, through the
   `toolbar` slot CAL-002 reserved), and `CalendarPage` renders no heading.
   AC-1 says the `<h1>` reads the period; `components.md` puts it in the
   bar; `routes.test` demands exactly one `<h1>`. Consequence: the five
   shell-level suites that assert the heading "Calendar" (CAL-009 PO
   decision 1 kept it so) now assert the period title and join `touches:`.
2. **A week URL is not rewritten.** `/week/2026-10-14` stays in the address
   bar; the view and title show the week of Monday the 12th (AC-1's
   "normalises"), the switcher writes the Monday (AC-3), and previous/next
   move from the Monday. A redirect would break the sign-in tests that
   assert `pathname === "/"` after sign-in, and the phone's 3-day window
   needs the day, not the Monday (CAL-010 AC-6).
3. **On the phone, Week from a selected day goes to that day**
   (`/week/2026-10-14`), since the phone week is the window around it; AC-3's
   `/week/2026-10-12` is the tablet/desktop answer.
4. **`/` renders the stored view in place, no redirect** (AC-6). Same reason
   as decision 2.
5. **`T`/`M`/`W`/`D` listen on `document` while a calendar route is shown**,
   with the same editable/dialog/modifier exclusions as the legend's `L`.
   "Focus in the calendar" is read as "on a calendar route": the bar and the
   grid are one page, and a key that only worked with a cell focused would
   fail the moment the user clicked Today.
6. **`Enter`/`Space` on a cell do nothing yet**: `accessibility.md` routes
   them to the day view or the new-event sheet, which is CAL-012's.
7. **The selected date is a tiny shared store** (`selection.ts`), because the
   grid that owns it and the switcher that reads it (AC-3) are in different
   subtrees (page and shell). Router `state` was the alternative and would
   put a `replace` navigation under every arrow key.
8. **PageUp/PageDown across a month keeps focus in the grid** by navigating
   with `state: { focus: "grid" }`, which `RouteFocus` honours (one guard in
   `routes.tsx`). Today/previous/next still focus the new title.
9. **Chips and "+N more" in the month grid are `tabIndex={-1}`** so the grid
   is one tab stop (AC-5; `accessibility.md`: chips are reached through the
   day list, not Tab). `EventChip` gains a `tabIndex` prop; its three files
   join `touches:` (CAL-013 lists them too and is blocked behind CAL-012).
10. **Epic done-when checked.** "navigation and view switching reflected in
    the URL" is this story; create/edit/drag/delete/undo are CAL-012/013.
    No gap between CAL-010 and here. No Lead Designer dispatch: the top bar,
    switcher, keyboard table and empty-day copy are already specified.
11. **`touches:` amended** (decisions 1, 7, 9 and the CSS modules).

    CAL-011 + CAL-038 as `CONFLICT` on `src/auth/SignInPage.test.tsx`: real,
