## Context

EPIC-07. Source: `docs/wiki/audits/EPIC-07-2026-11-23.md` (Decided 5,
Evidence E-SHEET and E-WHOLE).

When only the Reminder field changed, the sheet saves it without asking for
a scope (CAL-057 Block 4, `src/events/EventSheet.tsx:378-385`). It sets the
`saving` guard, awaits `writeReminder`, and clears the guard on `:382`.
While the guard is set, Save does nothing (`:356`). On a refused write the
sheet shows the save-failed alert and stays open, so the owner can try
again. That is what CAL-057's "a refused reminder write is a failed save:
the alert shows and the sheet stays open" (`EventSheet.test.tsx:2459`)
checks. It never presses Save a second time.

So the mutant `382s/saving.current = false;/saving.current = true;/`
survives the **whole unit project** (E-WHOLE). Under it, after one refused
reminder write every later press of Save is silently ignored. The owner
has to close the sheet and open it again to set the reminder.

Test-only. The shipped sheet is believed correct, so the case passes on
arrival and is earned by its mutant (DV-1). Required gate that would fail:
`unit` (and `coverage`).

## Acceptance criteria

- **AC-1** - Given an existing event with a reminder template of 30, and a
  `setReminder` that resolves a result with status `error` on its first call and
  `ok` on its second, when the owner changes Reminder to "1 hour before",
  presses Save, sees the save-failed alert and presses Save again, then
  `setReminder(id, 60)` has been called twice and the sheet closes (`onClose`
  called once). A test
  fails under `382s/saving.current = false;/saving.current = true;/` on
  `src/events/EventSheet.tsx`, with `setReminder` called once.

1. `await waitFor(() => expect(reminderSelect()).toHaveValue("30"));`
2. `await user.selectOptions(reminderSelect(), "1 hour before");` -

   sheet too, and would make the case fail for the wrong reason.
5. `await user.click(save());` - the same control, looked up again.
6. **First** `await waitFor(() => expect(reminders.setReminder).toHaveBeenCalledTimes(2));`
   This is the assertion the mutant must break, so it comes before any
   `onClose` assertion: AC-1 says the test fails "with `setReminder` called
   once", and the count has to be what the failure message reports.
7. `expect(reminders.setReminder.mock.calls).toStrictEqual([[DENTIST.id, 60], [DENTIST.id, 60]]);`
8. "The sheet closes" is `await waitFor(() => expect(onClose).toHaveBeenCalledTimes(1));`,
   the form every closing case in this `describe` uses (`ReminderHost`
   calls the `onClose` spy and then clears its request).
9. `expect(reminders.clearReminder).not.toHaveBeenCalled();`

**Block 4 - numbers.** 30 is the stored template; 60 is what "1 hour before"
writes; 2 calls is one refused and one accepted; 1 is `onClose` after the
