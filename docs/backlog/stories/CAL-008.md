## Context

EPIC-02, brief §8: "the legend is always reachable", and kinds stay editable
after the walkthrough. Legend: `components.md`, "Kind legend"; kinds page: the
same screen as the walkthrough titled "Event kinds" with Back instead of Done.
Both reuse `KindList` and `KindEditor` from CAL-007. `KindLegend` is a
CAL-002 placeholder that nothing imports: the shell's two "Legend" buttons
(top bar and bottom nav) are inert, so this story wires them in
`src/app/AppShell.tsx` as well as replacing the legend and kinds-page files
(PO decision 1, `## Notes`; the earlier text here said the shell already
rendered the legend, and `rg KindLegend src` shows it does not).

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given live kinds, when "Legend" is pressed, then a popover with
  `role="dialog"` named "Kind legend" lists every live kind in `sort_order` as
  a list item with its swatch, initial and name, followed by a link "Manage
  kinds" to `/kinds`.
- **AC-2** - Given the legend open, when Escape is pressed or the pointer goes
  down outside it, then it closes and focus returns to the "Legend" button;
  pressing `L` while focus is not in a text field toggles it.
- **AC-3** - Given a legend row, when it is activated, then `/kinds?kind={id}`
  renders with that kind's editor open.
- **AC-4** - Given zero live kinds, when the legend opens, then it reads "No
  kinds. Add one." with an "Add" button that opens the add-kind editor on
  `/kinds`.
- **AC-5** - Given `/kinds`, when it renders, then the heading is "Event
  kinds", a "Back" button returns to the previous calendar route, and renaming
  a kind there persists exactly as in the walkthrough (one smoke case; the
  editor's own behaviour is CAL-007's).

### Block 2 - `src/kinds/KindLegend.tsx` (replaces the placeholder)

```ts
import type { KindsStore } from "../sync/kindsStore";
export function KindLegend(props: {
  open: boolean;
  /** The one way the legend asks to open or close; the shell owns `open`. */
  onToggle: (open: boolean) => void;
  store?: KindsStore;            // default: the app's kindsStore
}): JSX.Element | null;
```
Always mounted by the shell (Block 4); renders `null` while `open` is false.

**Markup while open**, in DOM order, inside one
`<div role="dialog" aria-labelledby={titleId} data-legend>`:
1. `<h2 id={titleId}>Kind legend</h2>`;
2. with at least one live kind: `<ul>` with one `<li>` per kind of
   `useKinds(store).kinds` (the store's order, which is `sort_order`), each
   `<li>` holding exactly one `<Link to={"/kinds?kind=" + kind.id} state={{ from }}>`
   whose content is `<KindSwatch kind />` then the name in a `<span>`. The
   swatch is `aria-hidden`, so the link's accessible name is the kind's
   name (`getByRole("link", { name: "Movies" })`); AC-1's "swatch, initial
   and name" is asserted on the swatch's text (the initial) and its
   `--swatch-light`/`--swatch-dark` properties, as `KindList.test.tsx` does.
   After the list: `<Link to="/kinds" state={{ from }}>Manage kinds</Link>`;
3. with zero live kinds (`status === "ready"` and `kinds.length === 0`):
   no `<ul>`; `<p>No kinds. Add one.</p>` and
   `<button type="button">Add</button>`, which closes the legend and
   `navigate("/kinds?kind=new", { state: { from } })`. No "Manage kinds"
   link in this state;
4. while the store is `loading` or `unavailable`: the heading only
   (`components.md`: kinds are cached before the grid renders, so this is
   transient and gets no copy).

`from` is `location.pathname + location.search` of the shell route the
legend was opened on, read at click time (PO decision 3). It is passed as
router `state`, never in the URL.

**Behaviour:**
- On the transition to `open`, remember `document.activeElement` as the
  opener and move focus to the first focusable control in the dialog (the
  first row link, else "Add", else nothing).
- **Closing with focus return** (AC-2): `Escape` pressed anywhere in the
  document while open, or a `pointerdown` whose target is outside the dialog
  and outside any element carrying `data-legend-toggle`, calls
  `onToggle(false)` and then focuses the remembered opener - the Legend
  button that opened it in AC-2's case. When the opener is gone from the
  document or was `document.body` (opened with `L` from nowhere), focus the
  first `[data-legend-toggle]` in the document instead. The focus call is
  the one line GATES removes for the deferred verification.
- **Closing by navigation**: activating a row link, "Manage kinds" or
  "Add" calls `onToggle(false)` and does **not** touch focus - the route
  change moves focus to the new page's `<h1>` (`routes.tsx`, `RouteFocus`),
  and the opened editor then takes it (Block 3).
- **`L` toggles it** (AC-2): one `keydown` listener on `document` for the
  component's whole life. It fires `onToggle(!open)` when `event.key` is
  `"l"` or `"L"` with no `ctrl`/`meta`/`alt`, the event is not
  `defaultPrevented`, and the target is not editable - not inside
  `input, textarea, select, [contenteditable="true"]` - and not inside an
  open modal `dialog[open]` (the kind editor on `/kinds`). The same listener
  handles Escape as above, so Escape and `L` share one registration.
- The `pointerdown` listener is registered only while open, as
  `AccountMenu` in `AppShell.tsx` does; both listeners are removed on
  unmount and the open one on close.
- The legend remembers nothing and filters nothing (`components.md`).

**Amended in RED (2026-10-16, test-developer):** on the `pointerdown` path the
focus call has to land *after* the pointer's own focus handling, so a
synchronous `opener.focus()` inside the listener is not enough. Reason,
measured: the `mousedown` that follows a `pointerdown` on a non-focusable
target blurs the active element to `<body>` - in browsers, and in
user-event 14.6.7 (`system/pointer/mouse.js`, `down` → `focusElement`). A
throwaway probe (a pointerdown listener focusing a button, then
`user.click(<p>)`) ended on `BODY` with the synchronous call and on `BUTTON`
with the call deferred by `setTimeout(…, 0)`. So defer it (a macrotask, or the
following `click`/`pointerup`); the test awaits it with `vi.waitFor`. Not
constrained, and the implementer's choice: whether the deferred call skips
refocusing when the pointer landed on another focusable control outside the
legend (the test's outside target is a plain `<p>`). Escape keeps the
synchronous call; its test asserts focus immediately after the key. GATES'
deferred verification therefore has two focus calls to remove, not one.

`KindLegend.module.css`: desktop, a popover `position: absolute` under the
top-bar control (`--shadow-2`, `--z-panel`, `min-width: 240px`, rows 48px
with the hover tint `--color-surface` and the focus ring from `tokens.md`);
below 600px the same element is a bottom sheet (`position: fixed; inset:
auto 0 0 0`, padded by `env(safe-area-inset-bottom)`). jsdom sees none of
this; CAL-031 does.

### Block 3 - `src/kinds/KindsPage.tsx` (replaces the placeholder)

```ts
export function KindsPage(props?: { store?: KindsStore; actions?: KindActions }): JSX.Element;
```
The walkthrough's screen with a different title and Back instead of Done
(`components.md`). Markup, in order: `<h1 tabIndex={-1}>Event kinds</h1>`;
`<KindList kinds={useKinds(store).kinds} onEdit=…>`;
`<button type="button">Add kind</button>`; `<button type="button">Back</button>`.
No intro line (that copy is the walkthrough's), no Done, never disabled.
`KindEditor` is rendered with `open` exactly as `WalkthroughPage` does
(`kind` = the row's kind, or `null` for "Add kind"; `actions` passed through),
so AC-5's rename is `KindEditor`'s own behaviour over the same
`createKindActions(repo, store)`: the row shows the new name and
`repo.update` received `(kind.id, { name }, kind.updatedAt)`.
`KindsPage.module.css` may simply re-export nothing and the page may reuse
`WalkthroughPage.module.css`'s classes by importing that file; either is
fine - say which in the handoff.

**`?kind=`** (AC-3, AC-4; PO decision 4): read from `useLocation().search`
in an effect that runs when the store's `status` becomes `ready` (and again
if `search` changes): `new` → open the add editor (`kind: null`); a value
equal to a **live** kind's id → open that kind's editor; anything else
(absent, unknown, soft-deleted) → nothing. The URL is not rewritten on open
or close; after that first read the editor is ordinary local state, as in
the walkthrough. "Renders with that kind's editor open" means
`getByRole("dialog", { name: "Edit Movies" })` is present, with its Name
input holding `Movies`.

**Back** (AC-5; PO decision 3): `navigate(target)` where `target` is
`location.state?.from` when that is a string and a calendar route, else
`"/"`. Never `navigate(-1)`: a page reached by URL has no app history to go
back to, and `/capture` is not a calendar route.
