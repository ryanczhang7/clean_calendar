## Context

EPIC-05. Source: `docs/wiki/audits/epic-05-2026-10-31.md` (Decided 4;
Evidence E-DENO O7, O7b).

`requireOwner` (`supabase/functions/_shared/owner.ts:28-59`) is the
authorization check every function makes. Its fail-closed branches are pinned:
a fetch that throws (O6), a non-2xx (O4), `false`, `null`, the string `"true"`
(O5, O5b). One is not. When `is_owner()` answers **2xx with a body that is not
JSON**, the `catch` after `res.json()` (line 55-57) returns 403. Changing that
to `return null` (admit the caller, O7), or making `res.json()` fall back to
`true` (O7b), leaves all 160 Deno tests green.

PostgREST answers JSON, so the trigger is unlikely: a proxy or a misconfigured
`SUPABASE_URL` serving an HTML 200. But this is the one unpinned branch of the
check that decides who may call Gemini on the owner's key.

Test-only: the shipped check is believed right, so the assertion passes on
arrival and is earned by its mutant.

Required gate that would fail if this broke: `deno-test`.

## Acceptance criteria

- **AC-1** - Given a bearer token and `is_owner()` answering 200 with the body
  `<html>ok</html>` (content type `text/html`), when `requireOwner` runs, then
  it returns 403 `{error: "forbidden"}` with the CORS headers. A test fails
  under O7 (`56s#return forbidden();#return null;#` on `owner.ts`).
- **AC-2** - Given `is_owner()` answering 200 with an empty body, then
  `requireOwner` returns 403. A test fails under O7b
  (`54s#answer = await res.json();#answer = await res.json().catch(() => true);#`).
- **AC-3** - Given the same unreadable 200 through `handleCapture` with a valid
  text body, then the reply is 403, Gemini is never called and no job row is
  written. A test fails under O7.
