## Context

EPIC-05. Source: `docs/wiki/audits/epic-05-2026-10-31.md` (Decided 2;
Evidence E-DENO H63, H16, G19, H1, H31).

The Deno suite (160 tests) kills 92 of the audit's 119 valid hand mutants of
the capture function. Five survivors in `handler.ts` and `gemini.ts` change
what the function sends or how it answers:

- **H63**: the job-row write `POST /rest/v1/capture_jobs` (`handler.ts:295-303`)
  with its `"content-type": "application/json"` header deleted. All 160 pass.
  Deno's `fetch` then labels the string body `text/plain;charset=UTF-8`. The
  audit did **not** measure what PostgREST does with that. If it refuses it,
  every capture writes no row and answers 502. The AC-5 header test
  (`handler_test.ts:496`) checks the anon key, the JWT and `Prefer`, but not the
  content type. The owner-check POST and the Gemini POST already have a pinned
  content type (O16, G24 killed).
- **H16**: `handler.ts:102`, `body !== null ? body : {}` → `body`. A JSON
  `null` body then makes `Object.hasOwn(null, "image")` throw. The request gets
  the runtime's 500 with no CORS headers, instead of 400 `bad_request`.
- **G19**: `gemini.ts:140`, the `catch` that sets `body = null` when a Gemini
  200 is not JSON, made to throw. Nothing tests a 200 with a non-JSON body. A
  throw there escapes the handler: no job row, and no CORS headers on the 500.
- **H1**: `handler.ts:197`, `req.method !== "POST"` → `=== "GET"`. PUT, PATCH
  and DELETE are then handled as captures. Only GET is tested as 405.
- **H31**: `handler.ts:160`, the null-`kindName` branch returning `reply`
  unchanged. `missing` then keeps the model's duplicates whenever the model
  itself said `kindName: null`. AC-2 of CAL-018 says `missing` loses duplicates.
  Only the matched and unmatched branches are tested.

Test-only: the shipped code is believed correct, so each assertion passes on
arrival and is earned by its audit mutant.

Required gate that would fail if this broke: `deno-test`.

## Acceptance criteria

- **AC-1** - Given a successful text capture, when the job row is written,
  then that POST carries `content-type: application/json`, and its body
  parses as JSON. A test fails under H63
  (`299s#"content-type": "application/json",##` on `handler.ts`).
- **AC-2** - Given a POST with a valid bearer and the body `null` (the JSON
  literal), when the handler runs, then it answers 400 `{error:
  "bad_request"}` with the CORS headers, and nothing is fetched. The same
  holds for the bodies `42` and `"text"`. A test fails under H16
  (`102s#body !== null ? body : {}#body#`).
- **AC-3** - Given Gemini answers 200 with a body that is not JSON (`"<html>"`),
  when `callGemini` runs, then it resolves `{kind: "reply", text: ""}` and does
  not reject. Given the same answer through the handler, the reply is 502
  `{error: "unreadable"}`, with CORS headers and a discarded job row. A test
  fails under G19 (`140s#body = null;#throw new Error("x");#` on `gemini.ts`).
- **AC-4** - Given a PUT, a PATCH and a DELETE with a valid bearer and a valid
  text body, when the handler runs, then each is 405 `{error:
  "method_not_allowed"}` and nothing is fetched. A test fails under H1
  (`197s#!== "POST"#=== "GET"#`).
- **AC-5** - Given the model replies with `kindName: null` and `missing:
  ["title", "kind", "title"]`, when the reply is mapped, then the response's
  and the job row's `missing` is `["title", "kind"]`. A test fails under H31
  (`160s#return { ...reply, missing };#return reply;#`).
