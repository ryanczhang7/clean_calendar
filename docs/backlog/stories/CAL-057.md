## Context

EPIC-07, brief §4.6. Split out of CAL-026 on 2026-11-03 (CAL-026, Notes, PO
decision 1, the owner's choice): CAL-026 is the sync layer for `reminders`
(`ReminderActions` `setReminder` / `clearReminder` over the outbox, the
drain, catch-up, `useReminder(eventId)`, and `deleted_at` on the table);
this story is what the owner sees on top of it - the sheet's Reminder field
(`components.md`, "Event sheet", field 8), saving it with the event, and the
chip's bell ("Event chip", Reminder variant; `accessibility.md`, the chip's
name). Its criteria are CAL-026's original AC-1, AC-2, AC-4 and AC-5, with
the form half of its AC-3. `touches:` is a first estimate; the contract,
written at this story's PLANNED, settles it.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given the form, when the Reminder select is opened, then it offers
  None, At time, 5, 10, 15 and 30 minutes, 1 hour, 2 hours and 1 day before,
  mapping to `minutes_before` null, 0, 5, 10, 15, 30, 60, 120, 1440.
- **AC-2** - Given a new event saved with "30 minutes before", when it is
  written, then the outbox holds the event op followed by a `reminders` insert
  with `minutes_before = 30` and `occurrence_date = null`.
- **AC-3** - Given an event with a reminder, when its sheet opens the field
  shows that reminder; when it is changed and saved `setReminder` is called
  with the new value, and when it is set to None `clearReminder` is called; a
  change to the reminder alone is a change the sheet saves.
- **AC-4** - Given an all-day event, when "At time" is chosen, then the helper
  reads "At 09:00 on the day" and the stored `minutes_before` is `-540`
  (09:00 after the event's local midnight start).
- **AC-5** - Given an event with a live reminder, when its chip renders, then a
  bell glyph shows and the accessible name includes ", reminder 30 minutes
  before" (", reminder at start time" for 0; ", reminder 1 day before").

**Block 1 - `src/domain/reminder.ts` (new, pure).** The one place the
reminder's values, labels and phrases live.

```ts
export type ReminderChoice =
  | "none" | "at" | "5" | "10" | "15" | "30" | "60" | "120" | "1440";
/** In the select's order (components.md, field 8). */
export const REMINDER_OPTIONS: readonly { choice: ReminderChoice; label: string }[];
/** 09:00 after an all-day event's local-midnight start, as minutes BEFORE it. */
export const ALL_DAY_AT = -540;
export function minutesFor(choice: ReminderChoice, allDay: boolean): number | null;
export function choiceFor(minutesBefore: number | null): ReminderChoice;
export function reminderHelper(choice: ReminderChoice, allDay: boolean): string | null;
export function reminderPhrase(minutesBefore: number): string;
```

- Labels, in order: "None", "At time", "5 minutes before", "10 minutes
  before", "15 minutes before", "30 minutes before", "1 hour before", "2 hours
  before", "1 day before" (voice.md: "reminder", never "notification").
- `minutesFor`: "none" -> null; "at" -> 0 timed, `ALL_DAY_AT` (-540) all-day;
  every other choice -> its number (5, 10, 15, 30, 60, 120, 1440). The sign:
  `minutes_before` counts back from the event's start, so -540 is 540 minutes
  AFTER an all-day event's local-midnight start: 09:00 on the day (AC-4).
- `choiceFor`: null -> "none"; 0 and -540 -> "at"; a listed number -> its
  choice; any other number (another client's value) -> "none", for display
  only: Block 4's touched rule keeps it from being overwritten.
- `reminderHelper`: "At 09:00 on the day" for ("at", allDay true); null
  otherwise.
- `reminderPhrase`: 0 -> "at start time"; -540 -> "at 09:00 on the day";
  60 -> "1 hour before"; 120 -> "2 hours before"; 1440 -> "1 day before"; any
  other n -> `${n} minutes before`.

**Block 2 - `src/events/ReminderField.tsx` (new).** Mirrors `RepeatField`
(CAL-024): a `<label>` "Reminder" and a native `<select>` whose accessible
name is "Reminder", one `<option>` per `REMINDER_OPTIONS` entry (`value` =
the choice, text = the label). When `reminderHelper` is non-null a `<p>`
helper follows and the select is `aria-describedby` it.

```ts
export function ReminderField(props: {
  choice: ReminderChoice;
  allDay: boolean;
  onChange: (choice: ReminderChoice) => void;
}): JSX.Element;
```

**Block 3 - `EventForm`.** One optional prop, `reminder?: { choice:
ReminderChoice; onChange: (c: ReminderChoice) => void }`. Given, it renders
`ReminderField` after `RepeatField` (field 8 is last) with `allDay =
value.allDay`; absent, nothing changes, so ConfirmPage, which does not pass
it, is untouched. `EventFormValue` is NOT extended (that would break every
hand-built form value in ConfirmPage and the test helpers).

**Block 4 - `EventSheet`.** Two optional props: `reminderActions?:
ReminderActions` (default the app's `reminderActions`) and `remindersStore?:
RemindersStore` (default the app's `remindersStore`; the test setup's global
fake-indexeddb makes the default safe in existing suites).

- **What it shows.** `original = useReminder(id, store)`, where `id` is
  `request.event.id` in edit mode (an occurrence carries its series' id,
  `rows.ts:54`, so an occurrence's sheet shows and writes the series'
  template, one per event) and `""` in create mode (no template: "None").
  `originalMinutes = original?.minutesBefore ?? null`. A `chosen:
  ReminderChoice | null` state starts null (untouched); the field shows
  `chosen ?? choiceFor(originalMinutes)`, so a store that loads after the
  sheet opens still fills an untouched field.
- **Touched rule.** `reminderChanged = chosen !== null &&
  minutesFor(chosen, value.allDay) !== originalMinutes`. Only a touched field
  can change, so an unlisted stored value shown as "None" is never cleared by
  an unrelated save.
- **Dirty (AC-3).** `dirty = formDirty || reminderChanged`; "Discard
  changes?" and Save both see the reminder.
- **Save order (AC-2).** The event write first, then the reminder write, each
  awaited, so the outbox holds the event op before the `reminders` op.
  - create: `createEvent` ok -> if the choice is not "none",
    `setReminder(row.id, minutesFor(choice, value.allDay))`.
  - edit: the existing path runs (patch, occurrence scope) when the patch is
    non-empty; then, when `reminderChanged`, "none" -> `clearReminder(id)`,
    else `setReminder(id, minutesFor(chosen, value.allDay))`. An empty patch
    with `reminderChanged` writes only the reminder, then closes; an empty
    patch with no reminder change closes as today. After an edit-scope answer
    the reminder is written once the scoped write succeeds.
  - A non-`ok` reminder result is a failed save: `SAVE_FAILED` shows and the
    sheet stays open, as for the event. (Known edge, not handled here: in
    create mode a retry after a refused reminder write would create the
    event again; the outbox write is local and is not expected to refuse.)

**Block 5 - the chip.** `src/calendar/chipReminders.ts` (new):
`export const ChipRemindersContext = createContext<ReadonlyMap<string,
number>>(new Map())`, event id -> the live template's `minutesBefore`. Its
empty default means no caller that does not provide it changes.

- `EventChip` reads it with `event.id` (occurrences carry the series' id).
  When it has a value: a 12px "bell" glyph after the title, `aria-hidden`
  (the name carries it), as CAL-024's repeat glyph is.
- `chipName(event, kind, reminderMinutes?: number)`: a new optional third
  parameter; given, `, reminder ${reminderPhrase(reminderMinutes)}` is
  inserted after the repeats part and before the sync marker
  (`accessibility.md:99` order). Both `aria-label`s pass it.

**Block 6 - `CalendarPage`.** Two optional props, `reminders?:
RemindersStore` (default `remindersStore`) and `reminderActions?:
ReminderActions` (default `reminderActions`). It subscribes
(`useSyncExternalStore`), builds the map of live templates (`liveTemplate`'s
rule: `occurrenceDate === null && deletedAt == null`) eventId ->
`minutesBefore`, provides `ChipRemindersContext` around the views, and
passes `remindersStore` and `reminderActions` to `EventSheet`.

**Callers of changed signatures** (`rg` against `0d0b573`):

## Notes

- Created 2026-11-03 by the lead-po orchestrator (Fable 5.1) when CAL-026
  was split (CAL-026, Notes, PO decision 1).
- **Carried from CAL-026 - all-day "At time".** `components.md` says an
  all-day event's "At time" means 09:00 on the day. Storing it as a negative
  `minutes_before` (`-540`) keeps the scheduler's rule a single formula,
  `fire_at = start - minutes_before`, for every event.

  override cannot carry a reminder, and the template belongs to the series.
  The likely answer mirrors CAL-025 PO decision 4 (a repeat-rule change is
  always a series change, with no edit-scope dialog), but it is a product
  decision for the owner, not settled here.

- **PLANNED -> RED 2026-11-11 (lead-po orchestrator, Fable 5.2).**

     copy, the chip's bell comes from a context (`ChipRemindersContext`)
