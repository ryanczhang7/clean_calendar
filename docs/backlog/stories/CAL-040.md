## Context

EPIC-03, from `docs/wiki/audits/epic-03-2026-10-21.md` (Decided 3;
Evidence E-HAND H6, H7, H8 and E-STRYKER `src/calendar/useChipDrag.ts`).

`useChipDrag` (CAL-013, Block 4) is pinned well on the paths the tests take:
Stryker killed 112 of 135 mutants, and the rest are equivalent or acceptable
except five. A sixth defect, which Stryker cannot express, survives
**the whole unit suite** (1603/1603):

- **Dragging left or up** (`useChipDrag.ts:106-107`). With `Math.abs`
  dropped from the threshold, a chip moved left or up never starts a drag,
  so an event cannot be dragged to an earlier day or an earlier time. Every
  pointer move in every suite has a positive dx or dy (`pressAndMove(chip, 3
  | 4 | 30, 0)`, `MonthView.test.tsx:1188` 100 → 140, `TimeGrid.test.tsx:841`
  100 → 160, and so on).
- **Listeners outliving the press** (`:97`, `:99`). A `pointermove`
  listener left on `document` after a plain click turns the next 4 px of
  pointer movement into `dragging = true`, and nothing clears it. In a
  browser, `TimeGrid` then keeps `data-dragging`, and its CSS turns off
  pointer events on every block (`TimeGrid.module.css:132`). That part is
  reasoned, not observed (jsdom applies no CSS). The `keydown` one is
  milder: a stale Escape handler nulls a later drag's cleanup.
- **A click with no pointerdown before it** (`:76` initial `swallow`,
  `:135` its disarm). Keyboard Enter or Space on a chip fires `click` with no
  pointer events. With the swallow flag armed at mount, or never disarmed
  after a drop, that click is eaten, so the keyboard user's first Enter on a
  chip does nothing. Every drag-enabled test click goes through pointerdown,
  which resets the flag.
- **Only Escape cancels** (`:122`). With the check made `true`, any key
  (Shift, an arrow) cancels a drag in progress.

Test-only: the shipped hook is believed correct, so each new assertion
passes on arrival and is earned by its mutant.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given a chip with `onDrop`, when it is pressed and moved 4 px
  **left**, then a drag starts and a pointerup on a day cell drops there;
  and the same for 4 px **up**. A test fails when `Math.abs` is removed from
  either axis of the threshold (`useChipDrag.ts:106`, `:107`; audit H6).
- **AC-2** - Given a press released without reaching the threshold, when the
  pointer later moves 30 px with no button down, then `dragging` stays
  false. A test fails when `removeEventListener("pointermove", …)` is
  removed or given another type (`:97`; audit H7). In `TimeGrid`, the grid
  then carries no `data-dragging`.
- **AC-3** - Given a drag that has ended (dropped, cancelled by Escape, or
  released below the threshold), when it ends, then `document` holds none of
  the hook's three listeners. A test fails when any one of the three
  `removeEventListener` calls (`:97`, `:98`, `:99`) gets another type. Spying
  on `document.addEventListener`/`removeEventListener` is acceptable here;
  pair it with the behavioural AC-2.
- **AC-4** - Given a drag-enabled chip just mounted, when it receives a
  `click` with no pointerdown before it (as keyboard Enter fires), then the
  chip's `onClick` runs. And given a completed drop that swallowed its one
  click, when a second click arrives with no pointerdown, then it runs too.
  A test fails when `swallow` starts `true` (`:76`) and when the disarm at
  `:135` sets `true` (audit H8).
- **AC-5** - Given a drag in progress, when a key other than Escape (e.g.
  `Shift`, `ArrowRight`) is pressed, then the drag continues and a pointerup
  on a cell drops there. A test fails when the Escape check is `true`
  (`:122`).

  `dragging === false`. Include it only if it costs one case.
- Earning: one `scripts/mutate.sh` run per AC against
  `src/calendar/useChipDrag.test.tsx` (and `TimeGrid.test.tsx` for AC-2's
  second half), using the audit's expressions. AC-1 must go red with the H6
  expression, which removes `Math.abs` on both axes. Also run it once per
  axis.
- No production change. If an AC turns out to describe behaviour the hook
  does **not** have (it should not), stop and put it to the PO. That is a
  fix story, not a test edit.
