## Context

EPIC-01. The brief (§6) admits one Google account. The **security** of that
rule is row-level security (CAL-004); this story is the **experience** of it:
the sign-in screen, the redirect through Supabase Auth's Google provider, and
the refusal a different account sees. The allowed e-mail reaches the client as
`VITE_OWNER_EMAIL`, so this story does not depend on the schema. Copy is fixed
in `docs/wiki/design/voice.md` ("Sign-in screen"); the screen in
`components.md` ("Sign-in screen").

Required gate that would fail if this broke: `unit` (supabase-js auth is mocked
at the module boundary of `src/lib/supabase.ts`; the real Google round trip is
checked by hand and CAL-031 injects a session).

## Acceptance criteria

- **AC-1** - Given no session, when any app route is visited, then the user is
  redirected to `/signin`, which shows the heading "Clean Calendar", the line
  "Your calendar, with every event coloured by what it is.", a button "Sign in
  with Google" and the footnote "One account, yours only.", and the original
  path is remembered.
- **AC-2** - Given `/signin`, when "Sign in with Google" is clicked, then
  `supabase.auth.signInWithOAuth` is called once with `provider: 'google'` and
  a `redirectTo` on the current origin, and the button shows its busy state
  (`aria-busy="true"`).
- **AC-3** - Given a session whose e-mail equals `VITE_OWNER_EMAIL` ignoring
  case and surrounding whitespace, when the app loads, then the remembered
  path (else `/`) renders.
- **AC-4** - Given a session for any other e-mail, when the app loads, then no
  app route renders, an element with `role="alert"` reads "This calendar
  belongs to another account. Sign out and try the right one.", and its "Sign
  out" button calls `supabase.auth.signOut` and returns to `/signin`.
  *Control:* `owner@example.com.evil.test` against an owner of
  `owner@example.com` must be refused - no prefix or substring match.
- **AC-5** - Given `navigator.onLine` is false and no session, when `/signin`
  renders, then the sign-in button has `aria-disabled="true"` and the text
  "Sign-in needs a connection" is shown.
- **AC-6** - Given the owner signed in, when "Sign out" in the account menu is
  chosen, then `supabase.auth.signOut` is called and `/signin` renders.

### Session (`src/auth/session.ts`, `session.test.ts`)

- `export function isOwnerEmail(email: string | null | undefined, owner?: string): boolean`
  - `owner` defaults to `OWNER_EMAIL`. Both sides are `trim()`med and
    `toLowerCase()`d, then compared with `===`. An empty/absent `email` or an
    empty `owner` is `false` (an unconfigured owner admits nobody).
  - **Control cases, pinned** (owner `owner@example.com`):
    | input | result |
    |---|---|
    | `"owner@example.com"` | true |
    | `"  Owner@Example.COM \n"` | true |
    | `"owner@example.com.evil.test"` | **false** (AC-4's control: no prefix) |
    | `"xowner@example.com"` | false (no suffix) |
    | `"owner@example.co"` | false (no substring) |
    | `""`, `null`, `undefined` | false |
    | any input, owner `""` | false |
- `export type SessionState =
    | { status: "loading" }
    | { status: "signed-out" }
    | { status: "owner"; email: string }
    | { status: "other"; email: string }`
- `export function useSession(): SessionState` - starts `loading`; on mount
  calls `supabase.auth.getSession()` and classifies
  `session?.user?.email` with `isOwnerEmail`; subscribes
  `supabase.auth.onAuthStateChange((_, session) => …)` and unsubscribes on
  unmount (`data.subscription.unsubscribe()`).
- `export function signInWithGoogle(): Promise<void>` - exactly one call
  `supabase.auth.signInWithOAuth({ provider: "google", options: { redirectTo: \`${window.location.origin}/\` } })`.
  AC-2's "on the current origin" means `redirectTo` starts with
  `window.location.origin`.
- `export function signOut(): Promise<void>` - `supabase.auth.signOut()`.
- Remembered path: `export const RETURN_TO_KEY = "cc.returnTo"`;
  `export function rememberPath(path: string): void` writes it to
  `sessionStorage`; `export function takeReturnTo(): string` reads and
  **clears** it, returning `"/"` when absent. `sessionStorage` rather than
  `localStorage` so a stale target does not survive the tab.

### Gate (`src/auth/RequireOwner.tsx`, `RequireOwner.test.tsx`)

- `export function RequireOwner(): JSX.Element` - a layout route element,
  rendered **around** `AppShell` in `routes.tsx`:
  - `loading` → renders `null` (nothing visible; the cache-first open is
    CAL-014's concern).
  - `signed-out` → `rememberPath(location.pathname + location.search)` then
    `<Navigate to="/signin" replace />`. `/signin` itself is never
    remembered.
  - `other` → renders, **instead of** the Outlet:
    `<main><h1 tabIndex={-1}>Clean Calendar</h1><div role="alert">This calendar belongs to another account. Sign out and try the right one.</div><button type="button">Sign out</button></main>`.
    The button calls `signOut()` and then navigates to `/signin`.
  - `owner` → `<Outlet />`.

### Sign-in screen (`src/auth/SignInPage.tsx`, `.module.css`, `.test.tsx`)

- `export function SignInPage(): JSX.Element` (same export as the
  placeholder; the route line in `routes.tsx` does not change).
- If `useSession()` is `owner` → `<Navigate to={takeReturnTo()} replace />`
  (AC-3). If `other` → the same refusal markup as `RequireOwner` (so a
  non-owner who lands on `/signin` directly also sees it). Otherwise the
  card, inside a `<main>` landmark (so `e2e/boot.spec.ts`'s `main` + `h1`
  at `/` stays true after the redirect):
  - `<h1 tabIndex={-1}>Clean Calendar</h1>`
  - `<p>Your calendar, with every event coloured by what it is.</p>`
  - `<button type="button">Sign in with Google</button>` - secondary style,
    48px tall, full width (`components.md`). Click → `signInWithGoogle()`;
    the button sets `aria-busy="true"` and keeps it (the page is about to
    redirect). `aria-busy` is absent before the click.
  - `<p>One account, yours only.</p>` (12px muted).
  - **Offline (AC-5):** `navigator.onLine === false` → the button has
    `aria-disabled="true"`, clicking it calls nothing, and a sibling
    `<p>Sign-in needs a connection</p>` is shown. The page listens to
    `window` `online`/`offline` events and re-renders. Tests set
    `vi.spyOn(navigator, "onLine", "get")` and dispatch the events.
