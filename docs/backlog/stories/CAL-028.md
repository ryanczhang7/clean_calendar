## Context

EPIC-07, brief §4.6 and success criterion 4: a reminder must fire with the app
closed, which needs a server-side scheduler. `architecture.md`, "How the
pieces talk" and "Reminders": `pg_cron` calls the `send-reminders` edge
function every minute through `pg_net` with the service-role key (read from
Vault); the function selects due reminders, sends a Web Push (VAPID,
`npm:web-push`) to every subscription, marks `sent_at`, and prunes dead
subscriptions. The service worker shows the notification and opens the event
on click. This story handles non-recurring events; occurrences of a series
are CAL-029.

Required gates that would fail if this broke: `deno-test` (handler with the
database and push sender stubbed), `unit` (the worker's push handlers as plain
functions), and `db` (the cron migration), so `db` is in `required_gates`.

## Acceptance criteria

- **AC-1** - Given a request without a bearer JWT whose `role` claim is
  `service_role`, when the function is called, then it returns 401 and reads
  nothing.
- **AC-2** - Given live reminders (`deleted_at` null, `occurrence_date` null)
  whose event is not recurring and not soft-deleted, when the function runs at
  `now`, then exactly those with `fire_at = starts_at - minutes_before` in
  `[now - 5 min, now]` and (`sent_at` null or `sent_at < fire_at - 5 min`) are
  due. *Control:* a reminder due 6 minutes ago, one due in 1 minute, one
  already sent for this `fire_at`, the template of a recurring series, a
  soft-deleted reminder, and a reminder of a soft-deleted event must all be
  excluded; one sent before its event was moved 10 minutes later (`sent_at <
  fire_at - 5 min`) is due again.
- **AC-3** - Given a due reminder and two subscriptions, when it is sent, then
  each subscription receives one push whose payload is `{eventId, title,
  startsAt, allDay, location}` (`startsAt` the event's start as an ISO 8601
  instant, `location` a string or null), and `sent_at` is set once both
  attempts finish.
- **AC-4** - Given a push answered 404 or 410, when it is sent, then that
  subscription row is deleted and the reminder is still marked sent; any other
  failure leaves the subscription and is logged.
- **AC-5** - Given `supabase db reset`, when `cron.job` is inspected, then one
  job runs every minute (`* * * * *`) and posts to the `send-reminders`
  function URL with the service-role key, both taken from Vault; with neither
  Vault entry present (the local stack) the job's command runs without error
  and posts nothing.
- **AC-6** - Given the worker receives a push with that payload, when its push
  handler runs, then it calls `showNotification(title, {body, data: {url},
  tag: eventId})` with `body` "{HH:mm} · {location}" (or "{HH:mm}", or "All
  day") and `url = /day/{yyyy-MM-dd}?event={eventId}`, the time and the day
  both in the device's own zone; on `notificationclick` it focuses an open
  app window and navigates it to `url`, or opens a new window at `url`.

**Block 2 - the handler.** `supabase/functions/send-reminders/handler.ts`,
same seam as `capture/handler.ts`: every outbound call goes through
`deps.fetch`, tests answer from a routing table keyed by `METHOD url`.

```ts
export type SendDeps = {
  fetch: typeof fetch;
  env: (name: string) => string | undefined;
  now: () => Date;
  /** null when the VAPID secrets are not set (index.ts decides) */
  sendPush: ((sub: Subscription, payload: PushPayload) => Promise<PushOutcome>) | null;
  log: (line: string) => void;
};
export type Subscription = { id: string; endpoint: string; p256dh: string; auth: string };
export type PushPayload = {
  eventId: string; title: string; startsAt: string; allDay: boolean; location: string | null;
};
export type PushOutcome =
  | { status: "sent" }
  | { status: "gone"; code: 404 | 410 }
  | { status: "failed"; code: number | null; message: string };
export type ReminderRow = {
  id: string; minutes_before: number; sent_at: string | null;
  event: { id: string; title: string; starts_at: string; all_day: boolean; location: string | null };
};
export const WINDOW_MS = 5 * 60_000;
export function isServiceRole(req: Request): boolean;
export function fireAt(startsAt: string, minutesBefore: number): Date;
export function isDue(fireAt: Date, sentAt: string | null, now: Date): boolean;
export function dueReminders(rows: ReminderRow[], now: Date): ReminderRow[];
export function payloadFor(row: ReminderRow): PushPayload;
export async function handleSendReminders(req: Request, deps: SendDeps): Promise<Response>;
```

Semantics, in order:

1. `isServiceRole`: `bearer(req)` from `_shared/owner.ts` is non-null **and**
   the token's middle segment base64url-decodes to JSON whose `role` is
   exactly `"service_role"`. No signature check here - the gateway
   (`verify_jwt = true`, Block 7) has done that. False → `401 {error:
   "unauthorized"}` via `jsonResponse`, before any fetch (AC-1).
2. A method other than `POST` → `405 {error: "method"}`. (Checked after the
   token, so AC-1's "reads nothing" is also "reveals nothing".)
3. `deps.sendPush === null` → `503 {error: "vapid not configured"}`, before
   any read: a misconfigured deployment must not mark reminders sent.
4. The candidates, one read with the function's own service key (`apikey`
   and `authorization: Bearer` both `deps.env("SUPABASE_SERVICE_ROLE_KEY")`;
   the edge runtime injects it and `SUPABASE_URL`):
   `GET {SUPABASE_URL}/rest/v1/reminders?select=id,minutes_before,sent_at,event:events!inner(id,title,starts_at,all_day,location)&deleted_at=is.null&occurrence_date=is.null&event.deleted_at=is.null&event.recurrence=is.null`
   (the `!inner` join lets the two `event.` filters drop the parent row). A
   non-2xx, a throw or a non-array body → `502 {error: "upstream"}`. The
   due set is `dueReminders(rows, deps.now())`; `fireAt = Date.parse(starts_at)
   - minutes_before * 60_000` (a negative `minutes_before`, the all-day
   `-540`, fires *after* midnight: 09:00 on the day); `isDue` is `now -
   WINDOW_MS <= fireAt && fireAt <= now && (sent_at === null || Date.parse(sent_at)
   < fireAt - WINDOW_MS)`. The window's lower bound is what the Deferred
   verification mutates.
5. No due reminder → `200 {due: 0, sent: 0, pruned: 0, failed: 0}` with no
   further read.
6. `GET {SUPABASE_URL}/rest/v1/push_subscriptions?select=id,endpoint,p256dh,auth`
   (same headers; failure → 502). For each due reminder in the order
   returned, for each subscription in the order returned, **sequentially**
   (deterministic call order for the tests): `await deps.sendPush(sub,
   payloadFor(row))`. `payloadFor` is the five fields of `PushPayload` from
   the row: `eventId = event.id`, `startsAt = event.starts_at` as stored,
   `location = event.location` (null stays null; `""` becomes null).
7. Outcomes: `sent` → counted; `gone` → `DELETE
   {SUPABASE_URL}/rest/v1/push_subscriptions?id=eq.{sub.id}` once per
   subscription for the whole run (a second `gone` for the same id sends no
   second delete) and no further pushes to that subscription in this run;
   `failed` → `deps.log("send-reminders: push to {sub.id} failed: {code}
   {message}")`, the subscription kept (AC-4). A delete that fails is logged
   and does not change the response.
8. After every attempt for one reminder - whatever the outcomes, and also
   when there are zero subscriptions - `PATCH
   {SUPABASE_URL}/rest/v1/reminders?id=eq.{row.id}` with headers `Prefer:
   return=minimal`, `content-type: application/json` and body
   `{"sent_at": deps.now().toISOString()}` (AC-3, AC-4). A reminder nobody
   could receive is still marked, so a dead deployment does not retry every
   minute for five minutes; the 503 in step 3 is what protects the
   misconfigured case.
9. `200 {due, sent, pruned, failed}`: `due` the reminders, `sent` the
   attempts that returned `sent`, `pruned` the distinct subscriptions
   deleted, `failed` the attempts that returned `failed`.

**Block 3 - the push sender.** `supabase/functions/send-reminders/push.ts`,
with **no npm import** so `push_test.ts` runs offline under `--allow-net=127.0.0.1`:

```ts
export type WebPushLike = {
  setVapidDetails(subject: string, publicKey: string, privateKey: string): void;
  sendNotification(
    sub: { endpoint: string; keys: { p256dh: string; auth: string } },
    body: string,
    options?: { TTL?: number },
  ): Promise<{ statusCode: number }>;
};
export type Vapid = { subject: string; publicKey: string; privateKey: string };
export const PUSH_TTL_SECONDS = 600;
export function vapidFromEnv(env: (name: string) => string | undefined): Vapid | null;
export function createSender(webPush: WebPushLike, vapid: Vapid): NonNullable<SendDeps["sendPush"]>;
```

`vapidFromEnv` reads `VAPID_SUBJECT`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`
(the three function secrets `deployment.md`, "Later (CAL-028)", names) and is
null when any is missing or empty. `createSender` calls `setVapidDetails`
once, and each send is `sendNotification({endpoint, keys: {p256dh, auth}},
JSON.stringify(payload), {TTL: 600})`: resolves → `{status: "sent"}`; rejects
with an error whose `statusCode` is 404 or 410 → `{status: "gone", code}`;
any other rejection → `{status: "failed", code: err.statusCode ?? null,
message: String(err.message ?? err)}`. The sender never throws. TTL 600 s:
the push service may hold the message ten minutes, after which the reminder
is stale.

**Block 5 - the worker's handlers.** `src/pwa/pushHandlers.ts`: plain
functions with **no imports** (the worker never pulls the cache schema or
date-fns; CAL-022), typed structurally so the file compiles under both
`tsconfig.json` (DOM lib, where the unit tests run) and `tsconfig.sw.json`:

```ts
export type ReminderPayload = {
  eventId: string; title: string; startsAt: string; allDay: boolean; location: string | null;
};
export function pushData(data: { json(): unknown } | null | undefined): unknown; // null when absent or json() throws
export function parseReminderPayload(data: unknown): ReminderPayload | null;
export function reminderBody(p: ReminderPayload, timeZone?: string): string;
export function reminderUrl(p: ReminderPayload, timeZone?: string): string;
export type NotificationTarget = {
  showNotification(title: string, options: { body: string; data: { url: string }; tag: string }): Promise<void>;
};
export async function showReminder(target: NotificationTarget, data: unknown): Promise<void>;
export type WindowClientLike = { focus(): Promise<unknown>; navigate(url: string): Promise<unknown> };
export type ClientsLike = {
  matchAll(options: { type: "window"; includeUncontrolled: true }): Promise<WindowClientLike[]>;
  openWindow(url: string): Promise<unknown>;
};
export async function openReminder(clients: ClientsLike, url: string): Promise<void>;
```

- `parseReminderPayload`: an object with `eventId` and `title` non-empty
  strings, `startsAt` a string `Date.parse` accepts, `allDay` a boolean and
  `location` a string or null (absent counts as null); anything else → null.
- `reminderBody`: `allDay` → `"All day"` (no location, as AC-6 says);
  otherwise `HH:mm` of `startsAt` in `timeZone`, 24-hour, zero-padded
  (`Intl.DateTimeFormat("en-GB", {hour: "2-digit", minute: "2-digit",
  hourCycle: "h23", timeZone})`), then `" · "` (U+00B7, a space either side)
  and the location when it is a non-empty string.
- `reminderUrl`: `/day/{yyyy-MM-dd}?event={eventId}`, the date of `startsAt`
  in `timeZone` (`formatToParts` year/month/day), `eventId` URL-encoded.
- `timeZone` undefined means the device's zone, which is what the worker
  passes. The tests pin the zone to get a settled answer: `startsAt =
  "2026-11-03T05:30:00Z"` is `"05:30"` and `/day/2026-11-03` in
  `Europe/London`, and `"23:30"` and `/day/2026-11-02` in `America/Chicago`
  (UTC-6 on that date). Worked by hand; the Chicago case is the day-boundary
  control the second Deferred verification mutates. One case calls without a
  zone and asserts the result equals the explicit call with
  `Intl.DateTimeFormat().resolvedOptions().timeZone`.
- `showReminder`: `parseReminderPayload(data)`; null → resolves having called
  nothing; else `target.showNotification(p.title, {body: reminderBody(p),
  data: {url: reminderUrl(p)}, tag: p.eventId})` (the tag collapses a resend
  of the same event into one notification).
- `openReminder`: `clients.matchAll({type: "window", includeUncontrolled:
  true})`; a first client → `await focus()` then `await navigate(url)`; none
  → `await clients.openWindow(url)`.
