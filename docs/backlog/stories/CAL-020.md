## Context

EPIC-05, brief §3 step 4 and success criterion 2: a booking e-mail becomes a
correct, correctly coloured event in under 30 seconds including review. This
is the in-app path (a paste box and an image picker); the share-sheet path
(CAL-022) lands on the same screens. Screens: `components.md`, "Capture
screen" and "Confirm screen"; copy: `voice.md`. The confirm screen reuses
`EventForm` from CAL-012 and saves through `createEvent` with
`origin: 'capture'` and the job id. Nothing is saved before the owner
confirms.

Required gate that would fail if this broke: `unit` (the function call is
mocked at `supabase.functions.invoke`).

## Acceptance criteria

- **AC-1** - Given `/capture`, when it renders, then it shows the heading
  "Capture", a textarea labelled "Booking email or text", a "Choose a
  screenshot" control (`<input type="file" accept="image/*">`), and "Propose
  event", which has `aria-disabled="true"` until one input has content.
- **AC-2** - Given text pasted, when "Propose event" is pressed, then the
  function `capture` is invoked with `{text}`, the inputs become read-only,
  the status line "Asking the assistant… usually takes a few seconds." is
  shown, and on success `/capture/confirm` renders the proposal in the event
  form.
- **AC-3** - Given an image picked, when it is proposed, then it is downscaled
  so that its long edge is at most 2048 px and its encoded size at most 4 MB,
  sent as `{image, mime}`, and a 96px thumbnail with "Remove screenshot" was
  shown; with both text and an image present only the image is sent and a note
  says so.
- **AC-4** - Given `navigator.onLine` is false, when `/capture` renders, then
  "Propose event" is disabled and "Capture needs a connection. Your other
  changes are saved and will sync." is shown; given the function returns an
  error, an alert reads "Couldn't read that. Try pasting the text instead."
  with "Retry".
- **AC-5** - Given the confirm screen, when "Save event" is pressed, then
  `createEvent` is called with the edited values, `origin: 'capture'` and the
  `captureJobId`, the job is marked `confirmed`, the app navigates to that
  day in the last-used view with the new chip focused, and the toast "Added
  {title}" with "View" is shown.
- **AC-6** - Given the confirm screen, when "Discard" is pressed, then no event
  is created, the job is marked `discarded`, and `/capture` renders empty.
- **AC-7** - Given the proposal's `kindName`, when the confirm form fills, then
  the kind picker shows the live kind with that name, and every field stays
  editable; "Show what was captured" reveals the original text (or image) for
  comparison, which is not persisted.

### Block 1 - the function client (AC-2, AC-3, AC-4)

`src/capture/captureClient.ts`:

```ts
import { captureResponseSchema, type CaptureResponse } from "../../shared/captureSchema";
export type CaptureInput = { text: string } | { image: string; mime: string };
export type CaptureOutcome =
  | { status: "ok"; response: CaptureResponse }
  | { status: "offline" }                                   // navigator.onLine false, or the fetch threw
  | { status: "error"; code: "upstream" | "unreadable" | "bad_request" | "payload_too_large" | "unsupported_media_type" | "forbidden" | "unauthorized" | "unknown"; http?: number };
export async function proposeEvent(input: CaptureInput, client: SupabaseClient<Database> = supabase): Promise<CaptureOutcome>;
/** What /capture hands /capture/confirm in router state (PO decision 3). */
export type CaptureSource = { kind: "text"; text: string } | { kind: "image"; dataUrl: string; mime: string };
export type CaptureHandoff = { response: CaptureResponse; source: CaptureSource };
```

- Mechanism: `client.functions.invoke("capture", { body: input })`, which
  POSTs `{SUPABASE_URL}/functions/v1/capture` with the session's bearer. A
  reply with `error === null` and `data` that passes `captureResponseSchema`
  is `ok`; `data` failing the schema is `error "unreadable"`; a
  `FunctionsHttpError` is `error` with `code` read from the function's JSON
  `{error}` body when it parses and `http` set to the status; a
  `FunctionsFetchError` (network) is `offline`. **Checkable, not sacred**:
  the test drives the real supabase-js client at `TEST_ORIGIN` with MSW
  answering `POST http://supabase.test/functions/v1/capture`, exactly as the
  repository tests do for PostgREST; if supabase-js 2.117's functions client
  shapes the request or the errors differently, RED amends this block with
  what it measured.
- Nothing in `src/` names the Gemini host or key (CAL-018 AC-7 guard still
  runs).

### Block 2 - the downscaler (AC-3)

`src/capture/downscale.ts`:

```ts
export const MAX_LONG_EDGE = 2048;
export const MAX_IMAGE_BYTES = 4 * 1024 * 1024;              // the function's limit, CAL-019
export const QUALITY_STEPS = [0.92, 0.8, 0.65, 0.5] as const;
/** Pure: the target size. The long edge is capped at `maxEdge`, the aspect kept (rounded), never upscaled. */
export function planDownscale(width: number, height: number, maxEdge?: number): { width: number; height: number; scaled: boolean };
export type Downscaled = { mime: "image/png" | "image/jpeg" | "image/webp"; base64: string; bytes: number; width: number; height: number; dataUrl: string };
export type DownscaleDeps = {
  /** Decode a file: its pixel size and an opaque handle the encoder accepts. */
  decode(file: Blob): Promise<{ width: number; height: number; source: unknown }>;
  /** Draw `source` at width x height and encode it; `quality` applies to lossy types. */
  encode(source: unknown, width: number, height: number, mime: string, quality: number): Promise<Blob>;
};
export const browserDeps: DownscaleDeps;                       // createImageBitmap + canvas; untested in jsdom
export async function downscaleImage(file: Blob, deps?: DownscaleDeps): Promise<{ status: "ok"; image: Downscaled } | { status: "too_large" } | { status: "unsupported" }>;
```

- `planDownscale(4000, 3000)` is `{2048, 1536, scaled: true}`;
  `(3000, 4000)` is `{1536, 2048}`; `(1024, 768)` is unchanged with
  `scaled: false`; `(2048, 10)` is unchanged. Rounding is `Math.round`, with
  a floor of 1.
- Pipeline: `unsupported` unless `file.type` is one of the three accepted
  types; decode; plan; encode at the planned size with the file's own type at
  `QUALITY_STEPS[0]`; while the result is over `MAX_IMAGE_BYTES`: a PNG
  re-encodes as `image/jpeg` first (lossless PNG screenshots are the large
  case), then each type steps down `QUALITY_STEPS`; after the last step
  still over -> `too_large`. `bytes` is the encoded Blob's size; `base64` is
  the standard-alphabet encoding of its bytes (what CAL-019's function
  accepts); `dataUrl` is `data:<mime>;base64,<base64>` for the thumbnail and
  the "what was captured" view.
- Tests use a fake `deps` whose `encode` returns a Blob of a size the test
  chooses per (mime, quality) call, so the step-down order is observable
  without a canvas; jsdom has none.

Markup, in DOM order, inside the app shell's `<main>`:

- `<h1 tabIndex={-1}>Capture</h1>`.
- A `<label>` "Booking email or text" for a `<textarea>` with the `voice.md`
  placeholder, `rows={8}`; beside the label a `<button type="button">Paste</button>`
  that calls `navigator.clipboard.readText()` and appends the text; when the
  API is absent or rejects, it focuses the textarea instead (PO decision 7).
- A drop zone: `<label>` "Choose a screenshot" wrapping a visually hidden
  `<input type="file" accept="image/*">`. Once a file is chosen:
  `<img alt="Screenshot preview">` (96 px tall, the data URL) and a
  `<button type="button">Remove screenshot</button>`, which clears it. Desktop
  drop/paste-image targets are GREEN's choice and untested.
- When both a non-blank text and an image are present: `<p>` "Only the
  screenshot will be sent."
- Offline (`navigator.onLine` false, tracked with the `online`/`offline`
  window events as `SignInPage` does): `<p>` "Capture needs a connection.
  Your other changes are saved and will sync."
- Footer: `<button type="button">Propose event</button>` with
  `aria-disabled="true"` (not the `disabled` attribute: it stays focusable
  and announceable) while there is no content (text blank and no image), or
  offline, or a request is running. A click while `aria-disabled` does
  nothing.
- **Working state** after a click: inputs `readOnly` (the file input and
  Remove `disabled`), the button `aria-busy="true"`, a `role="status"` line
  "Asking the assistant… usually takes a few seconds.", and a
  `<button type="button">Cancel</button>` that abandons the request (its
  result, when it arrives, is ignored) and restores the inputs.
- **What is sent:** image present -> `downscale(file)` then
  `{ image: base64, mime }`; else `{ text }` with the text as typed
  (trimmed only for the emptiness check). The image wins when both are
  present (AC-3).
- **Success:** `navigate("/capture/confirm", { state: handoff })` with
  `CaptureHandoff` (Block 1): `source` is `{kind:"text", text}` or
  `{kind:"image", dataUrl, mime}`.
- **Errors**, each a `role="alert"` strip with a `<button>Retry</button>`
  that re-sends the same input:
  - `error` (any code) -> "Couldn't read that. Try pasting the text instead."
  - `offline` -> the offline notice above (no Retry needed; the button
    re-enables when `online` fires).
  - downscale `too_large` -> "That screenshot is too large, even after
    shrinking it. Try cropping it."; `unsupported` -> the same strip with
    "Couldn't read that. Try pasting the text instead." (no vendor talk).
- The page is reached with no state and keeps none: a fresh render after a
  Discard is empty (AC-6).

### Block 4 - the confirm page (AC-5 to AC-7)

`src/capture/ConfirmPage.tsx`:

```ts
export function ConfirmPage(props?: {
  actions?: EventActions;                     // default eventActions (the outbox)
  jobs?: Pick<CaptureJobsRepo, "setStatus">;  // default captureJobs
  kinds?: KindsStore;                         // default kindsStore
}): JSX.Element;
/** Pure: the form's initial value from a proposal. Exported for its tests. */
export function proposalToFormValue(proposal: Proposal, kinds: Kind[], now: Date): EventFormValue;
```

- Reads `useLocation().state` as `CaptureHandoff`; with none (a reload, a
  typed URL) it renders the `<h1>` below and a `role="status"` line
  "Nothing to confirm. Start from Capture." whose "Capture" is a `<Link
  to="/capture">`, and no form or buttons (PO decision 3; Block 8 says why
  it is not a redirect).
- `<h1 tabIndex={-1}>Check the details</h1>`, then `EventForm` (CAL-012)
  with `kinds` from `useKinds(store)`, `kindRemoved={false}`, `titleId` for
  the first focus (Title; CAL-021 moves focus to missing fields).
- `proposalToFormValue`:
  - `title`: `proposal.title ?? ""`; `location`: `proposal.location ?? ""`;
    `notes`: `""`.
  - `kindId`: the live kind whose `name` equals `proposal.kindName` after
    `trim().toLowerCase()` on both, else `null` (the picker then shows
    nothing chosen; CAL-021 marks it Missing).
  - dates: `startsAt` parsed with `new Date(proposal.startsAt)` when it is a
    string and parses (`!Number.isNaN(+d)`); otherwise `now` rounded up to
    the next whole hour. `endsAt` likewise; when absent or not after the
    start, start + 1 h (timed) or the same day (all-day). Then the form
    value is `newEventValue(start, end, proposal.allDay, kindId)` with the
    title/location set - so a date-only `startsAt` (`"2026-11-03"`) parses
    as midnight UTC and lands on the right calendar day in zones west of UTC
    only when `allDay` is true; RED pins the all-day case and the full
    date-time case, and GREEN may amend the date-only+timed rule with a
    reason.
- Buttons, in order: `<button type="button">Discard</button>` (ghost) and
  `<button type="submit">Save event</button>` (primary), the latter with
  `aria-disabled="true"` while `value.title.trim() === ""` or a save is in
  flight.
- **Save:** `validate(value)` as the sheet does (title and end errors shown
  by `EventForm`); with a `kindId` of `null` it saves nothing and focuses the
  kind picker's trigger (a kind is required, as in the sheet). Then
  `actions.createEvent({ ...toNewEvent(value, kindId), origin: "capture", captureJobId: handoff.response.jobId })`;
  on `status !== "ok"` an alert "Couldn't save. Try again." (the sheet's
  copy) and nothing else. On ok: `jobs.setStatus(jobId, "confirmed")`
  (awaited, its failure ignored: PO decision 5), then
  `navigate(periodPath(periodOf(readView(), row.startsAt, phone)), { state: { focusEventId: row.id } })`
  where `phone` is `useBreakpoint() === "phone"`, and
  `showToast({ text: \`Added ${row.title}\`, action: { label: "View", onClick } })`
  whose `View` navigates to `/day/<yyyy-MM-dd of startsAt>` with the same
  `focusEventId` state. `useMaybeToast()`, so a page rendered outside a
  provider still saves.
- **Discard:** `jobs.setStatus(jobId, "discarded")` (awaited, failure
  ignored) then `navigate("/capture", { replace: true })`. No `createEvent`.
- **"Show what was captured"** / "Hide what was captured": a
  `<button type="button" aria-expanded>` toggling a region (`hidden` when
  collapsed) holding `<pre>` with the text, or
  `<img alt="The screenshot you captured">` from the data URL. The source is
  read from router state only; the test asserts no `localStorage` key and no
  PostgREST body carries it.

### PO decisions at PLANNED (Lead PO, 2026-10-26)

1. **Gates.** `unit` and `coverage` (required) read `src/**`. Every artifact
   has a required gate; `required_gates` stays empty.
2. **Both screens are full pages inside the app shell on every breakpoint.**
   `components.md` (concern 5) wants the confirm screen as the desktop side
   panel over the calendar; that is a layout story of its own once CAL-021's
   per-field marking exists. Recorded as a follow-up, not absorbed.
3. **The proposal travels in router state, not storage.** `/capture` hands
   `/capture/confirm` the function's response and the original input through
   `navigate(..., { state })`. Opening `/capture/confirm` with no state
   shows the heading and "Nothing to confirm. Start from Capture." (not a
   redirect: two frozen route tests expect the heading there, Block 8).
   Nothing is written to localStorage, IndexedDB or the server before Save
   (AC-6, `architecture.md`: the input is not persisted).
4. **Chip focus after save needs one addition to `CalendarPage`:** when
   `location.state.focusEventId` is set, the page focuses
   `[data-event-id="<id>"]` once that chip is rendered, reusing the focus
   mechanism CAL-011 added. `src/calendar/CalendarPage.tsx` and its test are
   added to `touches:`. The "last-used view" is `readView()` from
   `period.ts`, the key the toolbar already stores.
5. **Job status updates go straight to PostgREST, not through the outbox.**
   A capture needs a connection (AC-4), so the owner is online when
   confirming; a status update that still fails is not retried and does not
   block the save or the navigation. The event is the record that matters;
   the job row is the audit trail.
6. **Image downscaling is automatic and silent.** `components.md` says a
   too-large image "says so and offers to downscale"; the downscale is done
   before sending, so the only case left is an image still over 4 MB after
   it. That shows the alert "That screenshot is too large, even after
   shrinking it. Try cropping it." (added to `voice.md`, Capture screen).
7. **The Paste button is in scope** (`components.md`): it calls
   `navigator.clipboard.readText()` and, on refusal or absence, focuses the
   paste box. It is not in the ACs; the Contract pins it and RED tests it
   lightly.
8. **The `C` shortcut from the calendar is a follow-up.** `useCalendarKeys`
   takes a handlers object, so adding it is a handler, a caller and a test,
   not one line; the story's own Out of scope rule puts it in a follow-up.
9. **Copy not in `voice.md`** is added there in this commit: the
   both-present note "Only the screenshot will be sent.", the buttons "Paste",
   "Remove screenshot", "Retry", "Cancel", the too-large alert, and the
   thumbnail's alt text "Screenshot preview".
10. **Epic done-when.** The in-app paste and pick paths reach the confirm
    screen here; confirming writes `origin = capture` here; the share path is
    CAL-022 and the per-field confidence display is CAL-021. No gap for this
    story to close.
