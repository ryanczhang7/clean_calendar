## Context

EPIC-07 follow-up. Source: `docs/wiki/audits/EPIC-07-2026-11-24.md`
(Decided 4, Evidence E-GUARD). The code is CAL-012's (`git blame`: `98a3635`),
which CAL-057 extended with the reminder write. It is filed under EPIC-07
because both audits of this epic met it, and CAL-088 pinned the same guard on
the reminder-only path only.

Every save that writes the event goes through `commit`
(`src/events/EventSheet.tsx:431-451`). It sets the `saving` guard at `:435`,
awaits the event's write and then the reminder's, and clears the guard at
`:444`. While the guard is set, `submit` returns at `:356` and Save does
nothing. The Save button is never disabled (`grep -n disabled` on the file
finds nothing), so the guard is the only thing that stops a double press from
writing twice.

Two mutants of that guard survive the **whole unit project** (3421 tests,
95 files, at `346c6df`; E-GUARD):

- `444s/saving.current = false;/saving.current = true;/`. After one refused
  save (offline, an error or a conflict: the three `REFUSALS` at
  `EventSheet.test.tsx:565-569`), every later press of Save is silently
  ignored. The owner sees "Couldn't save. Try again.", tries again, and
  nothing happens. Closing asks "Discard changes?", so the only way out loses
  what they typed. The tests at `:571` and `:591` check the alert and that the
  sheet stays open. None presses Save a second time. This is CAL-088's
  defect on the general path.
- `435s/saving.current = true;/saving.current = false;/`. A second press of
  Save while the first write is still in flight writes again. For a new
  event, `createEvent` is called twice and the calendar gets two events. No
  test presses Save twice while a write is pending.

Test-only. The shipped sheet is believed correct, so both cases pass on
arrival and each is earned by its mutant (DV-1, DV-2). The required gate that
would fail if the guard broke after this story: `unit` (and `coverage`).

**From the audit, settled:** these two mutants are a gap, and the story pins
them with tests and does not change `EventSheet.tsx`. **From the audit, to
verify rather than assume:** that both mutants survive today's unit project
(E-GUARD measured it at `346c6df`), and the line numbers `:435` and `:444`.
Re-pin with `sed -n 431,451p src/events/EventSheet.tsx` before RED's first
mutation.

## Acceptance criteria

- **AC-1** - Given an existing event and an `updateEvent` that resolves
  `{ status: "offline" }` on its first call and `ok` on its second, when the
  owner changes the title, presses Save, sees the save-failed alert and
  presses Save again, then `updateEvent` has been called twice with the same
  arguments and the sheet closes (`onClose` called once). A test fails under
  `444s/saving.current = false;/saving.current = true;/` on
  `src/events/EventSheet.tsx`, with `updateEvent` called once.
- **AC-2** - Given a new event with a title, Save pressed once, and that
  press's `createEvent` call not yet resolved, when
  the owner presses Save a second time, then `createEvent` has been called
  once. After it resolves `ok`, the sheet closes (`onClose` called once). A
  test fails under `435s/saving.current = true;/saving.current = false;/` on
  `src/events/EventSheet.tsx`, with `createEvent` called twice.
