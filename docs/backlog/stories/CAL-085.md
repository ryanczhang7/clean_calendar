## Context

EPIC-07. Source: `docs/wiki/audits/EPIC-07-2026-11-23.md` (Decided 3,
Evidence E-DENO and E-JWT).

pg_cron posts to the send-reminders edge function every minute with the
project's service-role JWT. `isServiceRole` in
`supabase/functions/send-reminders/handler.ts` (`:70-84`) decodes the JWT's
middle segment itself (`base64UrlDecode`, `:61-67`) and lets the run go
ahead only when `role` is exactly `service_role`. Anything else is 401, and
nothing fires. So a decoder that mis-reads the real key does not fail
loudly. It answers 401 every minute, and no reminder reaches any device.

Three mutants of that code survive the whole send-reminders Deno suite
(94 tests at `c6a1bac`):

- `:62:39`, `replaceAll("-", "+")` -> `replaceAll("-", "")`. The suite's
  one service-role JWT (`SERVICE_CLAIMS`, `handler_test.ts:91-96`) has a
  `_` in its middle segment and no `-`. A key whose payload has a `-`
  makes the mutated decoder throw `InvalidCharacterError`, so the run
  answers 401. The fixture self-check at `handler_test.ts:101` ("exercises
  base64url and missing padding") accepts `_` **or** `-`, so it is
  satisfied by half the mapping.
- `:63:36`, `(4 - (b64.length % 4)) % 4` -> `(4 + (b64.length % 4)) % 4`.
  The fixture's segment has length % 4 = 2, where the two expressions agree.
  At length % 4 = 3 the mutant pads with `===`, and `atob` throws.
- `:75:7`, `if (parts.length !== 3) return false;` -> `if (false) ...`.
  No test gives a token of two or four segments whose second segment is a
  valid service-role payload. The malformed cases have one segment, or a
  middle segment that does not decode. Under the mutant such a token is
  accepted. The gateway's `verify_jwt = true` (`supabase/config.toml:415-417`)
  rejects it first in production, so this is defence in depth, not an open
  door.

The audit measured the decoder's behaviour under each mutant with a scratch
Deno script (E-JWT). Deno's `atob` accepts unpadded input. So the padding
step matters only when it is wrong, and the mutants that remove it entirely
(`:63:24`, `:63:41`) are equivalent. They are not part of this story.

Test-only. The shipped decoder is believed correct, so each new case passes
on arrival and is earned by its mutant (Deferred verifications DV-1 to
DV-3). Required gate that would fail: `deno-test`.

## Acceptance criteria

- **AC-1** - Given a service-role JWT whose middle segment contains `-` and
  no `_`, `isServiceRole` is true and `handleSendReminders` answers 200,
  not 401. A test fails under
  `62s/replaceAll("-", "+")/replaceAll("-", "")/` on
  `supabase/functions/send-reminders/handler.ts`.
- **AC-2** - Given a service-role JWT whose middle segment has length % 4 = 3,
  `isServiceRole` is true. A test fails under
  `63s/(4 - (b64.length % 4)) % 4/(4 + (b64.length % 4)) % 4/` on the same
  file.
- **AC-3** - Given a bearer token of two segments, and one of four segments,
  whose second segment decodes to `{"role":"service_role"}`, `isServiceRole`
  is false and `handleSendReminders` answers 401 and fetches nothing. A test
  fails under `75s/if (parts.length !== 3) return false;/if (false) return false;/`.

**Block 1 - fixtures.** Build each JWT with the file's own `jwt()` and
`b64url()` helpers (`handler_test.ts:72-84`), choosing a claim value that
gives the property. Each case **asserts its own property** first: the middle
segment `includes("-")` and `!includes("_")` for AC-1, and
`length % 4 === 3` for AC-2. A later edit to the claims must not silently
remove what the case exists for. The audit found example values with a
scratch script: `n: "~~~>"` gives a `-` (length % 4 = 2), and
`n: "ab"` with `role: "service_role"` and no other claims gives
length % 4 = 3. These are evidence, not decisions. With the file's
`SERVICE_CLAIMS` shape (`iss`, `exp`), recompute them.

**Block 2 - where.** Directly after the existing "AC-1: isServiceRole is
true only for ..." test (`handler_test.ts:354`), named with `CAL-085` so
`--filter "CAL-085"` selects exactly the new cases.

**Block 3 - the fixture self-check.** Leave `handler_test.ts:101-107` alone.
AC-1 is what pins the `-` half. Tightening the self-check's `||` would not
earn anything, because it reads the fixture and not the decoder.
