## Context

EPIC-03 (the picker is CAL-012's), found by the EPIC-05 audit:
`docs/wiki/audits/epic-05-2026-10-31.md` (Decided 7; Evidence E-STRYKER
`src/events/KindPicker.tsx`, E-RECHECK K1, R11, R12). It is in that audit's
scope only because CAL-021 touched the file to add `describedBy`. EPIC-03's own
audit did not mutate this file. The epic is EPIC-03 because the behaviour
belongs there. Every CAL-021 line is killed.

Stryker ran `src/events` and `src/capture/ConfirmPage.test.tsx` per mutant and
left 35 of `KindPicker.tsx`'s 122 mutants alive. 21 are gaps:

- **Trigger keys** (`:78-79`). `if (ArrowDown || ArrowUp)` → `true` means
  *any* key opens the list and is `preventDefault`ed, Tab included. Keyboard
  focus then cannot leave the trigger. ArrowUp opening the list is untested
  (R12 survives the whole unit suite). So is the page not scrolling on those
  keys.
- **List keys** (`:87-91`). ArrowDown's clamp `kinds.length - 1` → `+ 1` lets
  the active option run past the end. `aria-activedescendant` then names no
  element, and Enter does nothing. The list's arrow keys may scroll the page.
- **Enter on an empty list** (`:98`). With the `kind !== undefined` guard gone,
  Enter with no kinds throws in `choose`.
- **Escape** (`:103-104`). `preventDefault` and `stopPropagation` each make the
  other redundant. **Both** can be deleted with the events suites green (K1:
  122/122). `EventSheet.tsx:143` then closes the whole sheet on the same Escape
  that closes the list.
- **Tab** (`:107-108`). Tab no longer closes the list.
- **After a choice** (`:59`). `close(true)` → `close(false)`: focus is left on
  the unmounted list instead of the trigger.
- **No kinds** (`:147`). `aria-activedescendant` names `…-option-0`, which
  does not exist.
- **The visible active marker** (`:160`). `data-active`, which the highlight is
  styled on, is never asserted. The tests follow `aria-activedescendant`
  (`KindPicker.test.tsx:93`) only.

Test-only: the shipped picker is believed correct, so each assertion passes on
arrival and is earned by its mutant.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given the picker closed with focus on its trigger, when the owner
  presses Tab, then the list does not open and the keydown's default is not
  prevented. When the owner presses ArrowUp, then the list opens on the chosen
  kind (or the first). In both cases where the list opens, the keydown's
  default is prevented. A test fails under
  `78s#event.key === "ArrowDown" || event.key === "ArrowUp"#true#`, under
  `78s# || event.key === "ArrowUp"##`, and under `79s#event.preventDefault();##`.
- **AC-2** - Given the list open on its last option, when the owner presses
  ArrowDown, then the last option is still active (`aria-activedescendant`
  and `data-active="true"` on it), and Enter chooses it. Given the list open on
  its first option, ArrowUp leaves the first active. Each arrow keydown in the
  list has its default prevented. A test fails under
  `88s#kinds.length - 1#kinds.length + 1#` and under each of the two list
  `preventDefault` deletions (`:87`, `:91`).
- **AC-3** - Given a picker with no kinds, when the owner opens it and presses
  Enter, then nothing throws, `onChange` is not called, and the listbox has no
  `aria-activedescendant`. A test fails under
  `98s#if (kind !== undefined) choose(kind);#choose(kind as Kind);#` and under
  `147s#kinds.length > 0#kinds.length >= 0#`.
- **AC-4** - Given the event sheet open with the picker's list open, when the
  owner presses Escape, then the list closes, focus is on the trigger, and the
  sheet is still open. A test fails under `103,104d` (both guards together).
- **AC-5** - Given the list open, when the owner presses Tab, then the list
  closes. A test fails under `108s#setOpen(false)#setOpen(true)#`, and with the
  `"Tab"` case label emptied.
- **AC-6** - Given the list open, when the owner chooses a kind (by click, and
  separately by Enter), then focus is on the trigger. A test fails under
  `59s#close(true)#close(false)#`.
- **AC-7** - Given the list open, when the active option moves (ArrowDown),
  then exactly one option carries `data-active="true"` and it is the one
  `aria-activedescendant` names. A test fails under each of `:160`'s three
  Stryker forms (`true`, `false`, `!==`).
