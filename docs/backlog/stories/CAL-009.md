## Context

EPIC-03, brief §4.1 and §8: a Google-Calendar-like month grid where each event
is a chip in its kind's colour. Grid: `components.md`, "Calendar grid" and
"Event chip"; maths: `layout.md`, "Grid maths that tests can pin" (six rows,
42 cells, weeks start Monday); names and roles: `accessibility.md`, "Roles
and names"; empty card copy: `voice.md`. Chip colours come from `useKinds()`
and `domain/colour` (CAL-006). Events are read through a new
`useEventsInRange(start, end)` hook in `src/sync/eventsStore.ts`, online
through the repository until CAL-014 moves it onto the local cache behind the
same signature. `CalendarPage` (a CAL-002 placeholder) renders the month of
`/` and `/month/:yyyy-mm`; week and day arrive in CAL-010 and the switching
between them in CAL-011.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given October 2026, when `monthGrid(2026, 10)` is called, then it
  returns 42 dates from Monday 28 September to Sunday 8 November 2026 in
  order, flagging which belong to October; every month returns exactly 42.
  (Settled: `layout.md`.)
- **AC-2** - Given the month view for October 2026, when it renders, then one
  `role="grid"` is named "October 2026", seven column headers are named
  Monday to Sunday, and 42 cells are named like "Wednesday 14 October, 3
  events" ("no events" for zero, "1 event" for one); the cell for today has
  `aria-current="date"`.
- **AC-3** - Given a timed event in a kind, when the month view renders it,
  then it is a `button` named "{title}, {kind name}, {HH:mm} to {HH:mm}" with
  a dot whose background is the kind's `color_light` (light scheme) or
  `color_dark` (dark scheme, `matchMedia` mocked); an all-day event is a
  filled chip in the kind's colour with the text colour `domain/colour`
  chooses, and its name ends ", all day". Each chip shows the kind's initial.
- **AC-4** - Given an event whose kind is soft-deleted, when it renders, then the
  chip uses `--color-chip-neutral`, shows `?` as its initial, and its name
  ends ", kind removed".
- **AC-5** - Given six events on one day, when the grid renders at the desktop
  breakpoint, then four chips show and a button named "2 more events on
  {Weekday} {d} {Month}" follows; at the tablet breakpoint three chips show;
  at the phone breakpoint the cell shows at most four 6px dots in kind
  colours and a "+" with no chips.
- **AC-6** - Given a hotel stay from 12 to 15 October (all-day, ending the
  morning of the 15th exclusive), when the month renders, then a chip appears
  in the 12th, 13th and 14th cells only.
- **AC-7** - Given no events in the visible month and the store loaded, when
  the month renders, then the card "Nothing this month" with "Capture a
  booking" (link to `/capture`) and "or add an event" is shown; one event
  removes it; it is not shown while the store is loading.
- **AC-8** - Given two kinds starting with the same letter, when chips render,
  then each shows its first two letters ("Gy", "Go"); otherwise one letter.

**A day is `[D 00:00, D+1 00:00)` local.** An event occupies day D iff

does not spill into the next day. This predicate is the story's central

### Block 1 - `src/domain/monthGrid.ts`

```ts
export type MonthCell = {
  /** Local midnight of the day. */
  date: Date;
  /** True for the days of the requested month, false for the leading and trailing ones. */
  inMonth: boolean;
};
/** Six Monday-start weeks (42 cells) covering `month` (1..12) of `year`. */
export function monthGrid(year: number, month: number): MonthCell[];
/** The ISO `yyyy-MM-dd` of a local date, for keys and `/day/` URLs. */
export function dayKey(date: Date): string;
```

Semantics: cell 0 is the Monday on or before the 1st of the month - **the 1st
itself when it is a Monday** (June 2026: cell 0 is Mon 1 June, cell 41 is Sun
12 July); cells 1..41 follow by one day each. Always 42, so a month that fits
in five weeks still gets a sixth row of trailing days. Settled values for
AC-1: October 2026 runs Mon 28 Sep 2026 … Sun 8 Nov 2026 (the 1st is a
Thursday, so three leading days); 31 of the 42 are `inMonth`. `month` out of
1..12 throws `RangeError`. Pure, no date-fns needed, but date-fns 4 is a
production dependency already and may be used.

### Block 3 - `src/calendar/media.ts` and `src/test/media.ts`

AC-3 and AC-5 are asserted under jsdom, which applies no media query, so the
theme and the breakpoint are read in JavaScript (PO decision 6, `## Notes`):

```ts
export type ColorScheme = "light" | "dark";
export type Breakpoint = "phone" | "tablet" | "desktop";
/** `window.matchMedia(query).matches`, live; false where matchMedia is missing. */
export function useMediaQuery(query: string): boolean;
/** "dark" when `(prefers-color-scheme: dark)` matches, else "light". */
export function useColorScheme(): ColorScheme;
/** "desktop" at `(min-width: 1024px)`, else "tablet" at `(min-width: 600px)`, else "phone". */
export function useBreakpoint(): Breakpoint;
```

`useMediaQuery` is `useSyncExternalStore` over `matchMedia(query)`'s
`change` event. Where `window.matchMedia` is not a function (jsdom without a
stub) every query is `false`, so the defaults are light and phone - no
throw, and the shell suites that render `/` without a stub keep passing. The
two numbers are `layout.md`'s breakpoints and match `breakpoints.css`.

`src/test/media.ts` (a test helper, so RED writes it):

```ts
export function installMatchMedia(opts: { width: number; colorScheme: ColorScheme }): {
  /** Change the answers and fire `change` on every list handed out. */
  set(opts: Partial<{ width: number; colorScheme: ColorScheme }>): void;
  /** Delete the stub from `window`. */
  restore(): void;
};
```

It defines `window.matchMedia` to answer `(min-width: Npx)` by comparing N
with `width` and `(prefers-color-scheme: X)` against `colorScheme`, returning
objects with `matches`, `media`, `addEventListener`, `removeEventListener`
(and the legacy `addListener`/`removeListener`). Tests assert layout at 375,
768 and 1280 (`layout.md`).

*Amended in RED (2026-10-17, test-developer):* the helper as written also
answers `(max-width: Npx)` and a query joined with `and` (every feature must
match), and answers any other feature `false`; `matches` is a live getter, so
a list read after `set()` gives the new answer even without its listener.
GREEN may use `min-width` or `max-width` queries - both are answered. Reason:
the Contract named only `min-width`, and an implementation reaching for
`max-width: 599px` would otherwise read `false` everywhere and look broken.

### Block 4 - `src/sync/eventsStore.ts`

```ts
import type { EventsRepo } from "../data/events";
import type { Event } from "../data/rows";
export type EventsStatus = "loading" | "ready" | "unavailable";
export type EventsSnapshot = {
  status: EventsStatus;
  /** Live events (deletedAt null), ascending startsAt, then createdAt. */
  events: Event[];
};
export type EventsStore = {
  refresh(): Promise<void>;
  subscribe(listener: () => void): () => void;
  getSnapshot(): EventsSnapshot;
};
export type EventsReader = Pick<EventsRepo, "listLive">;
export function createEventsStore(repo: EventsReader): EventsStore;
/** The app's one store, over `eventsRepo(supabase)` from `../lib/supabase`. */
export const eventsStore: EventsStore;
/** Pure: the events overlapping `[start, end)` - `startsAt < end && endsAt > start`. */
export function eventsInRange(events: Event[], start: Date, end: Date): Event[];
export function useEventsInRange(
  start: Date,
  end: Date,
  store?: EventsStore, // default: eventsStore
): EventsSnapshot;
```

The same shape and discipline as `kindsStore.ts`: `getSnapshot()` is stable
between changes; `refresh()` calls `listLive()` once, shares a request in
flight, publishes `ready` with the rows or `unavailable` keeping the last
rows; the hook asks a `loading` store to refresh from an effect, never during
render. The hook's `events` is `eventsInRange(snapshot.events, start, end)`,
memoised on the snapshot and the two instants' `getTime()`, so a caller
passing fresh `Date` objects each render does not re-filter. The range filter
is client-side over `listLive()` - no repository change (PO decision 8);
CAL-014 moves the hook onto the cache behind this signature (its AC-5 pins
the same overlap rule). Tests use a hand-written `EventsReader` fake
(`vi.fn` per member), as `kindsStore.test.ts` does; the module imports
`../lib/supabase`, so its suite mocks it the same way.

### Block 5 - `src/calendar/EventChip.tsx`

```ts
import type { Event, Kind } from "../data/rows";
export type ChipKind =
  | { status: "live"; kind: Kind; initial: string }
  /** Soft-deleted, or an id the store does not know. */
  | { status: "removed" };
/** The accessible name, exactly as the table below. */
export function chipName(event: Event, kind: ChipKind): string;
export function EventChip(props: { event: Event; kind: ChipKind }): JSX.Element;
```

| Case | `chipName` |
|---|---|
| timed, live kind | `"{title}, {kind.name}, {HH:mm of startsAt} to {HH:mm of endsAt}"` |
| all-day, live kind | `"{title}, {kind.name}, all day"` |
| timed, removed | `"{title}, {HH:mm} to {HH:mm}, kind removed"` |
| all-day, removed | `"{title}, all day, kind removed"` |

A removed kind's **name segment is dropped**, not replaced: the row's name is
stale, and AC-4 says the name ends ", kind removed" (PO decision 3). "HH:mm"
is 24-hour local time, zero-padded (`date-fns` `format(d, "HH:mm")`).

Markup: one `<button type="button" aria-label={chipName(...)} className=…>`
carrying `data-allday="true"|"false"` and `data-neutral="true"` when removed.
Inside, all `aria-hidden="true"`: a `<span class="initial">` with
`kind.initial` (`"?"` when removed), then for a timed event a `<span
class="dot" style={{ background: colour }}>` and the text `"{HH:mm} {title}"`;
for an all-day event just the title. `colour` is `kind.colorDark` when
`useColorScheme()` is `"dark"`, else `kind.colorLight`; for the all-day
variant the button's own inline style is `background: colour; color:
chipText(colour).text` (`domain/colour`). The timed variant sets **no**
inline background on the button (the dot is the colour carrier,
`components.md`). A removed kind sets no inline colour at all: the stylesheet
rule with prelude exactly `.chip[data-neutral="true"]` gives `background:
var(--color-chip-neutral)`, `color: var(--color-chip-text-light)` (light
theme; the dark block swaps to `--color-chip-text-dark`, `kinds-palette.md`)
and a 1px dashed border in `currentColor`; AC-4's "uses `--color-chip-neutral`"
is asserted on the attribute plus that rule's body, parsed from
`EventChip.module.css` with `src/test/css.ts` (jsdom computes no cascade).
Hover, focus-visible and active per `components.md`; no `title` attribute.
No `onClick` yet - opening the sheet is CAL-012.
