## Context

EPIC-05. Source: `docs/wiki/audits/epic-05-2026-10-31.md` (Decided 3;
Evidence E-DENO G13, G16, G20, and "Tests that are theatre").

`geminiResponseSchema` (`supabase/functions/capture/gemini.ts:24-56`) is what
the model is held to. Its comment calls it "the OpenAPI-subset mirror of
`geminiReplySchema` in shared/captureSchema.ts". The tests pin its top-level
keys, its six proposal keys, the confidence keys and the `missing` enum. Three
mutants of its *content* leave all 160 Deno tests green:

- **G16**: `nullable: true` deleted from `nullableString` (line 16), so title,
  startsAt, endsAt, location and kindName are all non-nullable. The model is
  then told it may not answer null for a field it did not find. That pushes it
  to invent one, which is the "never guessed silently" rule this epic exists
  for, and `geminiReplySchema` still accepts the invented strings.
- **G13**: `minimum: 0, maximum: 1` deleted from `rating` (line 17). Confidence
  out of 0..1 then fails zod, and the capture answers 502 `unreadable`.
- **G20**: `"allDay"` dropped from the proposal's `required` (line 41). A reply
  without `allDay` fails zod's `z.boolean()` and answers 502.

`gemini_test.ts:79` (`assertEquals(req.generationConfig.responseSchema,
geminiResponseSchema)`) compares the export with itself, so it pins the wiring
and not the schema.

Test-only: the shipped schema is believed right, so each assertion passes on
arrival and is earned by its mutant.

Required gate that would fail if this broke: `deno-test`.

## Acceptance criteria

- **AC-1** - Given `geminiResponseSchema`, then each of the proposal's
  `title`, `startsAt`, `endsAt`, `location` and `kindName` is a `STRING` marked
  `nullable: true`, and `allDay` is a `BOOLEAN` that is not nullable. A test
  fails under G16 (`16s#, nullable: true##` on `gemini.ts`).
- **AC-2** - Given `geminiResponseSchema`, then every confidence property is a
  `NUMBER` with `minimum` 0 and `maximum` 1. A test fails under G13
  (`17s#, minimum: 0, maximum: 1##`).
- **AC-3** - Given `geminiResponseSchema`, then the proposal's `required` lists
  exactly the six proposal fields. A test fails under G20 (`41s#"allDay",##`).
- **AC-4** - Given any key that `proposalSchema` (shared/captureSchema.ts)
  accepts as `null`, then `geminiResponseSchema` marks that key nullable, and
  given any key it does not, then the response schema does not. The check is
  derived from the zod schema, not from a second hand-written list. A test fails
  under G16, and also when `.nullable()` is removed from `location` in
  `shared/captureSchema.ts` (`25s#z.string().nullable()#z.string()#`).

## Test plan

Four new `Deno.test` blocks appended to
`supabase/functions/capture/gemini_test.ts` under a `CAL-051` banner, at unit
level (the schema is a plain exported object; nothing cheaper or more direct
exists). No existing case edited; `:79`'s self-comparison stays. All oracles
mechanical, read out of the AC text; nothing calibrated, no negative-control
thresholds.

- **AC-1** - for each of `title`, `startsAt`, `endsAt`, `location`,
  `kindName`: `{type, nullable}` equals `{type: "STRING", nullable: true}`
  (exact-case `"STRING"`, as the AC writes it; the older tests compare
  lower-cased). `allDay`: `{type, nullable === true}` equals
  `{type: "BOOLEAN", nullable: false}`, so an absent or `false` `nullable`
  both pass and only `true` fails. The failure message names the field.
- **AC-2** - for each key of the test file's `FIELDS`
  (`title, startsAt, endsAt, location, kind`): `{type, minimum, maximum}`
  equals `{type: "NUMBER", minimum: 0, maximum: 1}`. Keys are iterated from
  the test's own list, so a missing confidence key fails as `type: undefined`
  (the key set itself is already pinned by the CAL-018 test).
- **AC-3** - **order-insensitive**: `[...required].sort()` equals the six
  sorted names. Sorting keeps duplicates, so a duplicated or missing entry
  still fails.
- **AC-4** - `proposalSchema` imported from `../../../shared/captureSchema.ts`
  (as `handler.ts` does). Asserts (a) the response schema's proposal key set
  equals `Object.keys(proposalSchema.shape)`, (b) a sanity guard that the null
  probe discriminates (at least one key accepts null and at least one does
  not - this is a property of the probe, not a list of keys), and (c) the map
  `key -> responseSchema.nullable === true` equals the map
  `key -> proposalSchema.shape[key].safeParse(null).success`. No hand-written
  nullable list.

Earning: each case passes on arrival; each is earned by its mutant under
`## Deferred verifications` (entries 1-4, pasted). Out of scope not pinned:
whether Gemini honours `nullable`.
