## Context

EPIC-04, from `docs/wiki/audits/epic-04-2026-11-06.md` (Decided 8;
Evidence E-STRYKER `src/events/EventSheet.tsx` and E-HAND T154b).

CAL-045's failed-sync strip is pinned on the paths its tests take. Stryker
ran 87 mutants over its lines (`EventSheet.tsx:130-157`, `:210-252`,
`:445-472`): 59 killed and 7 timed out, three of those re-run by hand and
killed. Three of the survivors are behaviour the owner would see:

- **Discard when the server copy has the cached stamp** (`:142:22`,
  `:154:63`). The sheet remounts on Discard through a key of the row's
  stamp plus a generation counter. The generation exists for the case where
  the stamp does not change ("the generation remounts OpenSheet even when
  the row's stamp is unchanged", `:131`), and that is the ordinary case: a
  refused update never changed the server row, and an optimistic write never
  touches `updatedAt`, so the server copy carries the cache row's own stamp.
  Every Discard test hands back a server copy with a different stamp
  (`THEIRS_STAMP`), so the key changes anyway. With the generation pinned to
  0 (`:142:22`) or counting down (`:154:63`; T154b: 104 of 104), the tests
  pass, and in the app the form would keep the refused values after Discard
  (reasoned from the key, not observed).
- **A replacement belongs to its request** (`:139:26`). With `replaced.for
  === request` made `true`, the server copy from one Discard is shown in
  place of the next event the owner opens. No test opens a second event
  after a Discard.
- **A second Retry** (`:240:24`). With the busy flag left set after a retry
  resolves, a Retry refused again shows its new message, and then Retry does
  nothing. The "refused again" case presses Retry once.

Test-only: the shipped sheet is believed correct, so each new assertion
passes on arrival and is earned by the mutant its criterion names.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given an event whose op failed, opened in the sheet and edited
  there, when Discard resolves with a server copy whose `updatedAt` equals
  the cached row's, then the fields show the server copy, the sheet is clean
  (Close closes at once), and Save afterwards sends only what is changed
  from the server copy. A test fails when `EventSheet.tsx:142`'s
  `replaced?.for === request` is `false`.
- **AC-2** - Given a Discard that replaced the sheet's row for one event,
  when the sheet is closed and a **different** event is opened, then the
  sheet shows that event's own fields and title. A test fails when `:139`'s
  `replaced.for === request` is `true`.
- **AC-3** - Given a Retry that the server refuses again (the strip shows
  the new message), when Retry is pressed a second time, then `retry` is
  called a second time with the same seq. A test fails when `:240`'s
  `syncBusy.current = false` sets `true`.

### Block 1 - AC-1: Discard with an unchanged stamp (3 cases)

New fixture, in the AC-1 describe:

```ts
/** The server's copy when the refused update never changed the row: MINE's own stamp. */
const THEIRS_SAME_STAMP: Event = { ...THEIRS, updatedAt: MINE.updatedAt };
```

It differs from `MINE` in `title` ("Theirs") and `location` ("Harbour Rd")
and from `THEIRS` only in the stamp. That equality is the whole point of
the block: with it, `keyOf` returns the same string before and after
Discard, and only the generation remounts the form. A case that hands back
`THEIRS` earns nothing here.

Each case starts the same way:

1. `const sync = fakeSync(); sync.discard.mockResolvedValue(THEIRS_SAME_STAMP);`
2. `openSheet(edit(MINE), { sync })`, `const el = await strip()`.
3. Edit in the sheet: `await user.type(title(), " edited")`, and
   `expect(title()).toHaveValue("Mine edited")` - the criterion's "edited
   there", and what makes the sheet dirty before Discard.
4. `await user.click(within(el).getByRole("button", { name: "Discard" }))`.
5. `await waitFor(() => expect(title()).toHaveValue("Theirs"))`.

Then:

- **Case A - the fields show the server copy.** After step 5:
  `screen.getByRole("textbox", { name: "Location" })` has value
  `"Harbour Rd"`; `sync.discard.mock.calls` is `[[7, DENTIST.id]]`;
  `screen.queryByRole("alert")` is null; `sheet()` is in the document and
  `onClose` was not called.
- **Case B - the sheet is clean.** After step 5:
  `await user.click(closeButton())`; then
  `screen.queryByRole("dialog", { name: "Discard changes?" })` is null,
  `onClose` was called once, and `screen.queryByRole("dialog")` is null.
- **Case C - Save sends only what changed from the server copy.** After
  step 5: `await user.type(title(), " 2")`, `await user.click(save())`;
  `actions.updateEvent.mock.calls` is exactly
  `[[DENTIST.id, { title: "Theirs 2" }, UPDATED_AT]]`. The third argument
  is the server copy's stamp, which here is `UPDATED_AT`; the patch has no
  `location` because the form's baseline is the server copy, not `MINE`.

Under the mutant the form is not remounted, the title stays "Mine edited",
and step 5 times out in all three. That is the right reason: the assertion
that goes red is "the fields show the server copy".

### Block 2 - AC-2: a different event after a Discard (1 case)

The file's `Host` opens one request from one `make`. This block needs a
host that can open a **second, different** event while the same
`EventSheet` stays mounted (its `replaced` state must survive the close).
Either a local component in this describe, or `Host` given an optional
second `make` - RED's choice; if `Host` changes, every existing call must
be unaffected (the second prop optional, no second button without it).
Shape:

- two `type="button"` openers, "Open" (`edit(MINE)`) and "Open other"
  (`edit(TRIP)`), each `setRequest(make(e.currentTarget))`;
- one `<EventSheet request={request} kinds={KINDS} actions={...} sync={sync}
  onClose={() => { onClose(); setRequest(null); }} />`, inside
  `<MemoryRouter>`, with `userEvent.setup()`.

Steps: `fakeSync()` as it is (its `discard` resolves `THEIRS`; the stamp
does not matter to this block). Click "Open"; `await strip()`; click its
Discard; `await waitFor(() => expect(title()).toHaveValue("Theirs"))`;
`await user.click(closeButton())`; `expect(screen.queryByRole("dialog")).toBeNull()`
(clean, so it closes at once); click "Open other".

Assertions, all on the second sheet:

- `screen.getByRole("dialog", { name: "Edit event: Trip" })` is in the
  document, and `screen.queryByRole("dialog", { name: "Edit event: Theirs" })`
  is null - the title;
- `title()` has value `"Trip"`;
- the Location textbox has value `""` (`TRIP.location` is null; the
  replaced row's is "Harbour Rd");
- `allDaySwitch()` reads on (`TRIP.allDay` is true; the replaced row's is
  false), asserted the way the file's other all-day cases assert it.

Under the mutant the second sheet is `{ ...request, event: THEIRS }`: named
"Edit event: Theirs", title "Theirs".

### Block 3 - AC-3: Retry, refused, Retry again (1 case)

`failedOp` must answer a failed op for the first two asks (on open, and
after the first retry) and then null (after the second):

```ts
const sync = fakeSync(); // 1st ask: { seq: 7, message: "invalid input" }
sync.failedOp.mockResolvedValueOnce({ seq: 7, message: "still bad" }); // 2nd
// 3rd and later: null (fakeSync's default)
```

Steps: `openSheet(edit({ ...DENTIST, sync: "failed" }), { sync })`;
`const el = await strip()`; click its Retry; then
`await waitFor(() => expect(screen.getByRole("alert").textContent).toContain("still bad"))`,
which is the criterion's "the strip shows the new message" and the point at
which the first retry has fully resolved. Then press Retry a second time,
queried afresh from the strip as it now is:
`await user.click(within(screen.getByRole("alert")).getByRole("button", { name: "Retry" }))`.

Assertions:

- `await waitFor(() => expect(sync.retry.mock.calls).toStrictEqual([[7], [7]]))`:
  called a second time, with the same seq. This is the assertion the
  mutant turns red (the list stays `[[7]]`);
- then `await waitFor(() => expect(screen.queryByRole("alert")).toBeNull())`:
  the second retry's answer (null) is shown, so the press did its work.
