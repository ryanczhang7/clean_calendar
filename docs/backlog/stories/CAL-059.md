## Context

EPIC-03 owns the event sheet (CAL-012 built it; `components.md`, "Event
sheet"; `layout.md`, "Desktop specifics"). A `fix`: the criteria reproduce the
bug, and the failing test is the permanent regression test.

**The bug.** From 1024px the sheet is a 400px panel docked right
(`src/events/EventSheet.module.css`, the `@media (min-width: 1024px)` block:
`position: sticky; top: 0; height: 100dvh`). The panel is a flex sibling of
the view inside `AppShell`'s `.main`, which sits under a sticky 56px top bar
(`--size-topbar`) and has 16px padding (`--space-4`). So at 1280×800 the panel
starts at y = 72 but keeps the full viewport height and ends at y = 872: the
footer with Save is 72px below the fold, the document scrolls 88px, and once
scrolled the sticky `top: 0` panel covers the right 400px of the top bar.

**Source of the measurement.** CAL-031's GREEN, 2026-11-04, recorded in
CAL-031 `## Notes`, "Found in GREEN, not fixed here - the docked panel is
taller than the space below the top bar" (branch
`story/CAL-031-end-to-end-smoke-flow-against-the-local`). CAL-031's own
desktop test (`e2e/layout.spec.ts`, "the bottom nav is hidden, and the sheet
docks 400px wide at the right edge while the grid shrinks (AC-4)") reads the
panel's width and right edge only, so nothing asserts the height, and CAL-031
could not fix it without a failing test (law 1). The defect predates CAL-031's
change: before PO decision 6 the panel sat at y = 366 and was no better.

**Why it depends on CAL-031.** The tests live in `e2e/layout.spec.ts`, which
exists only on CAL-031's branch, and the panel is docked as a sibling of the
view only there (`CalendarPage.module.css`, new in CAL-031). This story
starts once CAL-031 is DONE and merged.

**Gate.** Only the browser can see this: jsdom has no layout. The
`integration` gate (`pnpm exec playwright test`) is optional repo-wide, so it
is in `required_gates` above. No required gate would fail if the panel
regressed.

## Acceptance criteria

All four at a 1280×800 viewport (Playwright's `viewport`, so 800 is the
layout viewport and `100dvh` = 800px), signed in as the owner, on this month,
with the event sheet open on a seeded event the way CAL-031's `openLunch`
opens it. Each one fails while the bug exists and is a separate test.

- **AC-1** — Given the sheet is open and the document is at scroll offset 0,
  when the sheet's bounding box is read, then its bottom edge
  (`y + height`) is ≤ 800, and its top edge is ≥ 56 (below the top bar).
  *While the bug exists:* bottom edge = 872.
- **AC-2** — Given the sheet is open and nothing has been scrolled, when the
  Save button's bounding box is read, then the whole button lies inside the
  viewport: `y ≥ 0` and `y + height ≤ 800` (and `x ≥ 0`, `x + width ≤ 1280`).
  *While the bug exists:* the footer, Save included, is 72px below the fold.
- **AC-3** — Given the document's `scrollHeight` with the sheet closed, when
  the sheet is opened, then `document.documentElement.scrollHeight` is no
  greater than it was with the sheet closed: opening the sheet adds no
  vertical scroll. *While the bug exists:* the open sheet makes the document
  888px tall, 88px more than the viewport, and taller than it is closed.
  (Why relative rather than "scrollHeight ≤ clientHeight": the month grid's
  own `min-height: calc(100vh - var(--size-topbar))` plus `.main`'s padding
  can make the document scroll by a few tens of pixels with no sheet open.
  That is not this bug - see Out of scope - and an absolute assertion would
  fail for a reason this story does not touch. RED measures the closed
  baseline and records it in the handoff.)
- **AC-4** — Given the sheet is open, when the window is scrolled as far down
  as the document allows (`window.scrollTo(0, document.documentElement.scrollHeight)`)
  and the sheet's and the top bar's bounding boxes are read, then the two
  boxes do not intersect: the sheet's top edge is ≥ the top bar's bottom edge
  (56), the top bar is still visible at `y = 0`, and the top bar's Account
  button (`getByRole("button", { name: "Account" })`, at the right end of the
  bar, inside the 400px the panel covers today) is the element at its own
  centre point (`document.elementFromPoint`, or Playwright's actionability on
  a click that opens the Account menu). *While the bug exists:* after the
  88px scroll the panel spans y = 0..800 and covers the top bar's right
  400px, Account included.

*Oracle partition* (story-authoring, "Brief RED by oracle"): AC-1, AC-2 and
AC-4's numbers are **settled** - 56 (`--size-topbar`), 16 (`--space-4`), 400
(`components.md`), 1280×800 (CAL-031's `DESKTOP`) - read them out, do not
calibrate. AC-3 is **mechanical**: two reads of `scrollHeight`, compared.
Nothing here is oracle-free.

**Accessible markup the tests select by** (all existing; GREEN changes none
of it):

- the sheet: `page.getByRole("dialog", { name: "Edit event: Lunch" })` - the
  `div[role="dialog"][data-sheet]` with `className={styles.sheet}` in
  `src/events/EventSheet.tsx`. Its bounding box is the panel's.
- Save: `sheet.getByRole("button", { name: "Save" })` - the `type="submit"`
  button inside `<footer className={styles.footer}>`.
- the top bar: `<header className={styles.topbar}>` in `src/app/AppShell.tsx`
  (line 120) - a top-level `<header>`, so `page.getByRole("banner")`; RED
  confirms the landmark resolves and falls back to `page.locator("header")`
  if it does not, saying which in the handoff. It is `position: sticky;
  top: 0; height: 56px; z-index: var(--z-topbar)`
  (`src/app/AppShell.module.css`, `.topbar`). Its right end holds the
  Account menu button (`aria-label="Account"`, `AppShell.tsx` line 59),
  which is what AC-4 clicks.

**The numbers and what they mean** (`src/styles/tokens.css`):

- `--size-topbar: 56px`: the top bar's height; it is sticky at `top: 0`, so
  at every scroll offset the band y = 0..56 belongs to it.
- `--space-4: 16px`: `.main`'s padding on every side at ≥600px (the
  bottom-nav allowance is removed there). So the panel's row starts at
  y = 56 + 16 = 72 at scroll 0, and the document is 16px taller than the row.
- `100dvh` = 800 at this viewport. The panel's height today is 800; the
  space below the top bar at scroll 0 is 800 - 72 = 728.
- What the fix must achieve, stated as geometry rather than CSS: at scroll
  offset 0 the panel's box lies within y = 72..800; at every scroll offset it
  lies within y = 56..800. One shape that does both is
  `top: var(--size-topbar)` with
  `height: calc(100dvh - var(--size-topbar) - var(--space-4))` (= 728), so
  the panel sticks *under* the top bar rather than under the viewport edge
  and never grows past the fold. GREEN may choose another shape (e.g. the
  panel escaping `.main`'s top padding the way `CalendarPage.module.css`
  already escapes its right padding) as long as the four criteria hold and
  the panel stays docked, 400px wide and flush right (CAL-031 AC-4's test,
  which must stay green). The `.body` region already scrolls internally
  (`overflow-y: auto`), so a shorter panel loses nothing: the form scrolls
  inside, the footer stays pinned.
- `--z-topbar: 20` and the sheet's `z-index: 20` are equal; the sheet comes
  later in the DOM, so wherever they overlap the sheet wins. The fix is to
  remove the overlap, not to reorder z-indices (a panel *under* the top bar
  would still steal the top bar's 400px of clicks).

**Baseline measurements** this story may read out (CAL-031 GREEN, 2026-11-04,
Chromium under Playwright, 1280×800): panel box with the sheet open
`y = 72, height = 800`, bottom edge 872; document scroll 88px with the sheet
open. Derived from the CSS, not measured: the document with the sheet
*closed* is roughly 832px tall (56 + 16 + the month grid's 744px min-height +
16) - RED measures the real value for AC-3's baseline and records it.

**What the tests do not constrain:** the panel's width and right edge
(CAL-031's test keeps those), the sheet below 1024px, how the panel's height
is expressed in CSS, whether the panel's own border/shadow changes.

**Test-only dependencies:** none new. `@playwright/test` and `date-fns` are
already dev dependencies; the fixtures exist on CAL-031's branch.

**No export changes.** This story changes CSS only; no signature moves, no

**Running the tests.** The `integration` gate needs the local stack CAL-031

## Design notes

Not needed beyond `components.md`, "Event sheet", and `layout.md`, "Desktop
specifics", which already fix the panel at 400px docked right, pushing the
grid. The only decision here is that the panel occupies the space *under*
the top bar rather than the whole viewport, which both documents already
assume ("the grid fills the viewport under the top bar").
