## Context

EPIC-01. The data model in `docs/wiki/architecture.md` ("Data model"), created
in one migration because every table shares one predicate: a row is visible
and writable only when `auth.jwt() ->> 'email'` equals
`app_config.owner_email`. This is the real enforcement of the brief's "one
allowed account" (§6); CAL-003 is only its user experience. Every later story
that persists anything writes into a table created here, so all seven tables
land now: `app_config`, `kinds`, `events`, `event_overrides`, `reminders`,
`push_subscriptions`, `capture_jobs`.

Required gate that would fail if this broke: `db` (Vitest project `db`,
`*.db.test.ts`, against `supabase start`). It is optional repo-wide, so it is
in `required_gates`. This story is the first to require it and therefore
probes it (see CAL-001's deferred verification).

## Acceptance criteria

- **AC-1** - Given `supabase db reset`, when the schema is inspected, then the
  seven tables exist with the columns `architecture.md` lists, each with `id`,
  `created_at` and `updated_at`; `kinds` has a unique index on `lower(name)`
  for rows where `deleted_at is null`; `reminders` is unique on
  `(event_id, occurrence_date)` with nulls not distinct; `push_subscriptions`
  is unique on `endpoint`.
- **AC-2** - Given a JWT whose e-mail is the owner's, when it selects, inserts,
  updates and soft-deletes a row in each client table (`kinds`, `events`,
  `event_overrides`, `reminders`, `push_subscriptions`, `capture_jobs`), then
  every operation succeeds.
- **AC-3** - Given a JWT for any other e-mail, when it does the same, then
  every select returns zero rows, every insert is refused, and every update
  and delete affects zero rows - for every one of the six tables, checked
  table by table so that a missing policy names its table.
  *Control:* the same test run against a table with RLS disabled must fail on
  that table.
- **AC-4** - Given no JWT (anon key only), when it selects from every table,
  then it reads zero rows.
- **AC-5** - Given the owner's JWT, when it tries to insert, update or delete
  `app_config`, then it is refused; the service role can.
- **AC-6** - Given a row, when it is updated, then `updated_at` is strictly
  greater than before (trigger-maintained), whatever value the client sent.
- **AC-7** - `src/data/database.types.ts` is generated from this schema by
  `supabase gen types typescript --local` and `tsc --noEmit` passes with it.

### Migration (`supabase/migrations/0001_core_schema.sql`)

One file, idempotent only in the sense `supabase db reset` gives it (a
fresh database). Order: extensions → helper function → tables → indexes →
triggers → RLS.

- `create extension if not exists pgcrypto;` (for `gen_random_uuid()`; a
  no-op on Supabase, stated anyway).
- **The predicate.** `create function public.is_owner() returns boolean
  language sql stable security definer set search_path = public as $$
  select coalesce(auth.jwt() ->> 'email', '') <> '' and
  lower(trim(auth.jwt() ->> 'email')) = lower(trim((select owner_email from
  public.app_config limit 1))) $$;` — `security definer` so the policy can
  read `app_config` whatever the caller's grants; `lower(trim())` on both
  sides so the rule is the same as CAL-003's `isOwnerEmail`; an empty or
  missing claim is never the owner. `revoke execute on function
  public.is_owner() from public, anon; grant execute … to authenticated,
  service_role;`.
- **Common columns on every table:** `id uuid primary key default
  gen_random_uuid()`, `created_at timestamptz not null default now()`,
  `updated_at timestamptz not null default now()`.
- **Tables** (`architecture.md`, Data model), `public` schema:
  | table | columns beyond the common three |
  |---|---|
  | `app_config` | `owner_email text not null` — plus `constraint app_config_single_row check (singleton)` where `singleton boolean not null default true unique` keeps it to one row |
  | `kinds` | `name text not null check (length(trim(name)) between 1 and 32)`, `color_light text not null check (color_light ~ '^#[0-9a-fA-F]{6}$')`, `color_dark text not null` (same check), `sort_order int not null default 0`, `is_default boolean not null default false`, `deleted_at timestamptz` |
  | `events` | `title text not null check (length(title) between 1 and 120)`, `kind_id uuid not null references public.kinds(id) on delete restrict`, `starts_at timestamptz not null`, `ends_at timestamptz not null check (ends_at > starts_at)`, `all_day boolean not null default false`, `location text`, `notes text`, `recurrence jsonb`, `origin text not null default 'manual' check (origin in ('manual','capture'))`, `capture_job_id uuid references public.capture_jobs(id) on delete set null`, `deleted_at timestamptz` |
  | `event_overrides` | `event_id uuid not null references public.events(id) on delete cascade`, `occurrence_date date not null`, `cancelled boolean not null default false`, nullable copies: `title text`, `kind_id uuid references public.kinds(id)`, `starts_at timestamptz`, `ends_at timestamptz`, `all_day boolean`, `location text`, `notes text` |
  | `reminders` | `event_id uuid not null references public.events(id) on delete cascade`, `minutes_before int not null`, `sent_at timestamptz`, `occurrence_date date` |
  | `push_subscriptions` | `endpoint text not null`, `p256dh text not null`, `auth text not null`, `user_agent text`, `last_seen_at timestamptz not null default now()` |
  | `capture_jobs` | `input_kind text not null check (input_kind in ('text','image'))`, `input_hash text not null`, `model text not null`, `proposal jsonb`, `confidence jsonb`, `status text not null default 'proposed' check (status in ('proposed','confirmed','discarded'))`, `error text`, `latency_ms int` |
  `capture_jobs` is created **before** `events` (the FK points at it).
- **Indexes / uniqueness (AC-1):** `create unique index kinds_live_name_key
  on public.kinds (lower(name)) where deleted_at is null;` ·
  `alter table public.reminders add constraint reminders_event_occurrence_key
  unique nulls not distinct (event_id, occurrence_date);` (Postgres 15+;
  the local stack is 17) · `alter table public.push_subscriptions add
  constraint push_subscriptions_endpoint_key unique (endpoint);` ·
  `event_overrides` unique `(event_id, occurrence_date)` · `events` index
  on `(starts_at)` and on `(kind_id)`.
- **`updated_at` (AC-6):** `create function public.set_updated_at() returns
  trigger language plpgsql as $$ begin new.updated_at :=
  greatest(clock_timestamp(), old.updated_at + interval '1 microsecond');
  return new; end $$;` with a `before update` trigger on all seven tables.
  "Strictly greater, whatever the client sent" means: the trigger
  overwrites `new.updated_at` unconditionally, and the `greatest` guards a
  clock that did not advance within the microsecond.
- **RLS:** `alter table … enable row level security` on all seven; `force
  row level security` is **not** set (the owner `postgres` role used by
  migrations must bypass). For each of the six client tables, four
  policies named `<table>_select_owner`, `<table>_insert_owner`,
  `<table>_update_owner`, `<table>_delete_owner`: `for select to
  authenticated using (public.is_owner())`, `for insert to authenticated
  with check (public.is_owner())`, `for update to authenticated using
  (public.is_owner()) with check (public.is_owner())`, `for delete to
  authenticated using (public.is_owner())`. `app_config` gets **only**
  `app_config_select_owner` — no insert/update/delete policy, so AC-5's
  refusals come from RLS itself; the service role bypasses RLS.
  `anon` gets no policy anywhere (AC-4).
- **Grants:** Supabase's default privileges already grant the three roles on
  new `public` tables; the migration states `grant select, insert, update,
  delete on all tables in schema public to authenticated; grant select on
  all tables in schema public to anon;` explicitly so the file is the whole
  truth (RLS, not grants, is what refuses).

### Tests

- `schema.db.test.ts` (AC-1, AC-6, AC-7 partly) via `sql`:
  `information_schema.columns` per table equals the pinned column sets
  (names and `is_nullable`); `pg_indexes` / `pg_constraint` carry the four
  uniqueness rules above (the partial index's `indexdef` contains `WHERE
  (deleted_at IS NULL)`; the reminders constraint's definition contains
  `NULLS NOT DISTINCT`); `pg_trigger` shows `set_updated_at` on all seven;
  `relrowsecurity` is true on all seven; AC-6: insert a kind through the
  service client, `update … set updated_at = '2000-01-01'`, re-read:
  `updated_at` > the original value.
- `rls.db.test.ts` (AC-2 … AC-5) via supabase-js, **one `describe` per
  table** so a failure names its table: owner CRUD succeeds (AC-2 —
  "soft-delete" = `update set deleted_at = now()` on `kinds`/`events`,
  `delete` on the other four, since only those two carry `deleted_at`);
  other e-mail: select → `[]`, insert → error (`42501` / RLS message),
  update and delete → zero rows (check with `.select()` returning `[]`),
  for `OTHER_EMAIL` **and** the lookalike; anon: select → `[]` on all
  seven (AC-4); owner on `app_config`: insert/update/delete → refused,
  select → the one row; service client: update succeeds (AC-5).
- **Rows that need parents** (`events` needs a kind; `event_overrides` and
  `reminders` need an event): the suite creates them through the
  **service** client in `beforeEach`, so the per-table assertion isolates
  the table under test.
