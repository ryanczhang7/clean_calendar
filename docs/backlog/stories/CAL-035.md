## Context

EPIC-01, from `docs/wiki/audits/epic-01-2026-10-15.md` (Decided 3; Evidence
E-TS-rows). Stryker 10 over `src/data/rows.ts`, against both the narrowed
command and the whole unit suite (220 tests), left 15 gap survivors in two
groups:

- **Patch mappers.** In `fromEventPatch` (`rows.ts:220–233`), the column
  keys for `kindId`, `endsAt`, `allDay`, `location`, `notes` and `origin`.
  In `fromEventOverridePatch` (`rows.ts:279–294`), the keys for `eventId`,
  `occurrenceDate`, `title`, `endsAt`, `allDay`, `location` and `notes`.
  Any of these can be renamed and nothing fails. Measured by hand: writing
  an `endsAt` patch to `starts_at` passes 220/220. In production, editing
  an event's end time would silently move its start. CAL-005's test plan
  says "patch mappers (… every field mapped)". That holds for
  `fromKindPatch` only, whose field-by-field test killed every key mutant.
- **Recurrence.** `toRecurrence` (`rows.ts:121`) accepts `daily`, `weekly`
  and `yearly`, but every fixture uses `weekly`. Making it reject `daily`
  survives, so a daily repeating event would map to `recurrence: null` and
  stop repeating.

Test-only: the shipped mappers are believed correct, so each new assertion
passes on arrival and is earned by its mutant.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** — Given an `EventPatch` naming every field with a distinct value,
  when `fromEventPatch` maps it, then the body is exactly the snake_case row
  fragment, each value under its own column (`toStrictEqual`). A test fails
  when any one of the ten column keys is renamed or swapped with another
  (audit: `rows.ts:223`, `:225`–`:228`, `:230`, and the hand-run `ends_at`
  → `starts_at`).
- **AC-2** — Given an `EventOverridePatch` naming every field with a
  distinct value, when `fromEventOverridePatch` maps it, then the body is
  exactly the snake_case fragment. A test fails when any one of the ten
  keys is renamed or swapped (audit: `rows.ts:283`, `:284`, `:286`,
  `:289`–`:292`).
- **AC-3** — Given an `events` row whose `recurrence` is
  `{freq: "daily", until: null, tz: "Europe/London"}`, and one with
  `freq: "yearly"`, when `toEvent` maps them, then `recurrence` is kept
  exactly, and `fromEvent(toEvent(row))` is the identity. A test fails when
  `toRecurrence` stops accepting `daily` (audit: `rows.ts:121:7` → `true`
  and `:121:16` `"daily"` → `""`).

## Contract

**Writes:** `src/data/rows.test.ts`

- Mirror the existing "every kinds patch field maps to its snake_case
  column" test. Use values that cannot be confused with one another: two
  different `Date`s for `startsAt` and `endsAt`, two different strings for
  `location` and `notes`, and so on. A swap between two fields is the
  realistic defect, and equal values would hide it.
- `fromEventPatch` writes `Date`s as `toISOString()` (`….000Z`). The
  existing test already pins that for `startsAt`.
- Earning, per rules.md: one `scripts/mutate.sh` run per AC against
  `src/data/rows.test.ts` alone, pasted into `## Handoff`. Suggested: AC-1
  `225s/"ends_at"/"starts_at"/`; AC-2 `291s/"location"/"notes"/`; AC-3
  `121s/freq !== "daily"/true/` (Stryker's mutant: `daily` then maps
  to `null`).
