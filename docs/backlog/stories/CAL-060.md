## Context

Epic: `docs/backlog/epics/EPIC-01.md` (the repository runs, builds and signs
in). Constraints: `docs/wiki/stack.md`, "Quality tooling and the gates", and
`.claude/harness/project.conf`.

`biome.json` lists `"!supabase"` in `files.includes` (written by CAL-001,
de6108f, to keep Biome off the Deno functions), and `tsconfig.json`'s
`include` is `src`, `shared`, `e2e` and the three `*.config.ts`. So the
`format`, `lint` and `typecheck` gates read nothing under `supabase/tests/`:
not the four `*.db.test.ts` suites and not `helpers.ts` (which `tsc` reaches
today only because `e2e/fixtures/session.ts` imports it). Measured on
519a243 (main): `pnpm exec biome format supabase/tests` prints "These paths
were provided but ignored", and `tsc --listFilesOnly -p tsconfig.json` lists
one file under `supabase/tests/` (`helpers.ts`, via the e2e import) out of
five. CAL-034's Test Developer found the gap while writing
`supabase/tests/constraints.db.test.ts` and had to format, lint and typecheck
it by hand. A test file nobody lints is a test file whose `var`, unused
import or mis-typed assertion is reviewed by eyes alone.

This story brings `supabase/tests/**` under all three gates and leaves
`supabase/functions/**` (Deno, covered by `deno-check` and `deno-test`)
exactly where it is.

**Required gate that would fail if this story's artifact broke:** `lint` and
`typecheck` are required and are the artifact. `format` is `optional` in
`project.conf`, and AC-1 can only be verified by it, so `required_gates:
[format]` above makes it binding for this story.

**Shape: a `chore` under SCAFFOLD, not RED -> GREEN.** The "test" of this story
is a gate probe: a deliberately broken file under `supabase/tests/` that each
gate must now refuse and today ignores. Those probes classify as `test`
(`paths.conf`, `**/__probe_*.*`), are transient (written, run against, deleted)
and must be run *after* the config change, in the same phase as it. RED can
write them but cannot change the config; GREEN and GATES can change the config
but cannot write or delete a test path. SCAFFOLD is the one phase that can do
both, and `rules.md`'s chore exception exists for exactly this: configuration,
the probe that proves it, and one test-file reformat that depends on each
other. The price is `## Scaffold inventory` and `## Gate probes`, both filled
below. Phase path: PLANNED -> SCAFFOLD -> GATES -> REVIEW -> DONE.

### Block 1 — `biome.json`

In `files.includes`, replace `"!supabase"` with two entries:
`"supabase/tests/**"` and `"!supabase/functions"`. Positive globs are a
whitelist, so `supabase/migrations/*.sql`, `supabase/config.toml` and
`supabase/seed.sql` are not read either way; the explicit
`"!supabase/functions"` is there so a later widening of the positive globs
cannot pull Deno code in silently (AC-4 pins it). Biome 2.2+ spells a directory
exclusion `!dir`, not `!dir/**` (stack.md). `biome.json` is itself in Biome's
includes, so the edit stays formatted.

**Baseline, measured on 519a243 by running the tools, not by reading config:**
`biome lint --error-on-warnings .` -> `Checked 233 files`, exit 0, "Found 4

### Block 2 — `tsconfig.json`

Add `"supabase/tests"` to `include`. **Decision: widen the root project rather
than add a second one.** Reason: `tsc` with the root project's exact
`compilerOptions` (`strict`, `noUncheckedIndexedAccess`, `isolatedModules`,

already resolvable from the root project. The `typecheck` gate command
(`tsc --noEmit -p tsconfig.json && tsc --noEmit -p tsconfig.sw.json`) picks
the change up with no `project.conf` edit, where a `tsconfig.db.json` would
need a third `-p` and a new `config` path for no isolation anyone asked for.
`helpers.ts` is already in the program via `e2e/fixtures/session.ts`, so the
widening adds the four `*.db.test.ts` files.
