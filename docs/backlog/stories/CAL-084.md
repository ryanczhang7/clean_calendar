## Context

EPIC-06. Source: `docs/wiki/audits/EPIC-06-2026-11-23.md` (Decided 3,
Evidence E-STRYKER-3 `page` and E-RECHECK-3 R9). It is the item CAL-082's
diff review round 1 left for `/audit-mutations` as a Nice to have ("AC-3
checks only the date half of the `:345` lookup"; CAL-082 `## Notes`).

When the owner moves one occurrence of a repeating event and answers "This
event only", `confirmScope` in `src/calendar/CalendarPage.tsx` looks up the
prior override of that occurrence for the Undo (PO decision 5 of CAL-025:
the Undo writes the prior override's times back, null where it had none):

    stores.overrides.getSnapshot().overrides.find(
      (o) => o.eventId === event.id && o.occurrenceDate === date,
    );

The mutant that drops the series half, `(o) => o.occurrenceDate === date`,
survives the whole unit project (95 files, 3415 tests, at `34aa1f4`).
CAL-082 AC-3 holds one override, Spin's own on 11 November, so it tells
"this date" from "any date" but not "this series" from "any series". Under
the mutant, the Undo of a "This event only" move on a day where **another**
repeating event has an override writes that other event's override times
into this occurrence, so the Undo moves it to the wrong time instead of
back. No error is shown, and the second Undo is gone with the toast.

Test-only. The shipped page is believed correct, so each case passes on
arrival and is earned by the mutant (Deferred verifications DV-1). Required
gate that would fail: `unit` (and `coverage`); both cover `src/**`.

## Acceptance criteria

- **AC-1** - Given the weekly Spin series (from 4 November, 10:00-11:00) and
  a second repeating series in the events store, and the overrides store
  holding exactly one override, which belongs to the **second** series, is
  dated `2026-11-18` and sets 12:00-13:00, when the owner moves the
  18 November Spin occurrence to 14:00, confirms "This event only" and
  presses Undo, then `setOverride` is called twice, and the second call is
  `(spin.id, "2026-11-18", { startsAt: null, endsAt: null })`. A test fails
  under `345s/o.eventId === event.id \&\& //` on
  `src/calendar/CalendarPage.tsx`, showing `{ startsAt: <18 Nov 12:00>,
  endsAt: <18 Nov 13:00> }` in the second call.
- **AC-2** - Given the same two series, and the overrides store holding two
  overrides dated `2026-11-18`, the second series' (12:00-13:00) **first**
  in the store's array and Spin's own (16:00-17:00) second, when the owner
  moves the 18 November Spin occurrence to 14:00, confirms "This event only"
  and presses Undo, then the second `setOverride` call is
  `(spin.id, "2026-11-18", { startsAt: <18 Nov 16:00>, endsAt: <18 Nov 17:00> })`.
  The same mutant fails it, showing 12:00-13:00.
