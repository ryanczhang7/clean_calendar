## Context

EPIC-06, brief §4.5: "edit one occurrence or the series". `architecture.md`,
"Overrides": editing one occurrence writes an `event_overrides` row keyed by
the occurrence's original date; deleting one writes `cancelled = true`;
editing the series edits the `events` row and overrides still win where they
exist. The edit-scope dialog asks which (`components.md`, "Edit-scope
dialog"; copy `voice.md`, "Dialogs"). Override writes go through the outbox
(CAL-015) like every other write.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given an occurrence of a series, when an edit is saved, a move is
  dropped, or Delete is pressed, then an `alertdialog` "Change which events?"
  (or "Delete which events?") offers "This event only" (selected, focused)
  and "All events in the series" with Cancel and Save (or Delete); for a
  non-recurring event no dialog appears.
- **AC-2** - Given "This event only" on an edit, when it is confirmed, then one
  override is written for that occurrence's original date holding only the
  changed fields; the other occurrences are unchanged and the edited one shows
  the new values.
- **AC-3** - Given "This event only" on a delete, when it is confirmed, then an
  override with `cancelled = true` is written, that occurrence disappears, and
  "Deleted {title}" with Undo is shown; Undo removes the cancellation.
- **AC-4** - Given "All events in the series" on an edit, when it is confirmed,
  then the series row is updated, every occurrence without an override shows
  the change, and overridden fields of overridden occurrences keep their
  override values.
- **AC-5** - Given "All events in the series" on a delete, when it is confirmed,
  then the series is soft-deleted, every occurrence disappears, and "Deleted
  {title} and all its occurrences" with Undo is shown.
- **AC-6** - Given "All events in the series" on a move by N days, when it is
  confirmed, then the series start moves by N days, the helper "Moving the
  whole series moves every occurrence by the same amount." was shown, and the
  dialog's Escape cancels without writing.

An **occurrence** throughout is an `Event` with `occurrenceDate` set
(CAL-024 Block 3): its `id` is the series id, its `startsAt`/`endsAt`/
`title`/`kindId`/`allDay`/`location`/`notes` are the occurrence's after
overrides, its `recurrence` and stamps are the series'. The **series row** is
the stored `Event` with that id (no `occurrenceDate`). Both the sheet and the
page already receive the occurrence `Event`; what they lack is the series
row, which Block 6 supplies.

**Block 2 - the edit-scope dialog (`src/events/EditScopeDialog.tsx`).**

```ts
export type EditScope = "occurrence" | "series";
export function EditScopeDialog(props: {
  open: boolean;                 // false → renders nothing
  kind: "change" | "delete";     // the title and the confirm button
  /** The write moves startsAt/endsAt: shows the helper under the second option. */
  moving?: boolean;
  onCancel: () => void;          // Cancel, and Escape
  onConfirm: (scope: EditScope) => void;
}): JSX.Element | null;
```

- Rendered through `Dialog` with `role="alertdialog"`; title "Change which
  events?" for `kind: "change"`, "Delete which events?" for `"delete"`
  (`voice.md`, Dialogs). Accessible name of the dialog = the title.
- Body: two radios sharing one `name`, in this order: `<input type="radio"
  value="occurrence">` labelled "This event only", checked on every open;
  `<input type="radio" value="series">` labelled "All events in the series".
  Each radio's accessible name is its label text exactly. When `moving` is
  true a `<p>` "Moving the whole series moves every occurrence by the same
  amount." follows the second radio's label and is the second radio's
  `aria-describedby`; when false it is not in the DOM.
- Actions, in order: a Cancel button, then the confirm button labelled
  "Save" (`kind: "change"`) or "Delete" (`kind: "delete"`, with
  `data-variant="danger"`). Confirm calls `onConfirm(<checked value>)` once
  and nothing else; Cancel and Escape call `onCancel` and nothing else.
- Focus on open is on "This event only" (Dialog's first-non-danger rule: the
  first radio is the first focusable). The selection is local state reset on
  every open.

**Block 3 - the chip (`src/calendar/EventChip.tsx`).** The CAL-024 Block 11

**Block 4 - the sheet (`src/events/EventSheet.tsx`).**

- Submit, edit mode, `request.event.occurrenceDate !== undefined`, patch
  non-empty: nothing is written; `<EditScopeDialog kind="change"
  moving={"startsAt" in patch || "endsAt" in patch}>` opens as a sibling of
  the sheet (as the Discard dialog does). Exception (PO decision 4): a patch
  whose **only** key is `recurrence` is a series edit with no dialog:

- Confirm `"occurrence"`: `overrides.setOverride(event.id,
  event.occurrenceDate, overrideFieldsOf(patch))`, where `overrideFieldsOf`
  is the patch without `recurrence` (the other seven keys verbatim). If the
  patch also carried `recurrence`, `actions.updateEvent(event.id,

- Confirm `"series"`: `actions.updateEvent(event.id, seriesPatchOf(series,
  event, patch), series.updatedAt)`: every key of the patch verbatim except
  `startsAt`/`endsAt`, which are replaced by `seriesSpan(series, event,
  {startsAt: patch.startsAt ?? event.startsAt, endsAt: patch.endsAt ??
  event.endsAt})` (Block 5) - only the keys the patch gave are set.
- After either confirm: a result that is not `ok` shows `SAVE_FAILED` as
  today and the dialog closes; `ok` stores the last kind and calls `onClose`.
  Cancel/Escape on the dialog returns to the sheet with the value intact and
  nothing written. A non-occurrence edit and every create are unchanged: no
  dialog (AC-1).

**Block 5 - the pure helpers (`src/domain/moveEvent.ts`).**

  // startsAt: series.startsAt + (next.startsAt - shown.startsAt)
  // endsAt:   series.endsAt   + (next.endsAt   - shown.endsAt)

  // `Deleted ${title} and all its occurrences`  (voice.md, Toasts)

Semantics behind the number: moving the 18 November occurrence of a weekly
series that starts 4 November forward by 2 days gives a series start of
6 November (AC-6); the occurrence's own absolute dates never become the
series' dates.

**Block 6 - the page (`src/calendar/CalendarPage.tsx`).**

- `CalendarPage` props gain `overrideActions?: OverrideActions` (default the

- A drop, a chip command or the sheet's Delete on an occurrence opens the
  dialog instead of writing: `kind: "change", moving: true` for a move,
  `kind: "delete"` for a delete. `sameSpan` still short-circuits a no-op move

  - move, `"occurrence"`: `setOverride(id, date, { startsAt, endsAt })`;

- **PO decision 4 - a repeat-rule change is always a series change.** An
  override cannot carry `recurrence`. A sheet patch whose only key is
  `recurrence` updates the series with no dialog; a mixed patch shows the
  dialog, and "This event only" puts the other fields in the override and
  `recurrence` on the series. The alternative, silently dropping the repeat
  change, loses an edit the user made.
- **PO decision 5 - Undo of a "This event only" move writes the prior
  override values back** (`null` for a field the override did not have),
  through `setOverride`. A cleared override row stays, since hard-deleting
  one is out of scope (CAL-056); the expander treats all-null fields as no
  override.
- **PO decision 6 - "All events" with a time change moves the series by the
  same delta** as the occurrence moved (`seriesSpan`, Block 5), never to the
  occurrence's absolute dates; the other fields apply verbatim. The series
  row comes from the events snapshot (Block 6).
