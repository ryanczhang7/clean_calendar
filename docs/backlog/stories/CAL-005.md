## Context

EPIC-01. `architecture.md` puts one typed repository per table in `src/data/`,
the only code that calls supabase-js for data, and only `src/sync/` calls it.
This story builds the three the calendar needs first - `kinds`, `events`,
`eventOverrides` - with the two properties sync depends on later: an update
is conditional on the `updated_at` the client last saw (the conflict rule in
`architecture.md`, "Where state lives"), and a delete is always a soft delete.
The remaining repositories (`reminders`, `pushSubscriptions`, `captureJobs`)
are written by the stories that first need them.

Required gate that would fail if this broke: `unit` (MSW intercepts the
PostgREST HTTP calls; nothing here needs a database).

## Acceptance criteria

- **AC-1** - Given PostgREST rows in snake_case, when a repository returns
  them, then they are camelCase domain objects (`startsAt`, `kindId`,
  `allDay`, `deletedAt`…) with timestamps as `Date`, and writing maps them
  back exactly; a round trip of every column of each table is the identity.
- **AC-2** - Given `kinds.listLive()`, when called, then it requests only rows
  with `deleted_at is null` ordered by `sort_order` ascending.
- **AC-3** - Given `events.listSince(t)` (and the same on `kinds` and
  `eventOverrides`), when called, then it requests rows with `updated_at > t`
  **including** soft-deleted rows, so a deletion on another device can be
  applied.
- **AC-4** - Given `update(id, patch, expectedUpdatedAt)` on any of the three,
  when the server matches one row, then it returns `{status: 'ok', row}`; when
  it matches zero rows (the request filters on both `id` and `updated_at`),
  then it returns `{status: 'conflict'}` and does not throw.
- **AC-5** - Given `remove(id, expectedUpdatedAt)`, when called, then it issues
  a PATCH setting `deleted_at` - never an HTTP DELETE - with the same
  conflict semantics as AC-4.
- **AC-6** - Given a 4xx response, when any call is made, then it returns
  `{status: 'error', code, message}`; given a network failure, it returns
  `{status: 'offline'}`. Neither throws.
