## Context

EPIC-05. Source: `docs/wiki/audits/epic-05-2026-10-31.md` (Decided 1;
Evidence E-STRYKER `src/capture/ConfirmPage.tsx`, E-RECHECK R1 to R5 and R15).

`ConfirmPage.tsx` (CAL-020 Block 4, CAL-021 PO decision 3) is the screen
where every capture becomes an event. Stryker left 55 of its 288 mutants alive
against `ConfirmPage.test.tsx`. The 19 gaps below also survive the **whole**
unit project (2,386 tests):

- `withEnd` (`:107-119`), which fills an empty end at Save:
  - `:109` → `true`: every **all-day** end date is replaced by the start date,
    so a 12-14 Oct proposal is saved as 12 Oct (R1);
  - `:112`, `||` → `&&` or either half → `false`: a **partly filled** timed
    end (date without time, or time without date) is overwritten with
    start + 1 h, when the PO decision leaves it to `validate` (R5).
- `submit`:
  - `:271`, `event.preventDefault()` deleted. In a real browser the Save
    button then submits the form natively and reloads the page (R2);
  - `:297` `end()` deleted, or `end` emptied (`:255-257`): after a failed
    `createEvent`, Save stays `aria-disabled`, so the owner cannot retry (R3);
  - `:214` `useState(false)` → `true`, `:277` `setFailed(false)` → `true`: the
    "couldn't save" alert shows when nothing has failed (R4).
- Smaller:
  - `:66`, `<` → `<=` or `true`: a proposal with no start opened exactly on the
    hour starts an hour late (R15);
  - `:260-262`, `:279`: after a submit refused for the end, focus does not go
    to End date;
  - `:200`: `aria-controls` of "Show what was captured" names no element;
  - `:324`: the `<h1>` enters the tab order.

Test-only: the shipped page is believed correct, so each new assertion is
expected to pass on arrival and is earned by its audit mutant
(`scripts/mutate.sh`, expressions below). If one fails on arrival, the page is
wrong: stop and put it to the PO, which makes this a fix to source.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given an all-day proposal from 12 Nov to 14 Nov, with every field
  found, when the owner presses Save event, then `createEvent` receives an
  all-day event whose end covers 14 Nov (the same end that a 12-14 Nov all-day
  event saved from the event sheet receives). A test fails under
  `109s#value.endDate === ""#true#`.
- **AC-2** - Given a timed proposal whose end date is filled and whose end time
  the owner has cleared (and, as a separate case, whose end time is filled and
  end date cleared), when the owner presses Save event, then the end is not
  replaced by start + 1 h: `createEvent` is not called and the form shows the
  end error, as `validate` decides. A test fails under `112s#||#\&\&#`, and a
  test fails under each of `value.endDate !== ""` → `false` and
  `value.endTime !== ""` → `false`.
- **AC-3** - Given the confirm form, when it is submitted (Save pressed, or
  Enter in the title), then the submit event's default action is prevented. A
  test fails under `271s#event.preventDefault();##`.
- **AC-4** - Given `createEvent` resolves with a non-ok result once and ok the
  second time, when the owner presses Save event, sees the save-failed alert,
  and presses Save event again, then the second press calls `createEvent` a
  second time and the event is saved. A test fails under `297s#end();##`.
- **AC-5** - Given a valid proposal, when the confirm screen opens, and again
  after a submit refused by validation, then no element with role `alert`
  carries the save-failed text. A test fails under
  `214s#useState(false)#useState(true)#` and under `setFailed(false)` →
  `setFailed(true)` at `:277`.
- **AC-6** - Given the clock at exactly 14:00:00.000 local and a proposal with
  no `startsAt`, when the screen opens, then the start is 14:00 on that day. A
  test fails under `66s#d.getTime() < now.getTime()#d.getTime() <= now.getTime()#`.
- **AC-7** - Given a submit refused because the end is before the start, then
  focus is on the End date input. A test fails under `279s#focusField(found);##`.
- **AC-8** - Given the form view, then "Show what was captured" has an
  `aria-controls` naming the element it reveals, and the `<h1>` has
  `tabindex="-1"`. A test fails with `:200`'s `sourceId` template replaced by
  an empty string, and under `324s#tabIndex={-1}#tabIndex={1}#`.
