## Context

EPIC-06. Source: `docs/wiki/audits/EPIC-06-2026-11-21.md` (Decided 4,
Evidence E-PROBE P4). Found while classifying the one `TimeGrid.tsx`
survivor (`:141`, the `?? { column: 0, columns: 1 }` fallback, equivalent);
it is a defect, not a surviving mutant.

CAL-074 made each time-grid block carry the occurrence it was clipped from
(`originals[i]`), because two occurrences of one series share an `id`. The
**layout** is still looked up by that shared id:
`overlapColumns(clipped)` (`src/domain/timeGrid.ts:67`) returns a
`Map<string, { column, columns }>` keyed by `event.id`, and
`TimeGrid.tsx:141` reads it with `layout.get(c.id)`. When the two occurrences
fall in different overlap clusters, the later cluster overwrites the earlier
one's entry. Measured on `main` at `c5a07a2` (E-PROBE P4, `overlapColumns`
called directly): with the series `S` clipped to 00:00-01:00 and 23:00-24:00
on 3 November 2026 and a one-off `X` at 00:30-01:30, the map holds
`S -> { column: 0, columns: 1 }` and `X -> { column: 1, columns: 2 }`. So the
00:00 block is drawn full width (`width: calc(100% / 1 - 2px)`) on top of
`X`, which takes the right half. CAL-074's own tests do not see it: their
two occurrences are alone in the column, so both clusters are one column.

The case is an overnight daily or weekly series beside anything in its first
hours, which is the case CAL-074 exists for.

Required gate that would fail: `unit` (and `coverage`).

## Acceptance criteria

- **AC-1** - Given the day view of Wednesday 14 October 2026 holding the two
  occurrences of CAL-074's daily 23:00-01:00 series (the 13th's, "Late
  shift", clipped to 00:00-01:00, and the 14th's, "Night", at 23:00-24:00)
  and a one-off timed event 00:30-01:30, when the time grid renders, then the
  "Late shift" block and the one-off each take half the column (the Late
  shift block `left: 0%`, the one-off `left: 50%`, both
  `width: calc(100% / 2 - 2px)`), and the "Night" block takes the whole
  column (`left: 0%`, `width: calc(100% / 1 - 2px)`).
- **AC-2** - The same three events with the one-off at 23:30-23:45 instead:
  "Night" and the one-off each take half the column, and "Late shift" the
  whole of it. Both criteria fail today, in opposite directions (E-PROBE P4,
  measured on these times): under AC-1 the Late shift block is drawn full
  width over the one-off; under AC-2 it is drawn at half width beside
  nothing, because the 23:00 cluster's `{ column: 0, columns: 2 }` won.

**Block 1 - the design: the layout is keyed by the event object, not by its
id.** `overlapColumns` in `src/domain/timeGrid.ts` changes its return type and
nothing else:

    export function overlapColumns(
      events: Event[],
    ): Map<Event, { column: number; columns: number }>

The key of each entry is **the very object passed in** (reference identity),
so two timed events that share an `id` each get an entry of their own. Every
other rule is unchanged and stays pinned by the existing CAL-010 tests: all-day
events are not in the map; start order, then the longer first, then title,
decides the columns; touching end-to-start is not overlapping; an entry's
`columns` is the column count of its own cluster. `column` is 0-based from the
left; `columns` is how many columns its cluster has, so a block's share of the
day column is `1 / columns` and its left edge is `column / columns`.

Why this and not the two alternatives (recorded so nobody re-derives it):
keying by `chipKey` would make `src/domain` import
`src/sync/useOccurrences.ts`, which imports React and the stores, and
`architecture.md` has `domain` as pure functions with no I/O; an array aligned
to the input by index would need an entry for an all-day event, which today
has none. Object identity needs no identity scheme at all, so CAL-074 Block 2
("no second identity scheme") holds.

**Block 2 - the caller.** `src/calendar/TimeGrid.tsx:141` reads the layout
with the clipped object it passed in (`layout.get(c)`), not `c.id`. `clipped`
and `originals` stay index-aligned exactly as CAL-074 left them; the block's
`event`, its `top` and `height`, and the two style expressions at `:151-152`
(``left: `${(column / n) * 100}%` ``, ``width: `calc(100% / ${n} - 2px)` ``)
do not change. Whether the `?? { column: 0, columns: 1 }` fallback stays is
GREEN's choice (the type still allows `undefined`; the audit classed its
