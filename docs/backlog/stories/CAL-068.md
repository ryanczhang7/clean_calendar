## Context

EPIC-04, from `docs/wiki/audits/epic-04-2026-11-06.md` (Decided 10;
Evidence E-STRYKER `src/sync/SyncStatus.tsx`).

The sync status's toasts and its indicator states are pinned: Stryker killed
136 of `SyncStatus.tsx`'s 165 mutants, and the Redo hand mutant (SY1) was
killed. The **problems dialog** (CAL-015 PO decision 9) is pinned only for
an events op whose row is cached, opened once, and never closed:

- **Only failed ops are problems** (`:89:18`, `:90:13`). With the `status
  === "failed"` filter removed, every queued op is listed too, each with a
  Discard that throws a pending edit away. Every dialog test opens it with
  failed ops alone in the outbox.
- **A kind is named by its name** (`:98`, `:99`, six mutants). With the
  kinds branch removed, emptied or its `?? ""` made `&& ""`, a failed kind
  reads ": invalid input". No dialog test has a kinds op.
- **A row the cache no longer holds** (`:97:15`, `:104:17`, `:110:30`, and
  their `""` fallbacks `:97:54`, `:104:62`, `:110:75`). With `?.` made `.`,
  one uncached row makes `readProblems` throw, its caller's catch empties
  the list, and the dialog opens blank while the status still says
  something could not sync.
- **The dialog closes** (`:217:32`, `:222:22`, `:222:36`). With `onClose`
  or the Close button made to keep it open, neither Escape nor Close closes
  it. No test presses either.

Test-only: the shipped component is believed correct, so each new
assertion passes on arrival and is earned by the mutant its criterion
names.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given an outbox with one failed and one queued op, when "Show
  sync problems" opens the dialog, then it lists exactly the failed op, with
  one Retry and one Discard. A test fails when `SyncStatus.tsx:89`'s
  `.filter(…)` is removed and when `:90`'s `op.status === "failed"` is
  `true`.
- **AC-2** - Given a failed `kinds` op for a cached kind named "Gym", when
  the dialog opens, then its row reads "Gym: {message}". A test fails under
  the `:98` mutants (`false`, `""`, the block emptied) and the `:99`
  mutants (`&& ""`, `?.` made `.`, the `""` fallback changed).
- **AC-3** - Given two failed ops, one whose cache row is gone (an event,
  and separately a reminder and an override whose rows are gone), when the
  dialog opens, then both are listed, and the uncached one is titled `""`
  (its row reads ": {message}"). A test fails under `:97:15`, `:97:54`,
  `:104:17`, `:104:62`, `:110:30` and `:110:75`.
- **AC-4** - Given the open problems dialog, when Close is pressed, then the
  dialog is closed; and when it is reopened and Escape is pressed, then it is
  closed. A test fails when `:222`'s handler does nothing or sets `true`, and
  when `:217`'s `onClose` sets `true`.
