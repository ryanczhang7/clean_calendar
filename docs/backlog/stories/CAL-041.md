## Context

EPIC-03, from `docs/wiki/audits/epic-03-2026-10-21.md` (Decided 4 and 8;
Evidence E-STRYKER `src/calendar/CalendarPage.tsx`, hand mutants H16, H17,
H19).

CAL-013 gave the page moves, resizes, deletes and their undo toasts.
Stryker, with the whole unit suite as the final judge, left these mutants of
`src/calendar/CalendarPage.tsx` alive:

- **A successful undo also shows "Couldn't save. Try again."** (`:182`,
  `if (r.status !== "ok") failed()` → `failed()`). The owner is told the
  undo failed when it worked. The case "a refused undo shows …"
  (`CalendarPage.test.tsx:1812`) pins the refusal. Nothing pins the absence
  of the alert after success.
- **`Alt+↑` is untested in every view.** With `case "up"` removed (`:125`),
  the command falls out of the switch and the key handler throws. With the
  sign made `+1` (`:127`, three mutants), `Alt+↑` moves the event *down*: a
  week later in the month, 15 minutes later in a time grid. CAL-013's AC-3
  names only `Alt+→`, and the suite covers `Alt+→` and `Alt+↓`.
- **An all-day event and `Alt+↑` in a time grid** (`:132`,
  `if (event.allDay) return null` → `false`). The start minus 15 minutes
  falls on the previous day, so the event moves a day earlier. The existing
  case uses `Alt+↓`, which this mutant leaves a no-op, so it cannot see it.
- **Focus after the second keyboard move** (`:163:48`, the focus reducer →
  `() => undefined`). The first move focuses the moved chip. Every later one
  does not, because the state stops changing.
- **A move out of the visible period** (`:170`, `?.focus()` → `.focus()`).
  `Alt+→` on a Sunday block in the week view moves the event into a week
  that is not rendered. The mutant throws inside an effect, and the router's
  boundary replaces the page.
- **Once-only undo rests on the toast's dismissal alone** (`:179`, `:180`;
  audit Decided 8, H19). With the page's `once()` and the toast's `done`
  flag **both** removed, `CalendarPage.test.tsx` and `Toast.test.tsx` stay
  green (138/138). "an undo runs once: Ctrl+Z after Undo writes nothing more"
  (`:1798`) is satisfied by the toast closing.

Test-only: the shipped page is believed correct, so each new assertion
passes on arrival and is earned by its mutant.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given a move (drop or `Alt+→`) and a delete, each undone
  successfully (Undo or Ctrl+Z), when the undo's write resolves ok, then no
  alert toast appears and no element with `role="alert"` holds "Couldn't
  save. Try again.". A test fails when `:182` becomes an unconditional
  `failed()` (audit H16).
- **AC-2** - Given a focused month chip on day D, when `Alt+↑` is pressed,
  then `update` is called with the span exactly seven days earlier at the
  same time of day, the toast reads "Moved to" that earlier date, and focus
  is on the moved chip. A test fails when `case "up"` is removed (`:125`) or
  the sign is `+1` (`:127`; audit H17).
- **AC-3** - Given a focused timed block in the week view, when `Alt+↑` is
  pressed, then it moves 15 minutes earlier with its duration kept. A test
  fails under the same mutants as AC-2.
- **AC-4** - Given a focused **all-day** chip in the week view, when `Alt+↑`
  is pressed, then `update` is not called and no toast appears. A test fails
  when `:132` is `if (false)`.
- **AC-5** - Given a focused month chip, when `Alt+→` is pressed **twice**,
  then after each move resolves, focus is on the moved chip (it may be a new
  element). A test fails when the focus reducer at `:163` returns a constant.
- **AC-6** - Given a focused block on the Sunday of the week view, when
  `Alt+→` is pressed, then `update` is called, the page is still rendered
  (the week grid is present), and no error is thrown or logged. A test fails
  when `:170`'s `?.focus()` becomes `.focus()`.
- **AC-7** - Given a move's undo toast, when its action is invoked twice
  before React re-renders (the Undo button's click and a Ctrl+Z keydown
  dispatched in the same task, outside `act`), then the undo's `update` is
  called exactly once. A test fails when the page's `once()` guard
  (`:179` `if (used) return` or `:180` `used = true`) is removed **on its
  own**, with the toast's `done` flag intact.
