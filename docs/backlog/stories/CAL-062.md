## Context

EPIC-04, from `docs/wiki/audits/epic-04-2026-11-06.md` (Decided 1 and 5;
Evidence E-STRYKER `src/sync/cachedStores.ts`, E-HAND C91 and C155).

`cachedTable` (CAL-014 Block 4) starts one Dexie `liveQuery` on the first
subscribe and stops it on the last unsubscribe; `withSyncMarkers` (CAL-015
Block 6) marks an event `failed` if any of its ops failed, else `saving`.
Stryker killed 108 of the module's 128 mutants. Two defects that survive
**the whole unit project** (3000/3000 each, measured by hand) are the ones
that matter:

- **Any unsubscribe stops the stream** (`cachedStores.ts:91`). With the
  guard reduced to `if (live !== null)`, the first listener to leave stops
  the liveQuery while others still listen, so every remaining view stops
  following the cache. The kinds store is read through `useKinds` by several
  components at once (`CalendarPage.tsx:469`, `:543`, `WeekView`, `DayView`,
  `KindLegend`), so a view
  switch would leave the page blind to a Realtime row or a drained op until
  something subscribes afresh. No test holds two listeners and removes one.
- **A later queued op hides a failure** (`:155`). With `else if
  (!marks.has(op.id))` reduced to `else`, an event whose op failed and was
  then edited again is marked `saving`, so its chip loses the failed badge
  and the sheet's failed-sync strip (CAL-045, gated on `sync === "failed"`)
  never shows. Every marker test queues the ops in the other order or one op
  per event.

Two lower-impact holes in the same file: an `"existing"` seed outcome that
writes the server's kinds into the cache itself (`:125:11` → `true`, W125t:
3000/3000), past the pending-op filter the sync applies, so a kind rename
still queued would be overwritten at start-up (reasoned); and a `refresh()`
whose re-read throws (`:66-67`; the catch can be emptied, so "only a cache
that cannot be read publishes unavailable" holds for `subscribe` but is not
pinned for `refresh`; W67: 3000/3000). The `"seeded"` half of `:125` is
pinned: with the write turned off, five `AppShell.test.tsx` legend cases
fail (W125).

Test-only: the shipped module is believed correct, so each new assertion
passes on arrival and is earned by the mutant its criterion names.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given a cached events store (and, separately, a cached kinds
  store) with **two** subscribed listeners, when one unsubscribes and a row
  is then written to the cache, then the remaining listener is called and
  `getSnapshot()` shows the row. A test fails when `cachedStores.ts:91` is
  `if (live !== null)` and when its `listeners.size === 0` is `true` or
  `listeners.size !== 0` (audit C91; Stryker `:91:13` → `true` and `!==`).
- **AC-2** - Given an event with a **failed** op and, after it, a **queued**
  op (higher `seq`), when the store publishes, then the event carries `sync:
  "failed"`. A test fails when `:155`'s `!marks.has(op.id)` is `true`
  (audit C155).
- **AC-3** - Given `ensureSeeded()` whose seed answers `"existing"` with
  rows, and an outbox holding a queued update of one of those kinds, when it
  resolves, then the cached kind still shows the queued value: the kinds
  store wrote nothing to `db.kinds` itself, and the sync after it held the
  row. A test fails when `:125`'s condition is `true` (audit W125t).
- **AC-4** - Given a subscribed store whose `read()` rejects during
  `refresh()`, when `refresh()` resolves, then the snapshot's status is
  `"unavailable"`. A test fails when the catch at `:66` is emptied or the
  `unavailable()` call at `:67` is removed.
