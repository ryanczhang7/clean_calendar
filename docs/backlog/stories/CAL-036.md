## Context

EPIC-01, from `docs/wiki/audits/epic-01-2026-10-15.md` (Decided 6;
Evidence E-TS-AppShell, E-TS-SignInPage, E-TS-NotFound, E-TS-Dialog).
Stryker 10, running the whole unit suite per mutant, left these
user-visible behaviours with no test that notices them breaking. None of
them is access control: the owner gate and `isOwnerEmail` were killed
cleanly.

- **Account menu** (`src/app/AppShell.tsx`), 15 gap survivors:
  - closing on a pointerdown outside the menu (`:22`–`:35`, 12 mutants).
    GREEN built this, CAL-002's Contract does not mention it, and users see
    it;
  - `event.key === "Escape"` → `true` (`:38:9`). Any key would close the
    menu and pull focus back to the button, so the menu could not be used
    from the keyboard. The Escape test passes because Escape is a key;
  - the **Notifications** item closing the menu (`:71`). The Contract says
    "a click on an item closes it", and only Kinds is tested.
- **Sign-in page** (`src/auth/SignInPage.tsx`), 3 gap survivors:
  - the owner's redirect off `/signin` uses `replace: true` (`:116`).
    Without it, Back lands on `/signin`, which redirects forward again;
  - the redirect happens once under StrictMode (`:115`,
    `sent.current = true`). CAL-003's Notes, clarification 1, names this
    hazard and says "the tests do not run under StrictMode and cannot catch
    this".
- **Heading tab order**: `tabIndex={-1}` → `{+1}` on the refusal's `<h1>`
  (`SignInPage.tsx:38`), the sign-in card's `<h1>` (`:80`) and
  `NotFoundPage`'s `<h1>` (`NotFoundPage.tsx:8`). The tests call `.focus()`,
  which works either way. A positive tabindex puts the heading first in the
  Tab order (`accessibility.md`, Focus).
- **Dialog Escape** (`src/ui/Dialog.tsx:49`): removing
  `event.preventDefault()` survives. The browser then closes the dialog
  even when the parent keeps `open` true, and the two drift apart.

Test-only: the shipped components are believed correct, so each new
assertion passes on arrival and is earned by its mutant.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** — Given the account menu is open, when a pointerdown lands outside
  the menu and its button, then the menu closes; and when one lands inside
  the menu, it stays open. A test fails when the outside-click effect is
  removed or its condition inverted (audit: `AppShell.tsx:22:3`, `:23:9`,
  `:27:9`, `:35:6`).
- **AC-2** — Given the account menu is open with focus inside it, when a key
  other than Escape is pressed (e.g. `ArrowDown`, `Tab`), then the menu stays
  open. A test fails when the Escape check is `true` (audit `:38:9`).
- **AC-3** — Given the account menu is open, when **Notifications** is
  chosen, then the app is at `/settings/notifications` and the menu is
  closed. A test fails when that item's `setOpen(false)` is removed (audit
  `:71:22`).
- **AC-4** — Given a signed-in owner arrives at `/signin` with a remembered
  path, when they are redirected, then the history entry for `/signin` is
  replaced, not pushed: going back does not return to `/signin`. A test
  fails when `replace: true` is dropped (audit `SignInPage.tsx:116`).
- **AC-5** — Given the app rendered inside `<StrictMode>` with a remembered
  path, when the owner's session settles on `/signin`, then they land on the
  remembered path, not `/`. A test fails when `sent.current = true` becomes
  `false` (audit `SignInPage.tsx:115:20`).
- **AC-6** — Given the sign-in card, the refusal and the not-found page, when
  each renders, then its `<h1>` has `tabindex="-1"`. A test fails when any
  of the three becomes `+1` (audit `SignInPage.tsx:38:23`, `:80:23`,
  `NotFoundPage.tsx:8:21`).
- **AC-7** — Given an open `Dialog` whose parent ignores `onClose`, when
  Escape is pressed, then the dialog is still open. A test fails when
  `event.preventDefault()` is removed from the cancel handler (audit
  `Dialog.tsx:49:5`).

## Contract

**Writes:** `src/app/AppShell.test.tsx`, `src/auth/SignInPage.test.tsx`, `src/app/routes.test.tsx`, `src/ui/Dialog.test.tsx`

- AC-1 is behaviour GREEN chose and the design never stated. If the Lead
  Designer rules outside-click dismissal out, AC-1 is dropped at PLANNED and
  the code question goes to its own story. Do not test it into permanence
  by default.
- AC-4: the tests render through `createMemoryRouter`. Assert on the
  router's history (e.g. `router.state.historyAction === "REPLACE"` after
  the redirect, or `router.navigate(-1)` not reaching `/signin`), not on
  the `navigate` mock's arguments. The audit's rule on needles applies.
- AC-5 needs the real `<StrictMode>` around the router in that one test.
  Under it, React 19 double-invokes effects in development, which is what
  the mutant depends on.
- AC-7: the jsdom dialog stub in `src/test/setup.ts` dispatches a cancelable
  `cancel` on Escape and closes "unless prevented", so this is observable
  in jsdom.
- Earning: one `scripts/mutate.sh` run per AC against the one test file
  that holds it. The audit's survivor list gives the line and the mutant.
- `SignInPage.test.tsx` is also CAL-038's file. Those two do not run side by
  side.
