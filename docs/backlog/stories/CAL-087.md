## Context

EPIC-07. Source: `docs/wiki/audits/EPIC-07-2026-11-23.md` (Decided 2,
Evidence E-SHEET and E-WHOLE).

The event sheet decides which reminder value a save writes
(`src/events/EventSheet.tsx:243-279`, CAL-057 Block 4 as amended three
times, and CAL-072). Two rules there have no test, and each decides **when**
a reminder fires.

1. **Only a stored "At time" follows an All-day switch.** An untouched field
   counts as chosen only when the stored value is "At time" (0 or -540) and
   All day was switched in this sheet (`:256-260`). Every existing test of
   the switch (`EventSheet.test.tsx:2541-2594`, `:2815`, `:2897`, `:2952`)
   stores "At time". None stores a numbered value. So the mutant
   `:258`, `(choiceFor(originalMinutes) === "at" &&` -> `... ||` (Stryker
   `258:6` LogicalOperator) survives the **whole unit project**. Its
   sibling, `258:6` ConditionalExpression `true` (the left operand
   replaced), survived the full sheet, form, chip and page suites in the
   audit's recheck run. It was not run over the whole project. Under
   either, an event with "30 minutes before" whose All day is
   switched on and saved with Reminder untouched has its reminder rewritten
   to -540 ("At 09:00 on the day"). The select still shows "30 minutes
   before", and the reminder now fires at 09:00 on the day. Switching off an
   all-day event with "1 day before" rewrites it to 0, "at start time". No
   error appears.
2. **A date's basis is the series' All day.** For an occurrence whose All
   day is unchanged in the sheet, `storedAllDay` is
   `request.series?.allDay ?? initial.value.allDay` (`:270-272`). CAL-072
   pinned the timed series with a date overridden to all-day (`:2853`,
   `:2877`). The mirror case, an all-day series with a date overridden to
   timed, is not tested. So `:271`, `??` -> `&&` (`271:10`), survives the
   whole unit project. Under it, "At time" picked on that date writes 0 to
   the series: the reminder fires at local midnight, not at 09:00.

The audit measured both survivals through `scripts/mutate.sh` against the
unit project with the two sandbox-broken git-listing files excluded (E-WHOLE).
The impact above is reasoned from the code, not observed in a running app.

Test-only. The shipped sheet is believed correct, so each case passes on
arrival and is earned by its mutant (DV-1, DV-2). Required gate that would
fail: `unit` (and `coverage`).

## Acceptance criteria

- **AC-1** - Given an existing timed event whose reminder template is 30,
  when the owner switches All day on, leaves Reminder untouched and saves,
  then `updateEvent` is called once and neither `setReminder` nor
  `clearReminder` is called. A test fails under
  `258s/(choiceFor(originalMinutes) === "at" \&\&/(choiceFor(originalMinutes) === "at" ||/`
  on `src/events/EventSheet.tsx`.
- **AC-2** - Given an existing all-day event whose reminder template is 1440,
  when the owner switches All day off, leaves Reminder untouched and saves,
  then `updateEvent` is called once and neither `setReminder` nor
  `clearReminder` is called. The same mutant fails it.
- **AC-3** - Given an all-day weekly series whose template is 15, and one
  date overridden to timed, when the owner opens that date, picks "At time"
  and saves with no other change, then `setReminder(series id, -540)` is
  called exactly once, no scope question is asked, and neither
  `setOverride`, `updateEvent` nor `clearReminder` is called. A test fails
  under `271s/request.series?.allDay ?? initial.value.allDay/request.series?.allDay \&\& initial.value.allDay/`,
  showing 0.
