## Context

EPIC-03, brief §4.1: week and day views - desktop-first for browsing a week
(§8). The time grid: `components.md`, "Week / day time grid"; maths:
`layout.md`, "Grid maths that tests can pin" (block position and height,
overlap columns, all-day row); phone week is a 3-day window (`layout.md`,
"Phone specifics"). Built as `WeekView` and `DayView` components over a shared
`TimeGrid`, reusing `EventChip` and `useEventsInRange` from CAL-009. Mounting
them under the routes is CAL-011's.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given `--size-hour` of 48px, when `blockGeometry(start, end)` is
  computed, then `top = minutes since 00:00 / 60 × 48` and
  `height = max(duration / 60 × 48, 20)`; a 15-minute event is 20px. (Settled:
  `layout.md`.)
- **AC-2** - Given timed events whose intervals intersect, when columns are
  assigned, then intersecting events share the width equally in start order
  (two overlapping → two halves; a third overlapping both → thirds) and an
  event that overlaps none takes the full width. Touching end-to-start does
  not count as overlapping.
- **AC-3** - Given the week of 12 October 2026 at desktop width, when
  `WeekView` renders, then the grid is named "Week of 12 October 2026", has
  seven day columns Monday to Sunday, and its slots are `gridcell`s named like
  "Wednesday 14 October, 09:00"; `DayView` for 14 October is named "Wednesday
  14 October 2026" with one column.
- **AC-4** - Given all-day events, when the all-day row renders, then its height
  is `max(1, min(3, count)) × 24 + 8` px and a fourth event becomes a "+1"
  button.
- **AC-5** - Given today is in view, when the grid renders, then a now-line with
  `aria-hidden="true"` is positioned at the current minute in today's column
  only, and the scroll container's initial `scrollTop` puts now one third
  from the top; otherwise it puts 08:00 at the top.
- **AC-6** - Given the phone breakpoint, when `WeekView` renders for a selected
  day, then it shows three columns: the day before, the selected day and the
  day after.

### Block 1 - `src/domain/timeGrid.ts` (pure)

```ts
import type { Event } from "../data/rows";
export const MIN_BLOCK_HEIGHT = 20;            // layout.md: a 15-minute event is 20px
export const ALL_DAY_CHIP_HEIGHT = 24;         // layout.md: all-day row maths
export const ALL_DAY_ROW_PADDING = 8;
export const ALL_DAY_MAX_CHIPS = 3;            // beyond three, a "+N" button
export const HOUR_HEIGHT = { phone: 56, tablet: 48, desktop: 48 } as const;
export const SCROLL_FALLBACK_HOUR = 8;         // 08:00 at the top when now is not in view

/** Whole minutes since local midnight: hours × 60 + minutes; seconds ignored. */
export function minuteOfDay(d: Date): number;
/** AC-1. top = minuteOfDay(start) / 60 × hourHeight; height = max((end − start in minutes) / 60 × hourHeight, MIN_BLOCK_HEIGHT). */
export function blockGeometry(start: Date, end: Date, hourHeight: number): { top: number; height: number };
/** The [start, end) of `event` clipped to the local day `day` (a midnight); null when it does not occupy the day. */
export function clipToDay(event: Event, day: Date): { start: Date; end: Date } | null;
/** AC-2. Column index and column count per event id, for the timed events of ONE day. */
export function overlapColumns(events: Event[]): Map<string, { column: number; columns: number }>;
/** AC-4. max(1, min(ALL_DAY_MAX_CHIPS, count)) × ALL_DAY_CHIP_HEIGHT + ALL_DAY_ROW_PADDING. */
export function allDayRowHeight(count: number): number;
/** AC-5. With `nowTop` a number: max(0, nowTop − viewportHeight / 3); with null: SCROLL_FALLBACK_HOUR × hourHeight. */
export function initialScrollTop(nowTop: number | null, hourHeight: number, viewportHeight: number): number;
/** Monday 00:00 local of the week holding `d`. */
export function weekStart(d: Date): Date;
/** `n` consecutive local midnights from `first`. */
export function daysFrom(first: Date, n: number): Date[];
```

Settled numbers (AC-1, AC-4; `layout.md`): at 48px/h, 09:00–10:30 → `{ top:
432, height: 72 }`; 09:15–09:30 → `{ top: 444, height: 20 }` (12 would be
below the floor); 00:00–24:00 (end = next midnight, after `clipToDay`) →
`{ top: 0, height: 1152 }`; at 56px/h, 09:00–10:00 → `{ top: 504, height:
56 }`. An end before or equal to start gets `MIN_BLOCK_HEIGHT`. `allDayRowHeight`:
0 → 32, 1 → 32, 2 → 56, 3 → 80, 4 → 80, 9 → 80. `initialScrollTop(432, 48, 600)`
→ 232; `initialScrollTop(100, 48, 600)` → 0 (clamped); `initialScrollTop(null,
48, 600)` → 384; `initialScrollTop(null, 56, 0)` → 448.

`clipToDay` is CAL-009's occupancy predicate with the clipping made explicit:
start is `max(startsAt, day)`, end is `min(endsAt, nextMidnight(day))`; an
event ending exactly at `day`'s midnight returns null (it belongs to the day
before); one starting exactly at midnight belongs to this day; one crossing
midnight returns `[startsAt, nextMidnight]` for the first day and `[midnight,
endsAt]` for the second.

**AC-2 semantics, worked out.** Two events *overlap* iff `a.startsAt <
b.endsAt && b.startsAt < a.endsAt` - strict on both sides, so 09:00–10:00 and
10:00–11:00 **do not** overlap (the deferred verification flips this). Sort by
`startsAt` ascending, then `endsAt` descending (the longer first), then
`title`. Walk in that order; a *cluster* is a maximal run of events each of
which overlaps at least one earlier member of the run (transitive). Within a
cluster each event takes the lowest column whose previous occupant ends at or
before this event's start; the cluster's `columns` is its highest column + 1,
shared by every member (equal widths, no cascading offsets - `layout.md`).
Examples to pin: A 09–10, B 09:30–10:30 → A `{0, 2}`, B `{1, 2}`; adding C
10:00–11:00 (overlaps B, not A) → C `{0, 2}` and `columns` stays 2 for all
three; A 09–10, B 09–10, C 09–10 → columns 0, 1, 2 of 3; A 09–10, B
10–11 → both `{0, 1}` (touching); a lone event → `{0, 1}`; two clusters in
one day (09–10 with 09–10, then 14–15 alone) → `{0,2}`, `{1,2}`, `{0,1}`. An
all-day event passed in is ignored (not in the map) - the caller filters.

### Block 3 - `src/calendar/TimeGrid.tsx`

```ts

export function TimeGrid(props: {
  /** Local midnights, in column order; 1, 3 or 7 of them. */
```

`hourHeight = HOUR_HEIGHT[useBreakpoint()]`. `dayName(d) = format(d, "EEEE d
MMMM")`. Markup, in DOM order:

```html
<div class=timeGrid data-breakpoint="desktop" style="--hour-height: 48px">
  <div role="grid" aria-label={label} aria-busy="true"?>          <!-- aria-busy only while loading -->
    <div role="row" class=header>
      <div class=gutter aria-hidden="true"></div>
      <div role="columnheader" aria-label="Wednesday 14 October" aria-current="date"?><span aria-hidden="true">WED 14</span></div>  ×days
    </div>
    <div role="row" class=allDay style="height: {allDayRowHeight(maxAllDay)}px">
      <div class=gutter aria-hidden="true">all day</div>
      <div role="gridcell" aria-label="Wednesday 14 October, all day">
        <EventChip event kind />  ×min(count, 3), all-day chips in startsAt then title order
        <button type="button" aria-label="1 more all-day event on Wednesday 14 October">+1</button>?   <!-- "{n} more all-day events on …" for n > 1; only when count > 3 -->
      </div>  ×days
    </div>
    <div class=scroll data-scroll>                                 <!-- the scroll container; overflow-y: auto; height from CSS -->
      <div role="row" class=hour>  ×24, hour h = 0..23
        <div class=gutter aria-hidden="true">09:00</div>            <!-- format(h, "HH:00") -->
        <div role="gridcell" aria-label="Wednesday 14 October, 09:00"></div>  ×days
      </div>
      <div class=overlay aria-hidden="false">                       <!-- absolutely over the 24 rows, one column per day -->
        <div class=column data-day="2026-10-14">                    <!-- dayKey(day) -->
          <div class=block style="top: 432px; height: 72px; left: 0%; width: calc(50% - 2px)">
            <EventChip variant="block" height={72} event kind />
          </div>  ×timed events clipped to this day
          <div class=nowLine aria-hidden="true" data-now style="top: {minuteOfDay(now)/60 × hourHeight}px"></div>  <!-- today's column only -->
        </div>  ×days
      </div>
    </div>
  </div>
</div>
```

- `aria-current="date"` on the one columnheader whose day is `now`'s local
  date; `data-now` exists in exactly that day's column and nowhere else; when
  `now` is outside `days`, neither exists.
- Per column, timed blocks are the events with `clipToDay(e, day) !== null &&
  !e.allDay`; `overlapColumns` runs over those events (with the **clipped**
  start/end deciding overlap for that day) and `left = column / columns ×
  100%`, `width = calc(100% / columns − 2px)` - the 2px gap of
  `components.md`. `top`/`height` come from `blockGeometry(clipped.start,
  clipped.end, hourHeight)`.
  *Sharpened by RED, 2026-10-17:* `left` must be written as a percentage
  string (`"0%"`, `"50%"`, never the number `0`, which React renders `0px`);
  `width` may be written either as `calc(100% / ${columns} - 2px)` or as
  `calc(${100 / columns}% - 2px)`, because jsdom 30.1.2 normalises both to
  `calc(50% - 2px)` / `calc(33.3333% - 2px)` (measured 2026-10-17) and the
  tests parse the percentage numerically (to 3 decimal places). A one-column
  block reads back exactly `calc(100% - 2px)`; a two-column one exactly
  `calc(50% - 2px)`. `top`/`height` are read back as exact `"Npx"` strings.
  The block element need not be the chip's direct parent: tests take the
  nearest ancestor of the chip with an inline `top`.
- `maxAllDay` is the largest per-day all-day count over `days`; the row
  height is one number for the whole row.
- The "+N" button navigates to `/day/${dayKey(day)}` (as the month's more
  button does; CAL-011 makes that view real).
- **Initial scroll (AC-5):** a `useLayoutEffect` on mount, once, sets
  `scroll.scrollTop = initialScrollTop(todayColumn ? nowTop : null,
  hourHeight, scroll.clientHeight)`. jsdom keeps an assigned `scrollTop`
  (measured 2026-10-17 on jsdom 30.1.2: set 123, read 123) and reports
  `clientHeight` 0, so under test the expected values are `nowTop` (today in
  view) and `8 × hourHeight` otherwise, exactly what the pure function says
  for a viewport of 0 - the test asserts through the function, not a literal.
- `TimeGrid.module.css`: `--hour-height` set inline on the root as above
  and read by `.hour { height: var(--hour-height) }`; gutter 56px (48px on
  phone, `layout.md`); `.allDay` on `--color-surface-sunken`; `.nowLine` 2px
  `--color-now` with an 8px circle at its left edge via `::before`;
  `--z-nowline`; the scroll region's height fills the viewport under the
  header rows (`layout.md`, Desktop specifics). jsdom sees none of this.
- Lint: the ARIA grid is divs with explicit roles, as `MonthView.tsx`;
  Biome's `useSemanticElements` / `useFocusableInteractive` are suppressed
  with the CAL-009 PO decision 14 wording (roving focus is CAL-011's).
