## Context

EPIC-04, from `docs/wiki/audits/epic-04-2026-11-06.md` (Decided 4;
Evidence E-STRYKER `src/sync/drain.ts`).

The drain is the best-pinned module in the epic: 303 of 399 Stryker mutants
killed plus 17 timeouts (four re-run by hand and killed), and 12 of the 15
hand mutants against it killed. What survives clusters on one situation no
test sets up: **a queued op whose row the cache, or the server, no longer
holds.** It is reachable today. Discarding a failed insert (`discardOp`,
`outbox.ts:304-319`) deletes the cache row and that one op, and leaves any
later op for the same id queued. The drain then sends that op with no cache
row (the token comes from `op.baseUpdatedAt`), the server matches zero rows,
the re-fetch finds none, and the branch at `drain.ts:214-221` drops it.
Every step of that is unpinned:

- **The token fallback** (`:176:19`). With `cached?.updatedAt` made
  `cached.updatedAt`, the send throws, the pass's catch reports `server`,
  and every later pass stops at the same op. The outbox is jammed for good,
  and the only thing shown is "Syncing n changes".
- **A row gone from the server altogether** (`:214`, `:216`, `:220`, six
  mutants). Remove the branch and the pass stops at the op on every run.
  Empty its transaction and the op is resent forever. Return `""` and the
  pass stops.
- **A failed notice's title for an uncached row** (`titleFromPatch`,
  `:95-99`, 19 mutants; `eventIdOf`, `:104-107`, 15; `noticeTitle`, `:159`
  and `:162`, 7). Emptied, the toast reads "undefined couldn't sync.". With
  `:162`'s guard broken, `titleOf(undefined)` throws inside the pass.

Test-only: the shipped drain is believed correct, so each new assertion
passes on arrival and is earned by the mutant its criterion names.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given a queued `update` op for an event the cache does **not**
  hold (its row deleted after queueing, as `discardOp` of the insert before
  it leaves it), when the drain runs, then the update is sent with the op's
  `baseUpdatedAt` as the token and the pass goes on to the next op. A test
  fails when `drain.ts:176`'s `cached?.updatedAt` is `cached.updatedAt`.
- **AC-2** - Given a queued op whose conditional write matches zero rows and
  whose re-fetch answers `conflict` (the row is gone from the server), when
  the drain runs, then the op leaves the outbox, the cache holds no row for
  the id, no notice is emitted, the pass goes on to the next op, and a second
  `run()` sends nothing for it. A test fails when `:214`'s condition is
  `false`, when its block or the transaction at `:216` is emptied, and when
  `:220` returns `""`.
- **AC-3** - Given a queued `update` op (events, and separately kinds) for a
  row the cache does not hold, answered `http: 400`, when the drain runs,
  then the `failed` notice's `title` is the patch's `title` (a kind: its
  `name`), `""` when the patch names neither, and `""` for a failed `delete`
  op (its patch is `null`). A test fails under the
  `titleFromPatch` mutants at `:95-99` and the `:162` guard mutants.
- **AC-4** - Given a queued reminders op whose reminder the cache does not
  hold, answered `http: 400`, when the drain runs, then the notice is titled
  by the cached event that the patch's `eventId` names, and `""` when the
  patch has no string `eventId` or is `null`. A test fails under the
  `eventIdOf` mutants
  at `:104-107` and the `:159` mutants.
