## Context

EPIC-08: one end-to-end run of the walking path against the local stack, so
that the path the owner uses every day cannot regress unnoticed, plus the
browser-only checks `accessibility.md` ("What tests assert", Integration) and
earlier stories deferred here because jsdom cannot see them: responsive
layout at 375 and 1280, the bottom sheet, focus return, reduced motion, and
axe. It runs against `supabase start`, `supabase functions serve` with
`GEMINI_API_BASE` pointed at a local stub, and `vite preview`.

Required gate that would fail if this broke: `integration`, optional
repo-wide, so it is in `required_gates`.

## Acceptance criteria

- **AC-1** - Given a fresh local database and an owner session injected by the
  session fixture (a local Auth user for the seeded owner e-mail), when the
  app opens, then the walkthrough shows eleven kinds; "Done, show my calendar"
  lands on this month with the empty-month card.
- **AC-2** - Given the month, when an event is created from a day cell in the
  Restaurant reservations kind, then its chip is on
  that day in the kind's light colour, and it is still there after a reload.
- **AC-3** - Given `/capture`, when the stubbed assistant returns a fixed
  flight proposal with the end time missing, then the confirm screen marks End
  as missing, saving after filling it puts a Flights-coloured chip on the
  proposed day, and the stub received exactly one request.
- **AC-4** - Given the viewport 375×812, when the month and the sheet are
  shown, then the page has no horizontal scroll, each bottom-nav tab is at
  least 44×44 px, and the sheet opens as a bottom sheet; at 1280×800 the
  bottom nav is hidden and the sheet docks at 400px.
- **AC-5** - Given axe (`@axe-core/playwright`, tags `wcag2a`, `wcag2aa`,
  `wcag21aa`), when it runs on sign-in, the walkthrough, the month with one
  event in each of the eleven kinds in light and in dark (`emulateMedia`), the
  week with the sheet open, the legend, capture, confirm with a missing field,
  and the edit-scope dialog, then it reports zero violations.
- **AC-6** - Given `reducedMotion: 'reduce'`, when the sheet opens, then its
  computed `transition-duration` is `0s`; and opening a chip then pressing
  Escape leaves focus on that chip.

`pnpm exec supabase start` (Postgres, Auth, PostgREST, Kong on
`http://127.0.0.1:54321`). Everything else is started by `playwright.config.ts`'s
`webServer`, which becomes an **array** of three, in this order:

1. the Gemini stub: `node e2e/fixtures/geminiStub.ts` (Node 24 strips types
   natively) on port **4174**, ready URL `http://127.0.0.1:4174/__health`;
2. the functions runtime: `pnpm exec supabase functions serve --env-file e2e/fixtures/functions.env`,

   without a JWT, which Playwright counts as ready);
3. the app: `pnpm build && pnpm exec vite preview --port 4173` as today, with

**Block 2 - the session fixture.** `e2e/fixtures/session.ts` exports

```ts
export const OWNER_EMAIL = "owner@example.com";
export const OWNER_PASSWORD = "e2e-owner-password";       // local Auth only, not a secret
export type Local = { url: string; anonKey: string; serviceKey: string };
export function local(): Local;                            // from `supabase status -o env`, cached
export async function ensureOwnerUser(): Promise<void>;    // admin API, idempotent
export async function ownerSession(): Promise<Session>;    // password grant → the GoTrue session JSON
export const test: TestType<{ owner: Session; seed: Seed }, {}>;  // extends @playwright/test
export const expect: typeof import("@playwright/test").expect;
```

- `ensureOwnerUser`: `POST {url}/auth/v1/admin/users` with the service-role
  key, body `{email, password, email_confirm: true}`; a 422 "already
  registered" is success.
- `ownerSession`: `POST {url}/auth/v1/token?grant_type=password` with the
  anon key, body `{email, password}`; returns the JSON
  `{access_token, refresh_token, expires_in, expires_at, token_type, user}`.
- The `owner` fixture injects that JSON before any script runs:
  `context.addInitScript` setting `localStorage["sb-127-auth-token"]` to
  `JSON.stringify(session)`. The key is supabase-js's default
  `sb-<first label of the project host>-auth-token`, and the host is
  `127.0.0.1` → `sb-127-auth-token`. **Checkable:** read
  `node_modules/@supabase/supabase-js` for the storage-key rule, or load the
  sign-in page once and inspect `localStorage` after a real password sign-in
  through `supabase.auth` in `page.evaluate`. If the key differs, amend this
  line - the mechanism, not the criterion.
- **A "reload" that proves persistence is a NEW browser context.** The UI
  renders from Dexie (IndexedDB), which survives `page.reload()` whether or
  not the outbox ever drained; so AC-2's "still there after a reload" opens a
  fresh `browser.newContext()` with the session injected again and reads the
  month from Postgres through sync. Deferred verification 1 depends on this:
  with the outbox append skipped, the same-context reload would still show
  the chip and the control would be vacuous.
- `seed`: a helper over PostgREST with the service-role key, so fixtures do
  not walk the UI for state the criterion is not about: `seed.kinds()`
  upserts the eleven `DEFAULT_KINDS` from `src/kinds/defaultKinds.ts` by
  name (`on_conflict=name` is not a constraint - the unique index is
  `lower(name) where deleted_at is null` - so read first, insert the missing);
  `seed.event({...})` inserts one event row; `seed.clear()` deletes events,
  overrides and reminders (not kinds). Reads from the seeded rows go through
  the app's own sync on page load.

**Block 3 - the Gemini stub.** `e2e/fixtures/geminiStub.ts`, a plain

- `POST /v1beta/models/gemini-3.8-flash:generateContent` (the path

  `{candidates:[{content:{parts:[{text: JSON.stringify(REPLY)}]}}]}`, where

- `GET /__requests` → `{count}`; `POST /__reset` → count 0; `GET /__health`

- Every other path → 404 with `{error:"stub"}`.

## Deferred verifications

holds the assertion (`pnpm exec playwright test e2e/<spec>.spec.ts -g "<name>"`);
the `webServer` rebuilds the app on every run, so each costs a build. All
are owned by **GATES** unless stated. RED cannot run any of them: they need
the built app against the live stack, and in RED the source is frozen for
everything but `mutate.sh`, which RED does not reach for.

   (`src/kinds/defaultKinds.ts`), the walkthrough shows ten and AC-1 fails.
   **Owner: GATES.**

   missing `endsAt` is not marked (RED names the line once it has pinned
   the marking), the "End marked missing" assertion fails. **Owner: GATES.**
4. **AC-4 sees the breakpoint.** With `AppShell.module.css`'s `display: none`
   for the bottom nav at ≥600px removed, the 1280×800 "nav hidden"
   assertion fails. **Owner: GATES.**
5. **AC-5 sees a violation.** With `EventChip.tsx`'s `aria-label` on the chip
   button removed (a button with no accessible name is a `button-name`
   violation), the month page's axe assertion fails and names it. **Owner:
   GATES.**
6. **AC-6 reduced motion is read, not assumed.** With the
   `prefers-reduced-motion` block in `src/styles/tokens.css` mutated to keep
   `--duration-slow: 280ms`, the reduced-motion read is `0.28s` and AC-6
   fails. **Owner: GATES.**
7. **AC-6 focus return.** With `opener.focus()` in `EventSheet.tsx` (line
   196) removed, the Escape assertion fails. **Owner: GATES.**
8. **The edge runtime reaches the stub on CI.** AC-3 passes on the PR's
   first `gates` run on ubuntu, where `host.docker.internal` must resolve
   from the CLI's edge-runtime container; the run URL is quoted in
   `## Notes`. If it does not resolve there, the fix is a documented host
   mapping or a stub bound differently, and this entry records which.
   **Owner: REVIEW.**
