## Context

EPIC-01, from `docs/wiki/audits/epic-01-2026-10-15.md` (Decided 8;
Evidence E-flake). This is **not** a surviving-mutant cluster. It is filed
because it makes mutation results untrustworthy: in the audit, 12 of 340
full-suite mutant runs (3.5%) failed one of two `SignInPage` offline tests
for reasons unrelated to the mutant, and in 3 of them that was the only
failure, so Stryker recorded a kill no assertion earned. The tests:

- `src/auth/SignInPage.test.tsx` › offline (AC-5) › "re-enables the button
  when the connection comes back" (`expect(button).not.toHaveAttribute("aria-disabled", "true")`
  fails). CAL-005 saw this once in about 15 full gate runs, and CI has passed it.
- … › "disables the button when the connection drops while the page is
  open" (`toHaveAttribute("aria-disabled", "true")` receives `null`). This
  one is newly observed in the audit.

Both dispatch `online`/`offline` synchronously right after awaiting the
button, then assert without waiting. The page subscribes in a `useEffect`
(`useOnline`, `SignInPage.tsx:54–66`). **The cause is not established.** It
could be the test (asserting before the listener is attached or before the
re-render lands) or the hook (an event missed between the first render and
the subscription, which a real browser could also hit). CAL-005 recorded
that it touched neither file. Load made it more frequent in the audit: up to
four parallel vitest processes plus a db suite. CAL-005 also says the flake
was "filed as a follow-up for its own story". No such story file existed on
2026-10-15.

Required gate that would fail if this broke: `unit` and `coverage` (where
CAL-005 saw it).

## Acceptance criteria

- **AC-1** — Given the unit suite under the load the audit used (four
  concurrent `pnpm exec vitest run --project unit` processes), when
  `src/auth/SignInPage.test.tsx` runs 200 times, then all of its tests pass
  every time. The baseline (failures out of 200 before the change) is
  measured and recorded first, so "it did not fail" is compared with a
  measured rate, not with an anecdote.
- **AC-2** — Given the fix, when `useOnline`'s `online` listener is not
  registered (`SignInPage.tsx:58`, event name → `""`), then "re-enables the
  button when the connection comes back" fails on every run. And when the
  `offline` listener is not registered (`:59`), "disables the button when
  the connection drops while the page is open" fails on every run. The
  tests must still detect the defect they exist for.

## Contract

**Writes:** `src/auth/SignInPage.test.tsx`, `src/auth/SignInPage.tsx`

- First establish the cause, with evidence: e.g. log whether the listener is
  attached at the moment of dispatch, under load. Only then choose between
  a test change (wait for the attribute with `findBy`/`waitFor`, or dispatch
  after the effect has run) and a source change (read `navigator.onLine`
  again when subscribing, so an event missed before the subscription cannot
  leave the state stale). Write the cause and its evidence in `## Notes`. A
  fix in production code needs its own failing test first. Do not add
  retries, `skip`, or a longer timeout.
  rules.md calls those weakening.
- If the change is test-only, `src/auth/SignInPage.tsx` drops out of the
  writes. Update `touches:` at PLANNED.
- A test edited here passes on arrival. Earn it with AC-2's two mutations
  through `scripts/mutate.sh`.
- Conflicts with CAL-036 on `src/auth/SignInPage.test.tsx`. Do this one
  first: CAL-036's earning runs are only trustworthy once this flake is
  gone.
