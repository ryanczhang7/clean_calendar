## Context

EPIC-03, and the brief's first complaint (§1): **every event is editable,
however it was created.** The event sheet is the one place events are created
and edited (`components.md`, "Event sheet (edit/create)"; copy in
`voice.md`; keyboard in `accessibility.md`). The form fields are a separate
`EventForm` component because the capture confirm screen (CAL-020) renders the
same fields. Writes go through `src/sync/eventActions.ts` - online through the
repository until CAL-015 routes them through the outbox behind the same
signatures.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given a month cell or an empty time slot, when it is activated
  (click, or Enter on a slot, or `N` on the focused day), then the sheet opens
  as `role="dialog"` named "New event" with the Title field focused; a slot
  pre-fills a 1-hour event starting there, a month cell an all-day event on
  that day.
- **AC-2** - Given the form, when Save is pressed with an empty title, then
  "Give the event a title." is shown on Title with `aria-invalid="true"` and
  focus moves there; with End not after Start, "End must be after start." is
  shown on End. Nothing is saved in either case.
- **AC-3** - Given Start is changed, when End was after Start, then End moves
  to keep the duration; toggling All day hides the time inputs and keeps the
  dates; an all-day event's End date is shown inclusive (the stored `ends_at`
  stays exclusive, CAL-009).
- **AC-4** - Given a valid new event, when Save is pressed, then `createEvent`
  is called with title, kind, start, end, all-day, location, notes and
  `origin: 'manual'`, the sheet closes, and the chip appears in the view.
  The kind picker defaults to the last kind used on this device, else the
  first live kind.
- **AC-5** - Given an existing event - including one with `origin: 'capture'`
  - when its chip is activated, then the sheet opens named "Edit event:
  {title}" with every field filled and editable, focus on Close; saving a
  change calls `updateEvent(id, patch, updatedAt)` with only the changed
  fields. A captured event shows "Captured from text, {date}" in the header.
- **AC-6** - Given unsaved changes, when the sheet is closed, then the dialog
  "Discard changes?" offers "Keep editing" and "Discard"; with no changes it
  closes at once. On close, focus returns to the chip or cell that opened it.
- **AC-7** - Given an event whose kind is soft-deleted, when it is edited, then
  the kind field reads "Kind removed" and the event saves without changing the
  kind.
