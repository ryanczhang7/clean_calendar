## Context

EPIC-03, and the brief's first complaint (§1): **every event is editable,
however it was created.** The event sheet is the one place events are created
and edited (`components.md`, "Event sheet (edit/create)"; copy in
`voice.md`; keyboard in `accessibility.md`). The form fields are a separate
`EventForm` component because the capture confirm screen (CAL-020) renders the
same fields. Writes go through `src/sync/eventActions.ts` - online through the
repository until CAL-015 routes them through the outbox behind the same
signatures.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given a month cell or an empty time slot, when it is activated
  (click, or Enter on a slot, or `N` on the focused day), then the sheet opens
  as `role="dialog"` named "New event" with the Title field focused; a slot
  pre-fills a 1-hour event starting there, a month cell an all-day event on
  that day.
- **AC-2** - Given the form, when Save is pressed with an empty title, then
  "Give the event a title." is shown on Title with `aria-invalid="true"` and
  focus moves there; with End not after Start, "End must be after start." is
  shown on End. Nothing is saved in either case.
- **AC-3** - Given Start is changed, when End was after Start, then End moves
  to keep the duration; toggling All day hides the time inputs and keeps the
  dates; an all-day event's End date is shown inclusive (the stored `ends_at`
  stays exclusive, CAL-009).
- **AC-4** - Given a valid new event, when Save is pressed, then `createEvent`
  is called with title, kind, start, end, all-day, location, notes and
  `origin: 'manual'`, the sheet closes, and the chip appears in the view.
  The kind picker defaults to the last kind used on this device, else the
  first live kind.
- **AC-5** - Given an existing event - including one with `origin: 'capture'`
  - when its chip is activated, then the sheet opens named "Edit event:
  {title}" with every field filled and editable, focus on Close; saving a
  change calls `updateEvent(id, patch, updatedAt)` with only the changed
  fields. A captured event shows "Captured from text, {date}" in the header.
- **AC-6** - Given unsaved changes, when the sheet is closed, then the dialog
  "Discard changes?" offers "Keep editing" and "Discard"; with no changes it
  closes at once. On close, focus returns to the chip or cell that opened it.
- **AC-7** - Given an event whose kind is soft-deleted, when it is edited, then
  the kind field reads "Kind removed" and the event saves without changing the
  kind.

### Block 1 - `src/domain/eventForm.ts` (pure)

```ts
import type { Event, EventPatch, Kind, NewEvent } from "../data/rows";
export type EventFormValue = {
  title: string;
  kindId: string | null;
  allDay: boolean;
  startDate: string;  // yyyy-MM-dd
  startTime: string;  // HH:mm; ignored while allDay
  endDate: string;    // inclusive while allDay
  endTime: string;
  location: string;
  notes: string;
};
export type FormErrors = { title?: string; end?: string };
export const TITLE_ERROR = "Give the event a title.";
export const END_ERROR = "End must be after start.";
export const TITLE_MAX = 120;
export const LAST_KIND_KEY = "cc.lastKind";
export function readLastKind(): string | null;          // localStorage; null when absent or storage throws
export function storeLastKind(id: string): void;        // swallowed when storage throws (onboarding.ts pattern)
/** `last` when it names a live kind, else the first live kind, else null. */
export function defaultKindId(live: Kind[], last: string | null): string | null;
/** A new event's value: all-day → the two dates equal, times "09:00"/"10:00"; timed → start and end as given. */
export function newEventValue(start: Date, end: Date, allDay: boolean, kindId: string | null): EventFormValue;
/** An existing event's value; an all-day event's endDate is the inclusive last day. */
export function valueFromEvent(event: Event): EventFormValue;
/** Start moved: when the old end was after the old start, the end moves by the same delta (duration kept); otherwise only the start changes. */
export function moveStart(value: EventFormValue, startDate: string, startTime: string): EventFormValue;
/** All-day toggled: times are kept in the value (hidden by the form), dates untouched. */
export function setAllDay(value: EventFormValue, allDay: boolean): EventFormValue;
export function validate(value: EventFormValue): FormErrors;
/** The stored instants: timed → the two local date-times; all-day → startDate 00:00 and endDate + 1 day 00:00. */
export function toInstants(value: EventFormValue): { startsAt: Date; endsAt: Date };
/** Requires a validated value and a kindId; blank location/notes → null; origin "manual", recurrence null, captureJobId null. */
export function toNewEvent(value: EventFormValue, kindId: string): NewEvent;
/** Only the fields whose stored value would differ from `original`; instants compared by getTime; {} when nothing changed. */
export function patchOf(original: Event, value: EventFormValue): EventPatch;
```

`validate`: `title.trim() === ""` → `TITLE_ERROR`; timed and `end <= start`
(as instants) → `END_ERROR`; all-day and `endDate < startDate` → `END_ERROR`
(equal dates are one day and valid); both errors can be present. `moveStart`
worked example: 09:00–10:30 on the 14th, start moved to 15 Oct 14:00 → end
15 Oct 15:30; with end not after start (10:00–09:00) only the start moves.
`valueFromEvent` of an all-day 12–15 Oct (exclusive) → `startDate
2026-10-12`, `endDate 2026-10-14`; `toInstants` of that value → `[12 Oct
00:00, 15 Oct 00:00)`. `patchOf` compares `title`, `kindId`, `startsAt`,
`endsAt`, `allDay`, `location` (blank ↔ null equal), `notes`; a value that
only re-typed the same title yields `{}`. `kindId` in `patchOf` is the
value's kindId when it differs from the original's and is not null; a null
kindId (removed kind kept) never appears in the patch (AC-7).

### Block 5 - `src/events/EventSheet.tsx`

```ts
export type SheetRequest =
  | { mode: "create"; start: Date; end: Date; allDay: boolean; opener: HTMLElement | null }
  | { mode: "edit"; event: Event; opener: HTMLElement | null };
export function EventSheet(props: {
  request: SheetRequest | null;    // null → renders nothing
  kinds: KindsSnapshot;
  actions?: EventActions;          // default eventActions
  onClose: () => void;
}): JSX.Element | null;
```

Markup while open: `<div role="dialog" aria-modal="false" aria-labelledby={titleId} data-sheet>`
(not a native `<dialog>`: the desktop panel is docked and must not trap
focus, `accessibility.md` Focus). In order: a header with `<button
type="button" aria-label="Close">`, `<h2 id={titleId}>` reading "New event"
or `"Edit event: " + title` (AC-5; the heading is the dialog's name), and
for `origin === "capture"` a `<p>` "Captured from text, {format(createdAt,
"d MMM")}"; a `<form noValidate onSubmit>` holding `<EventForm>`; a footer
with `<button type="submit">Save</button>` and `<button
type="button">Cancel</button>`. Save is **never disabled** (`components.md`'s
"disabled while a required field is empty" is replaced by the on-submit
error, PO decision 5, so AC-2's "focus moves there" has something to press).

Behaviour:
- On open: `value` = `newEventValue(start, end, allDay, defaultKindId(kinds.kinds, readLastKind()))`
  for create, `valueFromEvent(event)` for edit; `kindRemoved` = edit and
  `kinds.byId(event.kindId)` undefined or soft-deleted. Focus → the Title
  input (create) or the Close button (edit), in an effect after mount.
- Submit: `errors = validate(value)`; with any error, render them, focus the
  Title input when `errors.title` else the End date input, save nothing
  (AC-2). Otherwise create → `actions.createEvent(toNewEvent(value, kindId))`
  (kindId must be non-null: with no live kinds and no removed kind the picker
  shows nothing to choose and Save reports `TITLE_ERROR`-style nothing -
  unreachable after the walkthrough, not pinned); edit → `patch =
  patchOf(event, value)`; `{}` → close without a request; else
  `actions.updateEvent(event.id, patch, event.updatedAt)`. On `ok`:
  `storeLastKind(kindId)` (create and edit alike), `onClose()`. On a non-ok
  result: stay open, `<p role="alert">` with "Couldn't save. Try again."
  (new copy, added to `voice.md`'s error list by this story - a docs write,
  PO decision 6).
- Dirty = `value` differs from the opening value (field by field). Close,
  Cancel and `Escape` (keydown inside the sheet) → if dirty, open the
  `<Dialog title="Discard changes?">` (`src/ui/Dialog.tsx`) with body
  "You've edited this event." and actions `Keep editing` (closes the dialog
  only) / `Discard` (→ `onClose()`); if clean → `onClose()` at once (AC-6).
- After `onClose()` the sheet unmounts and focuses `request.opener` when it
  is still in the document (AC-6), in the same tick the parent clears the
  request (a `useEffect` cleanup holding the opener).
- `EventSheet.module.css`: docked 400px panel from 1024px, overlay with
  scrim 600–1023px, bottom sheet below (`components.md`); jsdom sees none
  of it.

### PO decisions at PLANNED → RED (2026-10-19, lead-po, Fable 5.1)

1. **No Delete button yet.** `components.md` puts Delete in the sheet header
   "visible always"; delete with undo is CAL-013's whole story, so the button
   arrives with its behaviour there rather than as a dead control here.
2. **One keyboard-reachable slot per time grid, no arrow navigation between
   slots.** AC-1 says "Enter on a slot"; `accessibility.md`'s slot arrow keys
   are in no acceptance criterion of any story. The selected day's 09:00 cell
   carries the tab stop so Enter/Space is reachable; the slot roving model is
   a follow-up story, filed when CAL-013 closes (noted for `plan.sh after`).
3. **`N` creates an all-day event on the selected day in every view.**
   `accessibility.md` says "on the focused day (or now, if none)"; the
   selection always exists after CAL-011, and a timed default would need a
   time nobody chose - the slot click is the path to a timed event.
4. **Month cell activation on tablet/desktop follows `accessibility.md`**: a
   cell with events opens Day view, an empty one opens the sheet (all-day on
   that day). On the phone a tap selects only (CAL-011) and the day list's
   Add opens the sheet - `layout.md`, "Phone specifics".
5. **Save is never disabled.** `components.md` disables it while Title is
   empty; AC-2 wants pressing Save with an empty title to show the error and
   move focus. A disabled button cannot be pressed, so the on-submit error is
   the one mechanism.
6. **One new string**: "Couldn't save. Try again." for a refused write, in
   `voice.md`'s error-message style; added to `voice.md` by this story (docs).
7. **The sheet is not a native `<dialog>`**: `accessibility.md` says the
   docked desktop panel does not trap focus. `role="dialog"` with
   `aria-labelledby`, Escape handled on the sheet. The nested "Discard
   changes?" IS the `Dialog` primitive, which does trap.
8. **Epic done-when checked.** Create from month, week or day and edit every
   field are this story; drag, delete, undo are CAL-013; reload persistence
   is the repository write. No gap. No Lead Designer dispatch: the sheet,
   the picker, the copy and the keyboard are specified.
9. **`touches:` amended** with the view, chip, grid, day-list and shortcut
   files the sheet hooks into (Block 6) and `KindPicker.module.css`. CAL-013
   lists several of the same files and is blocked behind this story, so no
   two in-flight stories share them.
