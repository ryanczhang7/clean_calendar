## Context

EPIC-06. Source: `docs/wiki/audits/EPIC-06-2026-11-21.md` (Decided 2,
Evidence E-STRYKER `recurrence`, E-PROBE P1 to P3, E-RECHECK R1 and R2).

`shared/recurrence.ts` resolves a shifted wall time that does not exist
(spring forward) with the pre-transition offset, and a shifted end the same
way, each on its own (`fromWall`, `:95-105`; `expand`, `:155` and `:160`). When
the start falls in the gap and the end does not, the two are resolved with
different offsets, and the occurrence can end before it starts. Measured on
`main` at `c5a07a2` (E-PROBE P1): a daily New York series stored 7 March 2026
02:30-03:00 EST (`07:30Z`-`08:00Z`) expands on 8 March 2026 to start
`2026-03-08T07:30:00.000Z` and end `2026-03-08T07:00:00.000Z`, **-30 minutes
long**. 02:15-03:15 gives a **zero-length** occurrence
(`07:15Z`-`07:15Z`). The 8 March occurrence is the one day a year the US
clocks go forward; the device zone this repository is developed in
(America/Chicago) does so at the same wall time.

The same audit found two mutants of the same function that survive the whole
unit project, because every DST-resolution test is in London, whose
pre-transition offset in spring is zero:

- `recurrence.ts:103` `return wall - before` -> `return wall + before`. In
  London `before` is 0, so the two agree. In New York the 8 March 02:30
  occurrence would start `2026-03-07T21:30Z`, the evening before.
- `recurrence.ts:151` `if (k === 0)` -> `if (false)`. Occurrence 0 then goes
  through `fromWall` like every other, which is the identity for every
  instant except the second 01:30 of a fall-back night. The test named
  "returns the series' own start and end instants byte for byte" uses
  Kolkata, which has no DST, so it cannot see this. A series whose first
  instant is `2026-10-25T01:30:00Z` London (the GMT 01:30) would draw its
  first occurrence an hour early, at `00:30Z`.

Required gates that would fail if this broke: `unit` and `deno-test` (the
fixture is shared, AC-7 of CAL-023), and `coverage`.

**PO decision needed before RED.** AC-1 states the recommended rule (the
occurrence keeps the series' length when its start falls in a gap). The
alternative is to resolve the end with the offset the start was resolved
with. Both give `08:00Z` for the case below; they differ only when the end
also falls in a gap. Pick one and write it into the `## Contract`.

## Acceptance criteria

- **AC-1** - Given a daily series in `America/New_York` stored 7 March 2026
  02:30-03:00 EST (`2026-03-07T07:30:00Z` to `08:00:00Z`), when it is expanded
  over 8 March 2026 (UTC `2026-03-08T00:00Z` to `2026-03-09T00:00Z`), then the
  8 March occurrence starts at `2026-03-08T07:30:00.000Z` (the pre-transition
  offset, as CAL-023 Block 3 says) and ends at `2026-03-08T08:00:00.000Z`,
  thirty minutes later, not before its start. In both runtimes. A test fails
  under `103s#wall - before#wall + before#` on `shared/recurrence.ts` (start
  `2026-03-07T21:30Z`) and under today's code (end `07:00Z`).
- **AC-2** - Given the same series stored 02:15-03:15 EST
  (`07:15Z`-`08:15Z`), when it is expanded over 8 March 2026, then no
  occurrence has `endsAt` at or before its `startsAt`; the 8 March one starts
  `07:15Z` and ends `08:15Z`. Today it is zero-length.
- **AC-3** - Given a weekly series in `Europe/London` whose stored start is
  `2026-10-25T01:30:00.000Z` and end `02:30:00.000Z` (01:30-02:30 GMT, the
  second 01:30 of that night), when it is expanded from `2026-10-24T00:00Z` to
  `2026-11-02T00:00Z`, then occurrence 0 starts at exactly
  `2026-10-25T01:30:00.000Z` and the 1 November one at
  `2026-11-01T01:30:00.000Z`. A test fails under
  `151s#if (k === 0) {#if (false) {#`.

## Out of scope

- An end that falls in a gap while the start does not (01:30-02:30 New York
  on 8 March): today it resolves to `07:30Z`, one hour after a `06:30Z`
  start, which is the series' length. Not a defect; pin it only if the chosen
  rule touches it.
- Changing how a nonexistent **start** resolves. CAL-023 Block 3 (the
  pre-transition offset) stands; AC-1 pins it in a zone where it is visible.
- The views. A negative-length occurrence is drawn by `TimeGrid` and
  `MonthView` from what `expand` returns; once `expand` cannot return one,
  nothing in the views changes.
- Overrides. An override's own `startsAt`/`endsAt` are instants, not wall
  times, and are used as given.
