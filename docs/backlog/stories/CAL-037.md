## Context

EPIC-01, from `docs/wiki/audits/epic-01-2026-10-15.md` (Decided 7;
Evidence E-tokens). CAL-002 deliberately asserts no token **value**, only
that each theme block declares the right set of names and that the two dark
blocks match. So a dark theme that keeps the light theme's text colour
passes. Measured: `--color-text` set to `#1b1b1f` in both dark blocks
(`src/styles/tokens.css:114` and `:145`) leaves the whole unit suite 220/220
green, with near-black text on a `#121417` surface. `docs/wiki/design/tokens.md`
already gives each text-carrying pair's contrast under the WCAG 2.x formula,
and `accessibility.md` sets the floor (text ≥ 4.5:1; borders and large text
≥ 3:1). That is a mechanical oracle, so this can be pinned without pinning
the values themselves.

Test-only: the shipped tokens are believed to meet the floor (tokens.md's
table says so), so the test passes on arrival and is earned by the mutant
above.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** — Given `tokens.css`, when each text-carrying pair in `tokens.md`'s
  contrast table is resolved for the light theme (`:root`), the media-query
  dark block and the forced `[data-theme="dark"]` block, then each meets its
  floor from `accessibility.md`: 4.5:1 for text and 3:1 for
  `border-strong`. A test fails when `--color-text` in both dark blocks is
  set to `#1b1b1f` (the audit's mutant), and the failure names the pair and
  the theme.
- **AC-2** — Given the same computation, when it is run on the token hex
  values behind each figure in `tokens.md`'s table, then each computed
  ratio agrees with the printed figure to the precision printed: within
  half a unit in its last printed decimal (`5.6` admits 5.55-5.65, `9.30`
  admits 9.295-9.305). This calibrates the formula, so a contrast function
  that is wrong everywhere cannot pass AC-1 vacuously. A test fails when
  the linearisation exponent is changed from 2.4 to 2.2.

## Contract

**Writes:** `src/styles/tokens.test.ts`, `src/test/css.ts` (both classify as
`test`). No source change is expected: the shipped tokens meet the floor,
so the tests pass on arrival and AC-1 is earned by its mutant (`## Deferred
verifications`). RED may amend a block in place with a reason; GREEN
(expected to be a no-op) builds what the amended block says.

**Block 1 - the oracle, in `src/test/css.ts`.** Two pure exports, no
imports from the source tree (the file's existing rule):

- `relativeLuminance(hex: string): number` - `#rrggbb` only (case-
  insensitive; throw on anything else, including `#rgb` and `rgba(...)`).
  Per WCAG 2.x: each channel `c = n / 255`; linear
  `c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4`; luminance
  `0.2126 R + 0.7152 G + 0.0722 B`.
- `contrastRatio(a: string, b: string): number` - `(L1 + 0.05) / (L2 +
  0.05)` with the lighter over the darker, so it is symmetric and >= 1.

**Block 2 - the pair table, hard-coded in `tokens.test.ts`** with a comment
naming `docs/wiki/design/tokens.md`, "Contrast of the roles that carry
text". One row per pair: `{ fg, bg, floor, light, dark }` where `fg`/`bg`
are token names (`--color-…`), `floor` is `4.5` or `3` (only
`border-strong` is `3`), and `light`/`dark` are the figures the table
prints, as the strings printed (`"5.6"`, `"9.30"`), or `null` for `—`:

| fg | bg | floor | light | dark |
|---|---|---|---|---|
| `--color-text` | `--color-surface` | 4.5 | 17.17 | 15.31 |
| `--color-text-muted` | `--color-surface` | 4.5 | 6.05 | 8.18 |
| `--color-text-muted` | `--color-surface-raised` | 4.5 | 5.6 | 7.33 |
| `--color-primary` | `--color-surface` | 4.5 | 5.85 | 8.91 |
| `--color-primary-contrast` | `--color-primary` | 4.5 | 5.85 | 8.91 |
| `--color-danger` | `--color-surface` | 4.5 | 6.54 | 9.30 |
| `--color-warning` | `--color-surface` | 4.5 | 5.93 | 11.18 |
| `--color-success` | `--color-surface` | 4.5 | 6.57 | 10.54 |
| `--color-border-strong` | `--color-surface` | 3 | 4.43 | 5.7 |
| `--color-focus` | `--color-surface` | 4.5 | 5.85 | 8.91 |
| `--color-chip-text-light` | `--color-chip-neutral` | 4.5 | 5.07 | — |
| `--color-chip-text-dark` | `--color-chip-neutral` | 4.5 | — | 8.80 |

The light `border-strong` figure is **4.43**, corrected in `tokens.md` and
`accessibility.md` at PLANNED (PO decision 2 in `## Notes`); the table in
the test carries the corrected figure.

**Block 3 - AC-1, the floor, in `tokens.test.ts`.** Three theme resolutions
through the existing `declaredAt` helper: light = `declaredAt(blocks,
":root")`; media dark = `declaredAt(blocks, "@media (prefers-color-scheme:
dark)", ":root:not([data-theme=\"light\"])")`; forced dark =
`declaredAt(blocks, ":root[data-theme=\"dark\"]")`. A `test.each` over
(theme × pair) - 10 pairs × 3 themes plus the chip pair that applies to
each theme - asserting `contrastRatio(resolve(fg), resolve(bg)) >= floor`.
The test name carries the pair and the theme, so a failure names both
(AC-1's last clause). The two dark blocks are resolved separately: the
audit's mutant edits both, and the existing "identical declarations" test
would catch an edit to only one, but AC-1 is about the value.

**Block 4 - AC-2, calibration, in `tokens.test.ts`.** A `test.each` over
every printed figure (light and dark, skipping `—`):
`contrastRatio(...)` from the **token hexes** is within half a unit in the
last printed decimal of the printed figure - `Math.abs(computed -
Number(printed)) <= 0.5 * 10 ** -decimals(printed) + 1e-9`, where
`decimals("5.6") = 1` and `decimals("9.30") = 2`. That is what "the figure
tokens.md prints" means for a table printed to mixed precision; a flat
±0.01 fails `5.6` (computed 5.644) and `5.7` (5.679) while they are
correctly printed. Baseline, computed at PLANNED from the shipped hexes
(the orchestrator's own run, `## Notes`): light 17.169, 6.050, 5.644,
5.847, 5.847, 6.536, 5.927, 6.567, 4.430, 5.847, chip-light 5.071; dark
15.308, 8.180, 7.326, 8.910, 8.910, 9.295, 11.175, 10.542, 5.679, 8.910,
chip-dark 8.800. Every one is within the rule above of its printed figure
once 4.56 reads 4.43.

**Oracle partition.** AC-1 is settled (floors from `accessibility.md`,
formula from WCAG): read the numbers out. AC-2 is the calibration that
keeps AC-1 from passing vacuously; its figures are the table's. Nothing is
oracle-free.

**Callers of changed signatures.** None; `css.ts` gains exports and changes
none.

**Test command.** `pnpm exec vitest run --project unit src/styles/tokens.test.ts`
(26 tests on arrival in that file; whole suite 2865).
