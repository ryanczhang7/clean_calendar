## Context

The first story of EPIC-01 (`docs/backlog/epics/EPIC-01.md`). It turns the
empty repository into the layout `docs/wiki/stack.md` describes - a Vite +
React + TypeScript PWA under `src/`, Deno edge functions under
`supabase/functions/`, code shared by both under `shared/`, Playwright specs
under `e2e/` - and makes every gate in `stack.md` real. `stack.md` is marked
**Unverified**: every command and version in it is researched, and this story
is where each is executed for the first time, observed failing on purpose, and
corrected where it has moved. Run under SCAFFOLD (`type: bootstrap`), so
nothing forces a test to exist; `## Scaffold inventory` is where the tests are
shown anyway.

Toolchain first: `/setup-environment` must have installed Node 22, pnpm 10,
Deno 2 and the Supabase CLI (`docs/wiki/environment.md`) before this story
starts. Docker is needed only to probe the optional `db` and `integration`
gates; if it is absent, say so in `## Gate probes` and leave those two probes
to the first story that requires them (CAL-004 for `db`, CAL-017 for
`integration`).

Required gates that would fail if this story's artefact broke: all of them -
`lint`, `typecheck`, `unit`, `coverage`, `deno-check`, `deno-test`, `build`.

## Acceptance criteria

- **AC-1** - Given the scaffold, when `bash scripts/gates.sh --gate lint` runs,
  then Biome checks the project files (excluding `.claude/**`, `docs/**`,
  `scripts/**`) and passes; with one lint violation introduced into
  `src/app/App.tsx` it fails.
- **AC-2** - Given the scaffold, when `bash scripts/gates.sh --gate unit` runs,
  then Vitest's `unit` project discovers and passes the example test
  `src/app/App.test.tsx`, which renders `<App />` and finds a heading by role;
  with `src/app/App.test.tsx` moved aside the gate fails.
- **AC-3** - Given the scaffold, when `bash scripts/gates.sh --gate coverage`
  runs, then V8 coverage is reported over `src/**` and `shared/**` and the gate
  fails when the configured threshold (80 for lines, branches, functions and
  statements) is not met.
- **AC-4** - Given the scaffold, when `bash scripts/gates.sh --gate typecheck`
  runs, then `tsc --noEmit` passes under `strict` and
  `noUncheckedIndexedAccess`; with a type error introduced it fails.
- **AC-5** - Given the scaffold, when `bash scripts/gates.sh --gate deno-check`
  and `--gate deno-test` run, then `deno check` type-checks every module under
  `supabase/functions/` and `deno test` discovers and passes
  `supabase/functions/_shared/health_test.ts`, which imports `shared/version.ts` from
  by relative path (the import shape `stack.md` says the functions
  will use); each gate fails when its subject is broken.
- **AC-6** - Given the scaffold, when `bash scripts/gates.sh --gate build`
  runs, then `vite build` writes `dist/index.html` and prints `built in`;
  `bash scripts/task.sh dev` serves the app on localhost and the page shows the
  example heading.
- **AC-7** - `.claude/harness/project.conf` has a command, `cwd` and `evidence`
  line for every gate in `stack.md` (corrected where execution showed the
  researched line was wrong), a `covers` line per gate per directory it reads,
  a `discovery` line per runner, and `BOOTSTRAPPED=yes`; and
  `bash scripts/gates.sh --audit` passes.
- **AC-8** - `bash scripts/classify.sh` reports `src/app/App.test.tsx`,
  `supabase/functions/_shared/health_test.ts`, `supabase/tests/x.db.test.ts`
  and `e2e/boot.spec.ts` as `test`; `vite.config.ts`, `biome.json`,
  `supabase/config.toml`, `supabase/functions/deno.json` and `tsconfig.json`
  as `config`; `package.json` as `manifest`; `src/app/App.tsx`,
  `shared/recurrence.ts` and `supabase/migrations/0001_core_schema.sql` as
  `source`.
- **AC-9** - Each required gate has been observed to fail and then pass again,
  with both outputs pasted in `## Gate probes`; `stack.md` is updated to what
  was actually installed and run, and its Unverified header is replaced by a
  line naming this story as the verification.

**Oracle partition.** Every criterion is *mechanical*: each names a command
and the exact observable (exit status, an evidence line, a classifier word).
Nothing is settled-by-number and nothing is oracle-free. The only judgement
calls are the version pins, decided below.

**Version pins (PO decisions, numbered so the user can overrule them):**

1. **Node 24, not 22.** `/setup-environment` measured Node v24.19.0 installed
   and nothing on 22. Node 24 is the current LTS line, so `.nvmrc` says `24`
   and `engines.node` says `>=24`. `stack.md` is corrected to match. Reason to
   overrule: a hosting or CI image pinned to 22 - none is planned.
2. **Deno `^2.9`**, what winget installed (2.9.7). `stack.md` said 2.5.x.
3. **Vitest: the current major at install time**, as `stack.md` already
   allows; the installed major is written into `stack.md`'s row.
4. **Supabase CLI as a dev dependency** (`supabase` on npm), run as
   `pnpm exec supabase`, because winget has no package (environment.md).
5. **pnpm 10.x via `packageManager`**, so corepack selects it inside the repo
   regardless of the global 12.3.4 shim.

**Modules and exports.**

- `shared/version.ts` - `export const APP_VERSION: string` (`"0.0.0"` until a
  release story owns it). Pure, no imports, so it is importable from both
  runtimes.
- `supabase/functions/_shared/health.ts` -
  `export function health(): { ok: true; version: string }`; `version` is
  `APP_VERSION`, imported **by relative path** `../../../shared/version.ts`.
  This is the import shape AC-5 exists to prove.
- `supabase/functions/_shared/health_test.ts` - one `Deno.test` asserting
  `health()` deep-equals `{ ok: true, version: APP_VERSION }`, using
  `jsr:@std/assert`.
- `src/app/App.tsx` - `export function App(): JSX.Element`, rendering a
  `<main>` landmark containing `<h1>Clean Calendar</h1>`. No product
  behaviour: the shell, tokens and routes are CAL-002.
- `src/app/App.test.tsx` - renders `<App />` with Testing Library and asserts
  `getByRole("heading", { level: 1, name: "Clean Calendar" })`. A render-only
  example is accepted here *because* the only behaviour is the heading; the
  first real interaction test is CAL-002's.
- `src/main.tsx` - `createRoot(document.getElementById("root")!)` rendering
  `<StrictMode><App /></StrictMode>`. Excluded from coverage: it is the one
  module that cannot run under jsdom without a DOM fixture.
- `src/test/setup.ts` - `import "@testing-library/jest-dom/vitest"` only.
- `e2e/boot.spec.ts` - one Playwright test: open `/`, expect the level-1
  heading `Clean Calendar`. Runs only under the optional `integration` gate.

**Configuration semantics.**

- `vitest.config.ts` - two projects: `unit` (environment `jsdom`, setup
  `src/test/setup.ts`, include `src/**/*.test.{ts,tsx}` and
  `shared/**/*.test.ts`) and `db` (environment `node`, include
  `supabase/tests/**/*.db.test.ts`). Coverage provider `v8`, `include`
  `src/**` and `shared/**`, `exclude` `src/main.tsx`, `src/sw.ts`,
  `src/test/**`, `**/*.test.*`; thresholds 80 for lines, branches, functions,
  statements. **80 means:** the gate fails when any one of the four is below
  80.00 over the included files; it is a floor on the *project*, not per file.
- `tsconfig.json` - `strict`, `noUncheckedIndexedAccess`, `noEmit`,
  `jsx: react-jsx`, `moduleResolution: bundler`; `include` `src`, `shared`,
  `e2e`, the three `*.config.ts`; never `supabase/**` (Deno owns it).
- `biome.json` - `files.includes` covers `src`, `shared`, `e2e`, the config
  files, `index.html`; and excludes `.claude/**`, `docs/**`, `scripts/**`,
  `supabase/**`, `dist/**`, `coverage/**`. `supabase/**` is excluded because
  `deno lint`/`deno fmt` own it and Biome does not know `npm:`/`jsr:`
  specifiers.
- `supabase/functions/deno.json` - `imports` pinning `@std/assert` by exact
  `jsr:` version; `compilerOptions.strict`. A `deno.lock` beside it is
  committed if `deno` writes one.
- `supabase/config.toml` - from `supabase init`, with `[functions.capture]`
  and `[functions.send-reminders]` `verify_jwt = true` pre-declared, and the
  Google provider block present but disabled until CAL-003.
- `.env.example` - the variable names the client reads
  (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`), empty values.
- `playwright.config.ts` - `testDir: e2e`, Chromium only, `webServer` runs
  `pnpm exec vite preview --port 4173` against `dist/`.

**Gate lines** are the block in `stack.md`, "Gate lines for `project.conf`",
each corrected by execution. Two things execution has to settle and record in
`## Notes`: how `deno-check` enumerates modules (`gates.sh` runs commands
through `bash -c`/`eval`, so `$(find …)` works, `**` does not without
`globstar`), and whether `deno test --dry-run` exists in Deno 2.9 for the
discovery line.
