## Context

EPIC-05, brief §4.3: the app sends a booking e-mail's text to Gemini and gets
back a proposed event. Decided after the interview: the Gemini key is a
server-side secret and captures go browser → edge function → Gemini.
`architecture.md` ("capture function", "Capture"): the function verifies the
JWT and the owner e-mail, gives the model the owner's kind names, validates
the reply with a zod schema shared with the client (`shared/captureSchema.ts`),
records a `capture_jobs` row (hash of the input, never the input), and returns
`{proposal, confidence, missing, jobId}`. Model: `gemini-2.5-flash`
(`stack.md`), REST `generateContent` with a JSON response schema, raw `fetch`.

Required gates that would fail if this broke: `deno-test` (handler and Gemini
client with `fetch` stubbed), `deno-check`, and `unit` (the shared schema and
the boundary guard under Vitest).

## Acceptance criteria

- **AC-1** - Given a POST `{text}` with the owner's JWT, when the handler runs,
  then it calls `{GEMINI_API_BASE}/v1beta/models/gemini-2.5-flash:generateContent`
  once with the key in the `x-goog-api-key` header, `responseMimeType:
  application/json`, a `responseSchema`, and a prompt that contains the text
  and the owner's live kind names; and it returns 200 with `{proposal: {title,
  startsAt, endsAt, allDay, location, kindName}, confidence: {<field>: 0..1},
  missing: [<field>], jobId}` validated by `shared/captureSchema.ts`.
- **AC-2** - Given the model returns a `kindName` that is not one of the
  owner's live kinds, when the reply is mapped, then `kindName` is `null` and
  `kind` is in `missing`.
- **AC-3** - Given the model's reply fails the shared schema (malformed JSON, a
  missing key, `confidence` outside 0..1), when the handler runs, then it
  returns 502 `{error: 'unreadable'}` and the job row records the error.
- **AC-4** - Given no JWT, the handler returns 401; given a valid JWT for an
  e-mail other than `app_config.owner_email`, it returns 403. In both cases
  Gemini is never called and no job row is written.
- **AC-5** - Given any successful or failed call, when the job row is written,
  then it holds `input_kind 'text'`, the SHA-256 hex of the text, the model
  name, `status 'proposed'` (or the error), and `latency_ms`; the text itself
  appears in no column.
- **AC-6** - Given an empty text or one over 20,000 characters, the handler
  returns 400 without calling Gemini.
- **AC-7** - Given every source file under `src/` and `shared/` (enumerated with
  `bash scripts/classify.sh --list source`), when the boundary guard runs,
  then none contains `generativelanguage.googleapis.com` or `GEMINI_API_KEY`.
  *Control:* a probe file `src/__probe_gemini.ts` containing the host must be
  reported by the guard's scanning function.

### Block 1 - the shared schema (AC-1, AC-2, AC-3)

`shared/captureSchema.ts`, imported by the browser as `"zod"` and by Deno
through the same bare specifier once `deno.json` maps it (Block 6). Exports,
exactly:

```ts
import { z } from "zod";
export const CAPTURE_FIELDS = ["title", "startsAt", "endsAt", "location", "kind"] as const;
export type CaptureField = (typeof CAPTURE_FIELDS)[number];
export const proposalSchema: z.ZodType<{
  title: string | null; startsAt: string | null; endsAt: string | null;
  allDay: boolean; location: string | null; kindName: string | null;
}>;
export const confidenceSchema;   // z.record(z.enum(CAPTURE_FIELDS), z.number().min(0).max(1)) - every key optional
export const missingSchema;      // z.array(z.enum(CAPTURE_FIELDS))
/** What the model must return (the Gemini responseSchema mirrors this). */
export const geminiReplySchema = z.object({ proposal: proposalSchema, confidence: confidenceSchema, missing: missingSchema });
/** What the function returns to the client. */
export const captureResponseSchema = geminiReplySchema.extend({ jobId: z.string().uuid() });
export type GeminiReply = z.infer<typeof geminiReplySchema>;
export type CaptureResponse = z.infer<typeof captureResponseSchema>;
```

- `startsAt`/`endsAt` are ISO-8601 strings as the model wrote them, or `null`;
  this story does not parse or normalise them (CAL-020/021 do).
- `missing` names the field the model could not find, in `CAPTURE_FIELDS`
  terms: the kind field is `"kind"` in `missing` and in `confidence`, while the
  proposal carries it as `kindName` (AC-2's wording). A `confidence` outside
  `[0, 1]`, an unknown key, a non-boolean `allDay`, or a missing key fails the
  schema (AC-3). `.strict()` on the proposal object, so an extra key fails too.
- `shared/captureSchema.test.ts` (Vitest, unit project) pins each of those
  rejections and one full accept.

### Block 2 - the handler (AC-1 to AC-6)

`supabase/functions/capture/handler.ts`:

```ts
export type CaptureDeps = {
  fetch: typeof fetch;                       // EVERY outbound call goes through this
  env: (name: string) => string | undefined; // Deno.env.get in production
  now: () => number;                         // performance.now in production
};
export const MAX_TEXT_CHARS = 20_000;
export async function handleCapture(req: Request, deps: CaptureDeps): Promise<Response>;
```

`index.ts` is one `Deno.serve((req) => handleCapture(req, { fetch, env: Deno.env.get, now: () => performance.now() }))`
and has no test. Environment the handler reads, by name: `SUPABASE_URL`,
`SUPABASE_ANON_KEY` (both injected by the edge runtime), `GEMINI_API_KEY`,
`GEMINI_API_BASE` (default `https://generativelanguage.googleapis.com`).

**Order of checks, and what each returns.** The order is the contract; AC-4
and AC-6 both assert "Gemini never called", and in the tests any `fetch` to a
URL the stub does not expect is a failure.

1. Method not POST -> 405. (Not an AC; pinned so the test's "unexpected
   fetch" never has an alibi.)
2. No `Authorization: Bearer <token>` header -> **401** `{error: "unauthorized"}`.
   No fetch of any kind has happened.
3. Body: JSON `{text: string}`; `text.trim()` empty or `text.length >
   MAX_TEXT_CHARS` (20,000, counted in UTF-16 code units as `String.length`,
   the client's measure) or not JSON -> **400** `{error: "bad_request"}`. No
   fetch, no job row. (PO decision 3: a request nothing was attempted for
   gets no audit row.)
4. Owner check, through `_shared/owner.ts` (Block 4): one PostgREST call. Not
   the owner -> **403** `{error: "forbidden"}`. No Gemini call, no job row.
5. Live kind names: `GET {SUPABASE_URL}/rest/v1/kinds?select=name&deleted_at=is.null&order=sort_order.asc`
   with `apikey: SUPABASE_ANON_KEY` and the caller's `Authorization` header
   (RLS does the rest). A non-2xx -> **502** `{error: "upstream"}`, no job
   row.
6. Gemini (Block 3). `latency_ms` is `round(now() after - now() before)`
   around that one call.
   - non-2xx or a network throw -> **502** `{error: "upstream"}`; job row
     with `status "discarded"`, `error "upstream <status>"` (or `"upstream
     fetch"` on a throw), `proposal null`.
   - reply text that is not JSON, or JSON that fails `geminiReplySchema` ->
     **502** `{error: "unreadable"}`; job row with `status "discarded"`,
     `error "unreadable: <first zod issue path and message, or 'not json'>"`,
     `proposal null`. (PO decision 2: `capture_jobs.status` is constrained
     to `proposed|confirmed|discarded`; a failed call is `discarded` with
     `error` set. No migration.)
7. Mapping (AC-2): if `proposal.kindName` is non-null and matches no live
   kind name **case-insensitively after trim** (the `isOwnerEmail` rule, the
   same the kinds editor uses), set `kindName = null` and add `"kind"` to
   `missing` if absent; a `kindName` that matches is replaced by the kind's
   stored spelling. `missing` keeps its order and is de-duplicated.
8. Job row: `POST {SUPABASE_URL}/rest/v1/capture_jobs` with `apikey`, the
   caller's `Authorization`, `Prefer: return=representation`, body
   `{input_kind: "text", input_hash, model, proposal, confidence, status, error, latency_ms}`
   where `input_hash` is the lowercase SHA-256 hex of the UTF-8 text
   (`crypto.subtle.digest`), `model` is `GEMINI_MODEL`. The returned row's
   `id` is `jobId`. A failed insert -> **502** `{error: "upstream"}`.
   **The text appears in no field of this body** (AC-5): the test asserts the
   serialised body does not contain the input text.
9. **200** with `captureResponseSchema`'s shape: `{proposal, confidence, missing, jobId}`.

Every response is `application/json`.

### Block 3 - the Gemini client (AC-1)

`supabase/functions/capture/gemini.ts`:

```ts
export const GEMINI_MODEL = "gemini-2.5-flash";
export const DEFAULT_GEMINI_API_BASE = "https://generativelanguage.googleapis.com";
export function geminiUrl(base: string): string;   // `${base}/v1beta/models/${GEMINI_MODEL}:generateContent`, base without trailing slash
export const geminiResponseSchema: Record<string, unknown>;  // the JSON-schema mirror of geminiReplySchema
export function buildGeminiRequest(prompt: string): {
  contents: [{ role: "user"; parts: [{ text: string }] }];
  generationConfig: { responseMimeType: "application/json"; responseSchema: typeof geminiResponseSchema; temperature: 0 };
};
export type GeminiOutcome =
  | { kind: "reply"; text: string; latencyMs: number }      // candidates[0].content.parts[0].text
  | { kind: "http"; status: number; latencyMs: number }
  | { kind: "network"; latencyMs: number };
export async function callGemini(args: { prompt: string; apiKey: string; base: string; fetch: typeof fetch; now: () => number }): Promise<GeminiOutcome>;
```

- Exactly one `fetch`, `POST`, headers `x-goog-api-key: <apiKey>` and
  `content-type: application/json`. The key appears in no URL, no log line,
  no error message, no job row.
- `supabase/functions/capture/prompt.ts` exports
  `buildPrompt(text: string, kindNames: readonly string[]): string`. The
  prompt contains the text verbatim and every kind name verbatim (AC-1's
  assertion is `includes`), tells the model today's date is not known, to
  return `null` for anything not stated rather than guess, and that
  `kindName` must be one of the listed names or `null`. Wording is GREEN's.
- `gemini_test.ts` pins URL, method, headers, body shape, the three outcomes,
  and that a reply with no candidate is `unreadable`-class (`kind: "reply"`
  with `text: ""` is acceptable and the handler's schema step rejects it).

### Block 4 - the owner check (AC-4)

`supabase/functions/_shared/owner.ts`:

```ts
export type OwnerDeps = { fetch: typeof fetch; env: (name: string) => string | undefined };
/** 401 when there is no bearer token, 403 when is_owner() is false, null when the caller is the owner. */
export async function requireOwner(req: Request, deps: OwnerDeps): Promise<Response | null>;
```

Mechanism: `POST {SUPABASE_URL}/rest/v1/rpc/is_owner` with `apikey:
SUPABASE_ANON_KEY`, the caller's `Authorization` header, `content-type:
application/json`, body `{}`. PostgREST returns `true`/`false` as the JSON
body; anything but literal `true` (a non-2xx, `false`, `null`) is 403. The
gateway (`verify_jwt = true`) has already checked the signature, so the
handler never decodes the JWT; `public.is_owner()` is the one predicate RLS
uses and is granted to `authenticated` (migration 0001). **This mechanism is
checkable, not sacred**: if PostgREST's rpc of a zero-argument function needs
a different call shape, RED or GREEN amends this block with the measured one.

### PO decisions at PLANNED (Lead PO, 2026-10-26)

1. **Gates.** `deno-test` and `deno-check` (required) read
   `supabase/functions/**`; `unit` and `coverage` (required) read `shared/**`
   and `src/**`. Every artifact has a required gate; `required_gates` stays
   empty. `supabase/config.toml` is read by no gate with a `covers` line, so
   `gates.sh` will WARN "read by no gate" for it: the manifest is complete,
   the file is genuinely ungated here (CI's `supabase start` is what reads it).
2. **A failed capture is `status "discarded"` with `error` set.** The
   `capture_jobs.status` check constraint allows only
   `proposed|confirmed|discarded` (migration 0001). AC-3/AC-5's "the job row
   records the error" is satisfied by the `error` column; adding a `failed`
   status would be a migration the `db` gate cannot judge on this machine.
3. **A 400 (empty or oversized text) writes no job row.** AC-6 says "without
   calling Gemini"; nothing was attempted, and hashing an empty or rejected
   input would be an audit row about nothing. AC-5's "any successful or failed
   call" is read as "any call that reached Gemini".
4. **Owner check by `rpc/is_owner` with the caller's JWT**, not by decoding
   the token in the function (Contract Block 4). One predicate, the one RLS
   uses, and no JWT parsing code to get wrong.
5. **Epic done-when.** EPIC-05 is done when all three entry paths reach the
   confirm screen and the key is never in the bundle. This is story 1 of 5;
   the key's absence is AC-7 here, and the screens are CAL-020/021/022.
   No gap for this story to close.
6. **Dependencies.** `zod` is already a production dependency of the client
   and will be mapped for Deno in GREEN (Block 6). No test-only dependency is
   expected; `@std/assert` is already in `deno.json`.
