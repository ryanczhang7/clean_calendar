## Context

EPIC-02. Source: `docs/wiki/audits/EPIC-02-2026-11-26.md`, Decided 4, and
Evidence `### E-STRYKER` (group `editor`) and `### E-WHOLE` (N03 to N07).
CAL-007 built the kind editor's custom colour (`src/kinds/KindEditor.tsx`,
Contract Block 5). It is correct today. The previous audit left the editor's
markup lines (`70-145`, `159-194`, `326-443`) out of its Stryker run. Given
the whole file, five mutants on the custom-colour path survive all 3444 unit
tests:

- **N03 and N04, `KindEditor.tsx:35`, the editor's own `HEX` anchors.** With
  the trailing `$` dropped, `#BD82001` (one digit too many) counts as a
  colour. With the leading `^` dropped, ` #BD8200` (a pasted leading space)
  does. Either way the editor then passes the text to `chipText` and
  `darkCounterpart`, whose own check (`src/domain/colour.ts:10`, `:19-21`) is
  anchored and throws `RangeError`. There is no error boundary under `src/`
  (`grep` for `ErrorBoundary`/`componentDidCatch` finds none), so by reading,
  one extra keystroke blanks the app. The audit reasoned this consequence and
  did not run it. The only invalid-hex test types a value that is too short
  (`#BD82`, `KindEditor.test.tsx:710`), which both mutants still refuse.
- **N05, `KindEditor.tsx:134`, the colour picker's `onChange`.** With it
  replaced by `() => undefined`, choosing a colour in the native picker does
  nothing. The only picker test (`:213`) checks that it exists and is
  `type="color"`. Nothing changes its value.
- **N06 and N07, `KindEditor.tsx:163` and `:168`, the preview's inline
  styles.** With either `style` object emptied, the preview shows no surface
  or no chip colour. The readout text under it (`Text contrast ...`) is still
  right, so every preview test passes. The preview is the one place the owner
  sees a custom colour before saving it.

This is a test-only story: the production code is right, and the tests pin it.
Each new test passes on arrival, so it has to be earned by putting the
audit's mutant back (see `## Deferred verifications`).

Required gate that would fail if this broke: `unit` (required).

## Acceptance criteria

- **AC-1** - Given the Climbing editor (light `#1565C0`, custom), when the
  light hex is replaced with `#BD82001`, then the hex is marked invalid,
  described as "Enter a colour like #BD8200.", Save is disabled, and the
  editor is still on screen.
- **AC-2** - Given the same editor, when the light hex is replaced with
  ` #BD8200` (a leading space), then the same three things hold as in AC-1.
- **AC-3** - Given the Climbing editor, when the light group's colour picker
  reports `#2e7d32`, then the light hex input holds `#2E7D32`.
- **AC-4** - Given the Climbing editor, the light preview's chip has
  background `#1565C0` and text colour `#FFFFFF` (its `chipText`), and the
  light preview's surface has background `#FFFFFF`; the dark preview's chip has
  background `#7EB4F1` and its surface `#121417`.

## Contract

**Writes:** `src/kinds/KindEditor.test.tsx`

- No source change. `src/kinds/KindEditor.tsx` and `src/domain/colour.ts` are
  read-only for this story.
- Use the file's harness (`renderEditor`, `group`, `hexInput`,
  `replaceText`, `saveButton`). The picker is
  `within(group("Light")).getByLabelText("Pick a colour")`. User-event cannot
  type into `type="color"`, so AC-3 fires an `input`/`change` event on it
  with the value set. RED chooses which, and records why.
- AC-4: the chip is the `Aa` span and the surface its parent `div`, both
  `aria-hidden`, so query by text or by structure, not by role. jsdom reports
  inline colours as `rgb(...)`. `toHaveStyle` with the hex compares them
  correctly. `chipText("#1565C0").text` and `chipText("#7EB4F1").text` should
  be computed from the module, not assumed.
- AC-1 and AC-2: "still on screen" means the editor's dialog is found after
  the typing. Under the mutants the audit expects a thrown `RangeError`, so
  the test is red either at a thrown error or at an assertion. Both count as
  earning it, and RED records which one it saw.
- Oracle partition: settled. Every value is read from the palette, the
  surfaces in `colour.ts` or the existing fixture.
