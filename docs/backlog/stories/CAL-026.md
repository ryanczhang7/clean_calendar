## Context

EPIC-07, brief §4.6: a per-event reminder time. This story is the data and
the field; delivery is CAL-027 (the device) and CAL-028/029 (the scheduler).
`architecture.md`, Data model: a `reminders` row holds `minutes_before`; for
a non-recurring event there is one row with `occurrence_date null`; for a
series that row is the template the scheduler materialises per occurrence.
Reminders are cached, synced and written through the outbox like events
(CAL-014, CAL-015). Field: `components.md`, "Event sheet", field 8; chip
marker: "Event chip", Reminder variant.

Required gate that would fail if this broke: `unit`.

## Acceptance criteria

- **AC-1** - Given the form, when the Reminder select is opened, then it offers
  None, At time, 5, 10, 15 and 30 minutes, 1 hour, 2 hours and 1 day before,
  mapping to `minutes_before` null, 0, 5, 10, 15, 30, 60, 120, 1440.
- **AC-2** - Given a new event saved with "30 minutes before", when it is
  written, then the outbox holds the event op followed by a `reminders` insert
  with `minutes_before = 30` and `occurrence_date = null`.
- **AC-3** - Given an event with a reminder, when the reminder is changed or set
  to None, then the row is updated or soft-deleted through the outbox; there is
  never more than one live template row per event.
- **AC-4** - Given an all-day event, when "At time" is chosen, then the helper
  reads "At 09:00 on the day" and the stored `minutes_before` is `-540`
  (09:00 after the event's local midnight start).
- **AC-5** - Given an event with a live reminder, when its chip renders, then a
  bell glyph shows and the accessible name includes ", reminder 30 minutes
  before" (", reminder at start time" for 0; ", reminder 1 day before").
- **AC-6** - Given sync, when it hydrates and catches up, then `reminders` rows
  are cached like events, and `useReminder(eventId)` returns the live template.
